# X79-VG4: the first real machine

LogitOS reached its desktop on physical hardware for the first time on
2026-10-31 at 19:29 local time. Spec:
`docs/superpowers/specs/2026-10-31-x79-vg4-bringup-design.md`.

## The machine

| Part | What it is |
|---|---|
| Board | "INTEL X79-VG4" V2.2, AMI BIOS 4.6.5 (2024-06-21), UEFI |
| CPU | Xeon E5-2670 v2, 10 cores / 20 threads, invariant TSC 2494 MHz |
| Memory | 2 x 8 GiB DDR3-1600 (Silicon Power SP008GBLTU160N02, CL11-11-11 D3-160) |
| Storage | Netac SSD 120 GB on AHCI port 4, shared with Windows 10 |
| Chipset | Intel 6 Series PCH: LPC 1c4e, AHCI 1c02, EHCI 1c26/1c2d, HDA 1c20, SMBus 1c22 |
| Network | Realtek 10ec:8168 rev 0c |
| Display | GTX 1050 10de:1c81, used through the UEFI boot framebuffer |
| Audio | Realtek ALC887 |
| Super I/O | Nuvoton NCT6779 at 0x2e |
| Input | USB keyboard 24ae:4056, mouse 18f8:1286, behind the 8087:0024 hub |

There is no serial port in use. Every finding below came from photos of
the screen (the boot marks, the live console and the paged boot report).

## How it boots

- A USB stick built with `tools/mkesp.py --layout gpt`, chosen from the
  firmware boot menu (F11) as "UEFI: General UDisk".
- The root filesystem lives in a 20 GiB GPT partition after C:, type
  `6c6f6769-7466-4a73-9a2b-58373956b434`, written from Windows by
  `tools/windows/install-root.ps1` (read back and checked by SHA-256).
  The kernel mounts whichever partition carries a LogitFS superblock.

## The ladder

| Level | What | Result on the X79-VG4 |
|---|---|---|
| L0 | UEFI loader hands over to the kernel | Pass (handoff from a stub below 1 GiB) |
| L1 | Framebuffer | Pass: 1280x1024, write-combining, 2.0 ms per frame |
| L2 | All CPUs | Pass: 20/20 online |
| L3 | Storage | Pass: Netac found, root partition mounted |
| L4 | USB input | Pass: keyboard and mouse enumerate |
| L5 | Desktop from the disk | Pass: desktop, Dock and Finder on screen |
| L6 | Network | Pass: DHCP lease, SLAAC, IPv6 |
| L7 | Audio playback | Not tested yet (ALC887 is configured) |
| L8 | DIMM SPD | Pass: both modules read over the CPU iMC SMBus |
| L9 | Reboot and power off | Not tested on the machine yet |

## What the hardware taught us

- AMI loads the UEFI loader above 1 GiB. The native handoff now runs from
  a low stub.
- AMI hands over HPET comparator 0 armed with the legacy route on, which
  takes IRQ0 from the PIT. The kernel disarms it at boot.
- AHCI port 4 was never started by firmware. The driver brings the link
  up itself.
- The EHCI legacy-support handoff completes, but the OS semaphore reads
  back clear. The driver warns and continues, as Linux does.
- On Sandy/Ivy Bridge-EP the DIMMs' SPD is on the CPU memory controller's
  SMBus, not the PCH's.

## Still open
