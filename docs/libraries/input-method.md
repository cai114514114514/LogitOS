# Pinyin input method

LogitOS converts Pinyin spelling into Chinese text through the engine in `c/lib/ime/pinyin.c`. It searches a resident dictionary, combines dictionary words, parses syllables, and ranks candidates. The window manager integrates the engine through `c/kernel/gui/ime/ime_ui.c`, which manages composition and candidate selection. Selection preferences are stored by `c/kernel/gui/ime/ime_learn.c`. These components run in the kernel and deliver committed Unicode codepoints to applications as window input events.

## State and ownership

The engine uses a caller-owned `struct ime_state`, declared in `c/lib/ime/pinyin.h`. It contains the typed spelling, candidate array, page position, and learning callback. Spelling includes apostrophes as typed, so backspace removes the last input byte. Every spelling change rebuilds candidates and returns to the first page.

`ime_open()` reads dictionary bytes supplied by its caller and builds an offset index in one static `struct ime_dict`. Candidate strings remain in the supplied buffer, which the caller must keep resident. Composition states share this dictionary. Engine lookup and composition use fixed arrays and stack storage.

The desktop keeps one active engine state and a parked spelling and page position for each window. `ime_ui_focus()` saves the outgoing composition and restores the incoming one by replaying its spelling. This reduces storage compared with keeping a full candidate array for every window. The implementation is in `c/kernel/gui/ime/ime_ui.c`.

## Dictionary layout and lookup

`c/lib/ime/pinyin_fmt.h` defines the version 2 binary format. Integers are little-endian, and the engine reads them byte by byte to support records at arbitrary alignments.

| Section | Contents |
|---|---|
| Header | A 48-byte header containing `PYN\0` magic, version, counts, section offsets, initials-row geometry, and a build identifier. |
| Keys and candidates | Ascending NUL-terminated ASCII keys. Each key has a candidate count; each candidate contains a UTF-8 byte length, a 32-bit frequency, and text. |
| Initials table | Sorted rows of fixed stride containing a NUL-padded initials string and a reference range. |
| References | Candidate-record byte offsets, grouped by initials and ordered by descending frequency. |

Keys concatenate toneless Pinyin syllables. This allows different syllable divisions to share a key: `xian` includes both 先 and 西安. Initials use the first letter of each syllable, such as `nh` for 你好. The writer indexes candidates containing at least two characters.

In `c/lib/ime/pinyin.c`, `ime_open()` checks record bounds, candidate totals, ascending key order, initials-row padding and order, contiguous reference ranges, and referenced-record bounds. It builds an offset index for the variable-length key records. The initials table supports binary search directly through its fixed stride.

Exact lookup and prefix lookup share two binary searches over the key index. The resulting range contains keys beginning with the typed spelling; an exact key, when present, occupies the start of that range.

## Parsing and word composition

The syllable inventory in `c/lib/ime/pinyin_syllables.inc` is generated by `tools/gen_pinyin_syllables.py`. The script collects all pronunciations reported by pypinyin across U+4E00 through U+9FFF, removes tone marks, and sorts the resulting inventory. `is_legal_syllable()` searches this table by binary search.

The engine first attempts composition through dictionary words. `tier_words()` computes a best suffix at each spelling position, then joins the chosen dictionary records into a candidate. Each word contributes a cost of 64 minus the integer base-two logarithm of its score. The word penalty favors dictionary phrases, while frequency and learned weights influence candidate choice and word boundaries. `tests/unit/ime_usability_test.c` includes `woaizhongguo` → 我爱中国 among its assertions.

The syllable fallback uses `seg_dfs()`. It tries longer legal syllables first and backtracks through shorter choices. The source uses `angong` to illustrate the need: choosing `ang` leaves an unusable remainder, while `an` followed by `gong` completes the parse. For each completed parse containing at least two syllables, the engine looks up the first dictionary candidate for each syllable and concatenates the results.

Apostrophes force syllable boundaries. The engine extracts searchable letters and records boundary positions alongside them. The syllable search respects those positions. For a dictionary word spanning a forced boundary, `syllable_counts()` computes possible syllable counts and checks them against the candidate’s codepoint count. This permits `xi'an` → 西安 while rejecting the one-syllable reading 先.

Partial selection lets a user commit a leading word or character and continue editing the suffix. Its trigger is failure of the full-spelling lookups: exact, prefix, and initials lookup for unseparated input, or exact lookup on the stripped letters for apostrophe input. `tier_partial()` visits longer leading keys first. Each candidate records the number of raw bytes it consumes in `raw_used`, including adjacent apostrophes. For example, the usability test checks that selecting 你好 from `nihaom` leaves `m` available for further input.

These algorithms are implemented in `c/lib/ime/pinyin.c`.

## Ranking

For spelling without apostrophes, `recompute()` assembles candidates in the following order. Earlier tiers retain priority over later ones.

| Tier | Candidate source |
|---|---|
| `IME_TIER_KEY` | Exact dictionary match for the complete spelling. |
| `IME_TIER_SEG` | Dictionary-word composition, followed by syllable-parse compositions. |
| `IME_TIER_PRE` | Dictionary keys that extend the typed spelling. |
| `IME_TIER_ABBR` | Initials bucket equal to the typed letters. |
| `IME_TIER_PART` | Leading dictionary entries offered by partial selection. |

Apostrophe input follows word composition, syllable parsing, and eligible partial selection.

Exact, prefix, and abbreviation searches use a bounded selector ordered by descending score, with encounter order breaking ties. Partial selection ranks candidates within each matching leading key and visits key lengths in descending order. The segmentation tier appends the word-path candidate first, then syllable results in parse order. Its stored scores serve as candidate metadata; insertion order determines its displayed order.

Deduplication compares output codepoints and consumed spelling length. The same text can represent different selections when those selections consume different amounts of input.

Dictionary candidates begin with their stored frequency. A callback installed by `ime_set_user_weight()` adds a bonus. Its arguments include the dictionary key, candidate UTF-8 bytes, their lengths, and base frequency.

The callback registration also supplies a score ceiling:

```text
((base * max_mul_q8) >> 8) + max_add
```

The engine saturates arithmetic and clamps the final score to this bound. Since dictionary records descend by base frequency, the bound permits early termination when all remaining records would fall below the selector’s threshold. The selection and pruning code is in `c/lib/ime/pinyin.c`.

## Building the dictionary

`tools/mkpinyin.py` produces the baseline artifact, `fsroot/ime/pinyin.dat`. Its full rebuild uses jieba words and frequencies, pypinyin readings, and character coverage from `fsroot/fonts/ui.ttf`. Its default transformation mode reads an existing dictionary and reconstructs the version 2 frequency and initials data.

For initials, the baseline generator segments each key into as many syllables as the candidate has characters. It resolves ambiguous results using readings recorded by single-character dictionary entries and an exception table. When pypinyin is available, the generator cross-checks the derived initials against its readings.

`c/lib/ime/build_dictionary.py` builds the expanded dictionary using the binary writer from `tools/mkpinyin.py`. It has two workflows:

1. Extraction verifies a recorded Qwen3.5 tokenizer hash, reverses its byte-level BPE encoding, and collects tokens that decode to Han text. It combines these with baseline candidate text, filters against the shipped font, and derives readings and initials with pypinyin 0.55.0. Jieba supplies frequencies; unknown terms receive frequency 1.
2. Regular rebuilding merges the checked-in `c/lib/ime/qwen35-zh.tsv.gz` with the baseline dictionary. The compressed TSV contains spelling, candidate text, frequency, and initials. This workflow uses Python’s standard library and the repository writer.

Extraction also supplies canonical readings for existing phrases, including `nvhai` for 女孩. `LICENSES/Qwen3.5-NOTICE.md` records the supplement’s provenance, extraction method, and licensing.

From the repository root, rebuild the expanded artifact with:

```sh
python3 c/lib/ime/build_dictionary.py --root . \
  --tsv c/lib/ime/qwen35-zh.tsv.gz --output fsroot/ime/pinyin-qwen.dat
```

`tests/ime.mk` makes this artifact a disk-image prerequisite. At desktop initialization, `ime_ui_init()` tries the guest file `/ime/pinyin-qwen.dat`, then falls back to `/ime/pinyin.dat`. The loader allocates a resident buffer, reads the file in chunks, and publishes the dictionary after `ime_open()` succeeds. See `c/kernel/gui/ime/ime_ui.c`.

## Learning and persistence

The desktop learning store identifies a preference by dictionary key and candidate text. Text remains a useful identity across dictionary regeneration, while candidate-record offsets identify locations within one generated file.

The ranking bonus is the retained selection count, capped at `IME_LEARN_COUNT_MAX`, multiplied by `IME_LEARN_STEP`. These constants are 64 and 256, giving a maximum bonus of 16,384. The policy is defined in `c/kernel/gui/ime/ime_learn.h` and implemented in `c/kernel/gui/ime/ime_learn.c`.

Before accepting a selection, `c/kernel/gui/ime/ime_ui.c` obtains its dictionary identity through `ime_commit_source()`. After acceptance, it records the selection and refreshes ranking for any remaining suffix. The UI installs the learning callback when the store contains entries, keeping pruning stronger while the store is empty.

A GUI spinlock protects preference lookup, mutation, and serialization. The writer allocates its output buffer before taking the snapshot lock and performs file I/O after releasing it. A timer queues a worker to save preferences to the guest file `/var/ime-learn.conf` after a three-second quiet interval. Turning input off or closing a window requests an earlier asynchronous flush.

The persisted format contains a dictionary key, candidate text, and count on each data line. The parser accepts complete newline-terminated records and reports rejected records. The implementation is in `c/kernel/gui/ime/ime_learn.c`.

## Engine and framework APIs

The engine interface is declared in `c/lib/ime/pinyin.h`.

| API | Contract |
|---|---|
| `ime_open()` | Validate resident dictionary bytes and return the shared dictionary object, or null on refusal. |
| `ime_reset()` | Initialize a composition and clear its learning callback. |
| `ime_set_user_weight()` | Install the callback, context, and score ceiling; rerank active spelling. |
| `ime_feed()` | Process letters, apostrophes, backspace, Escape, and page keys; return composition status. |
| `ime_candidates()` | Copy candidates from the current page; return `-1` for an empty composition. |
| `ime_commit()` | Read selected output codepoints. `IME_COMMIT_RAW` selects literal spelling, including apostrophes. |
| `ime_commit_source()` | Retrieve the selected dictionary key and candidate text for learning. |
| `ime_accept()` | Copy output, consume the selected spelling portion, and recompute the suffix. |

Selection indexes are relative to the current page. `ime_accept()` checks output capacity before copying or consuming input; insufficient capacity returns `-1`.

The framework entry point, `ime_ui_key()`, is declared in `c/kernel/gui/ime/ime_ui.h`. It returns `-1` to forward the key to the application, zero for consumed input without output, or a positive committed-codepoint count. `c/kernel/gui/wm.c` delivers returned codepoints as `EV_KEY` events with modifiers set to zero.

The UI controls are implemented in `c/kernel/gui/ime/ime_ui.c`:

| Input | Action |
|---|---|
| Shift+Space | Toggle Pinyin input for the window. |
| Space | Select the first visible candidate, or commit literal spelling when the candidate list is empty. |
| Digits 1–9 | Select an entry on the current page. |
| Enter | Commit literal spelling. |
| Escape | Cancel composition. |
| PgUp, Left, `-` | Previous page. |
| PgDn, Right, `=` | Next page. |
| Candidate click | Select the clicked candidate. |

`IME_TOGGLE_MOD` and `IME_TOGGLE_NAME` define the toggle in `c/kernel/gui/ime/ime_ui.h`. `ime_ui_compose()` draws the candidate popup, and `ime_ui_click()` handles mouse selection.

The UI also maps comma, period, exclamation mark, question mark, colon, semicolon, and parentheses to Chinese punctuation. During composition, these keys confirm candidates and remaining suffixes before appending punctuation.

## Limitations

- Raw composition accepts lowercase ASCII letters and apostrophes, with a 64-byte limit defined by `IME_MAX_RAW`. The segmentation inventory has 414 syllables of one to six letters and excludes `m`, `hm`, `n`, `ng`, and `hng`. See `c/lib/ime/pinyin.h` and `c/lib/ime/pinyin_syllables.inc`.
- Candidate storage holds 96 entries, nine per page, with 20 codepoints per entry. The syllable search retains up to eight complete parses within 8,192 recursive calls, so ambiguous spelling can exhaust its search budget. See `c/lib/ime/pinyin.h` and `c/lib/ime/pinyin.c`.
- The reader accepts dictionary version 2 and at most 65,536 keys. Reference validation checks bounds without proving that offsets identify record starts. Frequency ordering remains a generator responsibility. See `c/lib/ime/pinyin.c`.
- Dictionary-candidate delivery accepts ASCII and U+4E00 through U+9FFF; another decoded codepoint causes rejection of the whole selection. Chinese punctuation conversion follows its own output path. See `c/kernel/gui/ime/ime_ui.c`.
- Pronunciations depend on the dictionary lexicon. The baseline contains mixed `u` and `v` spellings, while the supplement adds canonical aliases. Tokenizer-derived entries can be word fragments, and unknown terms receive frequency 1. See `c/lib/ime/pinyin_fmt.h`, `c/lib/ime/build_dictionary.py`, and `LICENSES/Qwen3.5-NOTICE.md`.
- Learning accepts keys up to 48 bytes and candidate text up to 60 UTF-8 bytes. Inserting a new entry triggers aging when it would exceed 768 occupied slots or the active 12,288-byte string arena. Aging halves counts and removes zero-count entries. Compositions assembled from several dictionary records have no single identity for learning. See `c/kernel/gui/ime/ime_learn.h`, `c/kernel/gui/ime/ime_learn.c`, and `c/lib/ime/pinyin.c`.

## Test coverage

`tests/ime.mk` defines engine, dictionary, UI, geometry, and guest checks. `tests/unit/ime_usability_test.py` rebuilds the expanded dictionary, exercises both dictionaries, and checks mutations that disable word composition or consume the entire spelling during partial acceptance.

`tests/unit/ime_ui_test.py` links the UI, engine, and learning store with host adapters and includes a punctuation-loss mutation. `tests/imelearn.mk` defines learning-store tests and controls.
