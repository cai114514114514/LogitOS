# AetherScript 语言重构：数值语义第一步

目标仍是接近 Python 的简洁通用语言、原生执行、可显式进入底层。
实现直接落在原有 `c/apps/as/` 和 `fsroot/as/lib/asc.as`，使用原有入口。

仓库自带脚本和标准库的迁移范围、数值修正、缓存重建及验收入口见
[A1 到 A2 迁移记录](AETHERSCRIPT_A1_TO_A2.md)。这次迁移不代表 A2 到 3.x 已完成。

## 已实现的版本边界

语言 2 现为迁移通道，完成迁移前保留。今后语言能力沿 3.x 演进。
文件第一行可明确选择 A2：

```python
# aether: 2
maximum = 9223372036854775807
try:
    result = maximum + 1
except error:
    print(error)
print(wrapping_add(maximum, 1))  # -9223372036854775808
```

原先“无声明或声明 1 继续使用旧规则”的决定已作废。现在无声明源码
默认使用 A2；显式 `# aether: 1` 被拒绝并提示迁移。`3`/`3.0` 交给原生
前端，不能放进 A2 VM 执行。普通目录仍是工程，当前不要求工程配置文件。

## 可执行数值规则

| 操作 | 语言 2 |
| --- | --- |
| 整数字面量 | 精确的有符号 64 位十进制或十六进制；越界是编译错误 |
| 最小值 | `-9223372036854775808`、`-0x8000000000000000` 精确成立 |
| 整数 `+ - * **` | 结果越界抛出可捕获错误，不转换成浮点 |
| 整数左移 | 位数必须为 0–63；数学结果越界抛错 |
| 一元负号、整数 `/ %` | 保留已有最小整数边界检查；除零抛错 |
| `wrapping_add/sub/mul` | 两个整数参数，明确按模 2^64 回绕并返回有符号值 |
| `wrapping_shl(value, bits)` | 明确截断移出的高位；位数仍限制在 0–63 |
| `parse_int(text)` | 精确转换带可选正负号的十进制/十六进制字符串；不饱和、不舍入 |

这里的整数仍由现有 VM 的整数值表示；尚未实现 i8/u8 等独立静态类型。
整数除法仍沿用原有向零截断规则，不宣称与 Python 的 `/` 相同。
混合整数/浮点运算保留原有行为。乘方仍不支持浮点指数。
表达式优先级保持一致：`(-9223372036854775808) ** 0` 合法，
`-9223372036854775808 ** 0` 包含无法表示的正数字面量，编译时拒绝。

## 原编译器、自举与缓存

C 编译器和自举编译器共用精确整数解析规则；自举端通过 `parse_int()`
调用同一数值实现。两端的新版程序应生成逐字节相同的 `.la`。

原先保留旧格式 5 的方案已取消，格式 5 的 A1 字节码拒绝加载。
语言 2 使用格式 6，在原文件头后增加一个小端
u32 语言版本，值为 2；函数字节码布局与操作码不变。加载时把版本赋给
模块内所有函数，函数按定义模块的规则执行，不受调用方版本影响。
当前 VM 只接受格式 6 和语言策略 2；未知版本拒绝加载。

迁移时逐文件添加声明，并重新编译相应 `.la`。依赖原来溢出转浮点的
代码需要明确改成浮点运算；依赖截断位运算的代码改用显式回绕函数。
旧源码里 C 编译器字面量饱和、自举端拒绝越界的历史差异曾保留在语言 1；
现在这条执行路径已删除，全部 A2 源码统一精确解析。

## 验证与尚未完成的工作

`make BUILD=build-studio-refactor test-as-numeric` 同时检查优化构建与
O0 + AddressSanitizer/UndefinedBehaviorSanitizer 构建，通过两套编译器、
源码执行、字节码重载、模块调用和 Python 整数参考值验收。
前置故障对照分别移除加法溢出检查和放宽字节码策略校验，要求测试明确失败。

这一阶段固定的是后端必须保持的数值规则。原先未实现的静态前端、类型化
树、LLVM 后端、布局类型和借用检查现已有子集，见《AETHERSCRIPT_LANGUAGE_3.md》；
当前没有 Rust 性能对比结果。
字面量错误支持源码行列定位，运行错误仍使用现有函数和字节码位置回溯，
完整运行时源码映射是后续编译器重构工作。
