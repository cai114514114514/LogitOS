# Positioned insets and shared fixed projection, 2026-09-09

The native Bing baseline exposed a general producer/consumer gap. The unmodified inline CSS has `.sbox,.sbox_cn{top:20%;position:fixed;...}`, `.sbox_cn{left:0;right:0;margin:auto;...}`, and a fixed header with higher z-index. In `build/site-general/bing-native/home-retry-boxes.txt`, the query control is (0,12) 838×28 while a navigation text item is (182,0) 26×39. The visual search area therefore targets the navigation link. The inline-CSS private probe showed `topCSS=20%` but `has_top=0`; the style bridge intentionally discarded percentage offsets, and the absolute solver treated auto margins as zero. Neither defect needs a hostname or alternate site response.

`css_engine.c` now preserves composed physical percentages in `cstyle` as signed fixed-point fractions, separately from the has-value and zero-pixel states. The raw LibCSS getters are intentional: its relative public getter synthesizes an opposite edge but loses the unit through a type-only bits getter. Layout resolves the selected edge against its actual containing block instead. Logical pixel overrides clear the old percentage state. Absolute boxes resolve against their padding containing block, fixed boxes against the viewport, and relative percentages use their normal containing block with indefinite height remaining auto. Inset calc expressions remain unsupported by the underlying cascade and are deliberately not replaced by guessed values.

The positioned width/height constraints now solve auto margins after used dimensions and min/max constraints. Horizontal negative free space with two auto margins goes to the end margin according to containing-block direction; vertical auto margins split negative space too. Opposing specified insets constrain auto height even when content overflows. The reference rules are [CSS 2.2 absolute width](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-width), [absolute height](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-height), and [relative positioning](https://www.w3.org/TR/CSS22/visuren.html#relative-positioning).

Layout rectangles alone did not close the defect: the old painter, native hit, and CSSOM each subtracted page scroll from fixed descendants. `css_viewport_fixed_owner` in css.h supplies their shared viewport-origin decision, including selection's browser.c caller integrated by root. Element scrolling retains internal scrolling but stops at the nearest fixed or top-layer owner. A more distant fixed ancestor must not override a closer promoted dialog. `scrollIntoView` uses this same boundary so it cannot move the page or an external DOM scroller to reveal fixed content. This follows the engine's existing viewport-fixed layout model; transformed ancestors establishing a different fixed containing block remain unsupported.

## Evidence and limits

`make BUILD=build test-positioned-insets` passes: 70 layout/cascade assertions and 18 real-painter/native-hit/CSSOM assertions. Its prerequisites build and run the old-behavior controls: percentage offsets produce 18 failures, auto margins 9 failures, and fixed projection 6 failures. The projection failures include wrong CSSOM rectangles, elementFromPoint, native targeting, painted background location, and page movement from scrollIntoView. The first pre-fix projection run also found a harness issue (no horizontal scroll range on an auto-width body); the final fixture explicitly sets body width 1000px and asserts real scroll (50,100) before comparing coordinates. The actual top-layer gate uses focus.c's native stack, not a simulated owner.

Logs: `build/site-general/layout/positioned-final.log`, `positioned-insets/{negctl,margin-negctl,projection-negctl}.log`. The meaningful related regression run in `positioned-regressions.log` passes percentage-height 41, absolute-auto-height 39, grid 318, flex 176, CSSOM 149, element-scroll 28, and scroll-sync 23; expected negative-control failures remain in the log beside the positive passes. After the final nearest-boundary/scrollIntoView change, the projection gate is rerun; the scrolling companion gates passed again in `positioned-scroll-final.log`: element-scroll 28 and scroll-sync 23. `test-mk-wired` also passes with 221 fragments, 220 reachable and one explicitly declared wrapper.

`tests/fixtures/engine-expansion/positioned-insets.html` reports `POSITIONED-INSETS PASS` with query geometry, native-click point, elementFromPoint target and page scroll, and logs submitted input. Root owns the final disk link and guest/Bing natural-coordinate click acceptance. These host results do not claim that final guest acceptance already happened. Full shrink-to-fit/static-position behavior, inset calc, transformed fixed containing blocks, and unrelated empty-box hit coverage are separate boundaries. No production path branches on a site or framework and no network or identity change is part of this patch.
