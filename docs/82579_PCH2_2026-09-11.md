# Intel 82579LM/V：独立 PCH2 路径与验收边界

2026-09-11。新增 `e1000-pch2`，精确接受 `8086:1502` / `8086:1503`。它有独立初始化、PHY、收发和卸载代码；82574、I217、I219 不进入此路径。**这是具备收发实现的受限驱动，只有宿主寄存器模型证据，尚无 82579 实体机或 guest 联网证据。**

## 依据与适用条件

[Intel C600 / X79 官方 datasheet §5.4](https://www.intel.com/content/dam/www/public/us/en/documents/datasheets/c600-series-chipset-datasheet.pdf) 说明 PCH 的 GbE MAC 与 82579 Platform LAN Connect 的关系。寄存器定义参考 [Intel 82579 datasheet rev 2.1，章节 10、12（Intel 原文，Mouser 镜像）](https://www.mouser.com/pdfdocs/82579datasheetvol21.pdf)。初始化和 LV PHY 修正交叉核对 Intel 编写的 Linux v6.12 [ich8lan.c](https://github.com/torvalds/linux/blob/v6.12/drivers/net/ethernet/intel/e1000e/ich8lan.c)、[phy.c](https://github.com/torvalds/linux/blob/v6.12/drivers/net/ethernet/intel/e1000e/phy.c) 及同目录寄存器头文件。原始 Linux 参考副本保留于 `build-x79-pch2/reference/`；两次下载 PDF 未成功，datasheet 寄存器章节通过网页 PDF 提取核对。

本轮支持条件必须全部满足：

- 只有一个 PCH2 MAC；PCI Ethernet class、厂商和上述两个 ID 都匹配。
- PCI PM capability 可用，D0 转换读回成功，BAR0 为至少 128 KiB 的可映射 MMIO。
- `FWSM.FW_VALID=0`，并取得 `FWSM.RSPCIPHY` 复位许可和 `EXTCNF_CTRL.SWFLAG` 仲裁。
- `FEXTNVM.SW_CONFIG=0`，扩展 LCD 配置长度为零，OEM 自动加载启用；PHY 可直接通过 MDIO 访问，并确认 82579 PHY ID。
- 复位和 LAN NVM 自动初始化完成，RAR0 有有效非零单播 MAC。没有编造 MAC，也不尝试直接读取、修改或修复共享 SPI flash。

`FW_VALID` **不是“固件阻止访问”的同义词**。它表示固件已有有效模式，而本轮尚未实现该模式下的 ME / AMT 协作，所以返回明确的 `managed-firmware path not implemented`。82579V 也可能具备 Standard Manageability，不能因为 V 后缀就保证通过本驱动。本轮不声称覆盖所有 X79 板载 82579；实际覆盖比例未知。PHY 复位许可不足和 SWFLAG 争用分别有独立诊断。

## 已实现的行为

PCI Bus Master 在 D3 → D0 前关闭，避免沿用固件描述符；PME 的 W1C 状态得到保留。复位前停止 RX/TX、屏蔽中断并确认 master drain。全局 MAC / PHY 复位后保持 20 ms 无 MMIO 访问窗口，再确认复位与 LAN 初始化完成。PBA 在复位前设置，并检查硬件报告的剩余 TX FIFO 大于 4 KiB。

PHY 使用 PCH2 的 HV 访问规则：标准页在 PHY 地址 2，768 页及以上在地址 1；页选择为地址 1 / 寄存器 31，768 页映射为页零。MDIO 检查 READY、ERROR、回显地址和寄存器，使用单调时钟超时；SWFLAG 在访问前等待空闲、写入后读回，释放也确认。包含 MDIO slow mode、LV MSE 参数、自动 MDI-X、降速重试和自动协商设置；EEE / LPI 与 K1 禁用，尊重 OEM 全局禁用 GbE 的配置。保留 ME 的 RAR1–6，只修改受 SWFLAG 保护的 PCH2 SHRA0–3。

收发为单队列 legacy descriptors，64 RX / 32 TX、1500 MTU。描述符和 payload 使用 DMA ledger 分配的 DMA32 coherent buffer；CPU 指针不作为 DMA 地址。TX 保留一个空槽，DD 后才计完成，错误单独统计；RX 校验 DD / EOP / 长度 / error，按实际字节回调，再归还描述符。链路状态来自 MAC STATUS，并根据半双工调整碰撞距离。

最终开启 Bus Master 时，必须同时读回 `MASTER=1` 和 `INTX_DISABLE=1`，之后才启动 RX/TX。中断源保持屏蔽，等待公共 `netdev_irq_route()` 成功注册后才启用；没有路由时仍可轮询。共享 INTx 的零 cause / 全一 cause 不触发接收调度。正常回调使用 ICR 的 read-clear 语义，不依赖写回 ACK，也不直接发 EOI。

晚到的 FW_VALID 会使接口静默，但保留 bound 的 PCI / MMIO / netdev / DMA 身份，供随后 remove 收口。`PHY_PERMIT` 只是复位许可，运行期间单独变化不会误判成失去所有权。停机确认 IMC → IMS 清零并读取 ICR；即使 IMC 写丢，仍被绑定的离线 IRQ 回调也会读取 pending ICR，只抑制接收调度。

卸载须在公共 IRQ 释放后执行，并通过 NET_GUARD 排除旧收发调用。IRQ 仍 live、master drain 失败、SWFLAG 释放失败或中断屏蔽未确认时保留资源并隔离，不释放给分配器、不允许重绑。若复位本身未确认，则只通过 PCI config 隔离，不再次读改写 CTRL，避免重新触发复位或执行危险的过早 MMIO flush。隔离不等于已证明设备停止；其目的正是保持未知 DMA 状态下内存不被复用。

## 验收

从仓库根目录执行：

```sh
make BUILD=build-x79-pch2 test-e1000-pch2-host
make BUILD=build-x79-pch2 test-netif test-nic-drv test-mk-wired
make BUILD=build-x79-pch2 build-x79-pch2/kernel.elf -j6
```

6 个负控都是编译后执行相同夹具，并在日志内观察到目标断言变红：

| `PCH2_NEGCTL_…` | 目标红灯 |
| --- | --- |
| `IGNORE_FW` | managed firmware is explicitly refused without PHY reset |
| `STEAL_SWFLAG` | busy SWFLAG is neither stolen nor cleared |
| `WRONG_PHY_ADDR` | complete non-managed 82579 probe succeeds |
| `NO_MASTER_DRAIN` | unacknowledged master drain retains every DMA buffer |
| `ACCEPT_RX_ERROR` | RX hardware errors are never delivered |
| `OFFLINE_NO_ACK` | offline retained IRQ acknowledges pending without scheduling |

夹具替换 MMIO、PCI config、时钟、DMA allocator / ledger 和网络锁环境；生产文件内的 probe、PHY 分页、描述符收发、IRQ 与资源回收分支保持真实。154 是断言次数，包含环槽循环，不是 154 场物理测试。它证明这些生产路径在指定模型下遵守合同，不能证明真实 PHY 电气行为、SPI 配置完整性、ME 竞争、跨 CPU 锁语义、实际线速或交换机兼容性。

`qemu-system-x86_64 -device help` 的本机输出已保存为 `build-x79-pch2/qemu-devices.txt`，其中 `e1000e` 明确是 **Intel 82574L**，无 82579 模型。本轮不运行或引用它作为 82579 guest 证据。
