# X79 / Xeon E5 x2APIC 与中断路由边界（2026-09-11）

本轮补齐的是固件已经交付 x2APIC 模式时的 CPU 启动和 IPI 路径，同时保留原有 xAPIC 机器。普通镜像读取每个 CPU 的 `IA32_APIC_BASE`，在 xAPIC 模式使用 MMIO，在 x2APIC 模式使用 `0x800..0x83f` APIC MSR；普通镜像不自行切换模式。`LOGIT_X2APIC_QEMU_TEST` 只用于合成 QEMU 客体执行 MSR 后端，串口会明确打印 `TEST-ONLY-force`，不能用于描述实体 X79。

## 已实现的生产行为

- MADT 同时解析 type 0 Processor Local APIC 和 type 9 Processor Local x2APIC。type 9 的 APIC ID 与 ACPI UID 都保留 32 位；相同 ID+UID 的 type 0/type 9 重复项只计一次，单独复用 ID 或 UID 的冲突项拒绝。type 0 的保留 ID `0xff` 与 type 9 的广播 ID `0xffffffff` 拒绝。
- 只启动 flags bit 0 `Enabled` 的 CPU。flags bit 1 `Online Capable` 代表可由操作系统后续上线的禁用 CPU；LogitOS 还没有 ACPI CPU hotplug/online 引擎，因此不会把只有 bit 1 的记录误当成已在线 CPU。
- 当前上限为 32 个逻辑 CPU，覆盖单路 X79 上 Xeon E5 v1/v2 的最大常见 24 线程配置。超过容量的 MADT 记录不会覆盖数组。
- x2APIC 的 ID 读取使用 MSR `0x802`，EOI 使用 `0x80b`，INIT/SIPI/fixed IPI 通过一次 64 位 `WRMSR 0x830` 保留完整 32 位目的 ID。xAPIC 继续使用 ICR high/low MMIO，并在写前、写后检查 delivery-status；超时返回失败。
- INIT 到第一个 SIPI 使用单调时钟等待至少 10 ms，两个 SIPI 间至少 200 us。单调时钟为 0 或长时间停滞时拒绝继续启动 AP。`pit_init()` 内的 `time_init()` 早于 `smp_init()`。
- AP 启动握手绑定固定 CPU slot。AP 先发布 online count，再发布终态；一旦发出 INIT/SIPI，超时或失败的 AP 栈会隔离，不会释放给迟到的 AP 形成栈 UAF，也不会复用共享启动 mailbox。
- IOAPIC 初始化逐项先写 mask 并读回，确认后才清目的字段；异常 VER 导致 RTE selector 溢出的设备被拒绝。路由在 masked 状态下写目的/向量并完整读回，最后解掩码再读回。GSI 0/1/12 作为一个事务配置；重复 override、部分失败或回滚未确认会拒绝或停机，不会同时留下 PIC 与活跃 IOAPIC 路由。
- x2APIC CPU 的 IPI 可使用完整 32 位 ID；当前没有 Intel VT-d interrupt-remapping 所有权与 EIM 配置，因此 IOAPIC/MSI/MSI-X 的 legacy 8 位物理目的字段只接受 `0x00..0xfe`。`0xff` 是 legacy 广播值，和所有更宽 ID 一样会明确拒绝，绝不截断。若 BSP ID 无法表达，保留 PIC；AP 的 vector 32 仍按本地 LAPIC timer 发送 EOI。
- PCI INTx、MSI 与 MSI-X 都按硬件停源事务管理。任何 IRQ 请求和任何回退入口都会先同时静默设备上已有 MSI 与 MSI-X capability，并读回确认；随后才分配向量、写 message target 或启用 INTx。MSI 校验 address/data/MME/PVM 与 capability enable，MSI-X 校验 table entry、entry mask、function mask 与 capability enable，二者都确认 `Command.INTX_DISABLE`。
- MSI/MSI-X 的 setup 只要曾尝试启用却未通过读回，就必须以 teardown 的新鲜读回确认消息源已经停止；不会依据启用后的旧快照释放或复用向量。宿主故障夹具覆盖了“第一次读回看似安全、teardown 写被硬件忽略、下一次读回仍为 live”的 MSI 与 MSI-X 情况。
- IRQ teardown 只有在停源读回成功后才释放向量或拆共享 INTx member。失败时 `dev_irq_release()` 返回错误并保留 mode、vector、handler 与成员所有权；`dev_unbind()` 会取消解绑，保留 driver/drvdata，不调用 remove。MSI 到 INTx 的运行时降级同样在 release 失败时停止。

## 体系结构依据

- [Intel 64 and IA-32 Architectures Software Developer's Manual](https://cdrdv2-public.intel.com/922486/325384-092-sdm-vol-3abcd.pdf)，当前 325384-092 版：§13.12.2 规定 x2APIC 只能通过 MSR 访问；§13.12.5 规定 x2APIC 收到 INIT 后仍保持 x2APIC 且保留全部 32 位 ID，同时禁止直接 x2APIC→xAPIC；§13.12.9 定义 64 位 ICR、完整 32 位 destination 和移除 delivery-status；§11.4.4.1 / Table 11-1 给出 INIT→SIPI 10 ms、SIPI→SIPI 200 us。
- 同一 Intel 手册 §13.12.6–13.12.8 规定 x2APIC 设备中断依赖 VT-d interrupt remapping/EIM，并要求当启用 APIC ID 大于等于 255 的处理器时，固件将 BSP 和全部已启用 AP 都以 x2APIC 模式交付。§13.12.5 说明 INIT 不改变这一模式，因此普通 firmware-active x2APIC 的 AP 在 SIPI 后仍与 BSP 使用相同 MSR 后端。
- [ACPI Specification 6.6, System Description Tables](https://uefi.org/specs/ACPI/6.6/05_ACPI_Software_Programming_Model.html) 的 Multiple APIC Description Table 定义 type 0、type 9、Processor Local APIC Flags，以及 type 9 的 16 字节布局和 32 位 x2APIC ID/UID。本实现按 `Enabled` 与 `Online Capable` 的规范语义区分启动状态。

## 验证证据

生产 host gate：

```sh
make BUILD=build-x2apic-final-host test-x2apic-host
```

结果为 x2APIC 36/36、PCI INTx 43/43、device unbind 36/36、MSI/MSI-X/INTx 49/49。共 25 个生产变异全部实际变红：10 个 APIC/SMP、5 个 x2 相关 INTx/IOAPIC、2 个 IOAPIC init、1 个 unbind、7 个 MSI/MSI-X。5 个 PCI INTx 与 7 个 MSI/MSI-X focused control 各自精确产生 1 checks/1 failed；两个 init 控制分别只产生其命名的一个 `FAIL`，unbind 控制为 36 checks/1 failed。完整 INTx gate 另跑 9 个生产控制并通过：

```sh
make BUILD=build-x2apic-intx-full-final test-pci-intx-host
make BUILD=build-x2apic-msi-final test-pci
make BUILD=build-x2apic-final-host test-mk-wired
```

`test-pci` 为 PCI 58/58、device model 36/36、MSI/MSI-X/INTx 49/49；make fragment 连通性为 293 个 fragment、292 个从顶层可达、1 个按声明式 wrapper 设计保留。普通、没有 test-only 强制切换的内核也在独立目录完成链接，并分别完成 BIOS 与 UEFI 启动：


## 真机边界

上述 BIOS/UEFI 记录来自 QEMU TCG 的稀疏 APIC-ID 合成拓扑，不是实体 X79 证据。实体板仍需核对 BIOS 与 UEFI 两种启动方式下的 MADT、`IA32_APIC_BASE`、全部 CPU 上线、定时器、键鼠、存储和网卡中断。普通镜像只接收固件模式：固件给 xAPIC 就运行 xAPIC，固件给 x2APIC 就运行 x2APIC；本轮没有实现操作系统主导的全系统 xAPIC→x2APIC 转换、VT-d interrupt remapping/EIM 或 ACPI CPU hotplug。

GTX 1050 的图形驱动属于独立 PCI/GPU 工作，不由 APIC 测试证明。设备 IRQ 能路由也不证明显卡显示、加速、复位或电源管理在真机可用。
