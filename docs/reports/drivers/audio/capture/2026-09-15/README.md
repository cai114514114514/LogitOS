# AC’97 / ES1370 录音验收

本轮给 Intel 82801AA AC’97（8086:2415）和 Ensoniq ES1370（1274:5000）补上录音，支持关闭后重新录音、播放与录音同时运行。现有 HDA 录音一并回归通过。应用入口保持为：

```sh
rec 5 /rec.wav
```

这会录制 5 秒并保存 WAV；需要启动包含本轮内核的镜像。验收镜像为 `build/drivers/audio/capture-kernel/logit.iso`，SHA-256：

```text
481fb9f016e6aea28bcdae5f6e1d2cdb1332ec1cd87406f4cfdf7313957ef271
```

## 实现

- AC’97：独立 PCM 输入 DMA 环和描述符表，通过立体声 ADC 的麦克风路由录音；校验 ADC 就绪和实际采样率；共用 IRQ 时分别处理播放与录音完成通知。
- ES1370：独立 ADC DMA 环，保留 DAC2 / ADC 共享的时钟、控制寄存器和辅助 DMA 缓冲区。停止一个方向时保留另一个方向；启动或停止失败时隔离整卡，避免继续访问可能仍归硬件所有的内存。
- 共享录音层：输入设备独立注册和初始化；拒绝未选中设备的完成通知；DMA 环溢出后跳过正在写入的槽；关闭、重开和设备移除保留正确的生命周期。
- 可读性：驱动分别位于 `c/drivers/audio/ac97/` 和 `c/drivers/audio/es1370/`，拆分编解码器、流操作、共享引擎和 PCI 生命周期。没有修改 `rec` 或其他应用。

## 实际录音与双工

QEMU 11.0.0 的公开 D-Bus 音频输入接口供应确定的非周期 PCM。模拟控制器通过 DMA 接收数据，来宾系统的原有 `/bin/rec` 经正常系统调用录音并写入私有磁盘。宿主随后从磁盘提取 WAV，逐字节核对。没有使用宿主麦克风，没有给内核 DMA 缓冲区写入测试替身数据。

每张卡执行两次 `rec 1`，第二次同时播放 `sndtest ramp 3000 &`。检查录音重新打开后使用新的输入区间，且第二次 ADC 启停全部处于 DAC 的播放区间内，录音停止后播放继续。

| 模拟声卡 | WAV 格式 | 两次录音帧数 | 在输入轨迹中的字节起点 | 同时播放的有效帧数 | 结果 |
| --- | --- | --- | --- | --- | --- |
| HDA | 48000 Hz / s16 / 双声道 | 48000、48000 | 0、195840 | 144000 | [通过](guest/intel-hda/result.json) |
| AC’97 | 48000 Hz / s16 / 双声道 | 48000、48000 | 0、193920 | 144000 | [通过](guest/AC97/result.json) |
| ES1370 | 48662 Hz / s16 / 双声道 | 48662、48662 | 0、198272 | 145987 | [通过](guest/ES1370/result.json) |

六份 WAV 的全部音频数据均与各自输入区间逐字节相同。三张卡的播放轨迹均通过振幅、声道极性、斜率和相位连续性检查，计数为 600 次过零、0 个错误步进。ES1370 按实际整数分频率工作，共享混音器会将播放数据重采样。两种采样率的测试都不把串口成功文本当作音频成功证据。

各卡的 `guest/` 子目录保留 `source.pcm`、`injected.pcm`、`playback.pcm`、两份 WAV、串口和后端日志、QMP 记录、命令及校验结果。原始 ISO 和私有磁盘保留在 `build/drivers/audio/capture-verify/audio-capture/guest.hK2rDc/`。每次测试均复制独立磁盘；只读模板不含这两份录音文件，测试前后哈希相同。

## 失败对照与回归

同一套后端、模板和验收程序启动上一轮仅支持播放的冻结镜像，两张新增声卡均正常启动，音频后端均报告就绪，但 `rec` 返回 `REC_FAIL open=-1`、测试退出 1，输入数据为零。原始失败结果保留在 [旧版本对照](before/controls.json)，没有改写为录音成功。旧 ISO 的 SHA-256 为 `f61ccff42352e9f7cb3060fa774c58a3f82c1eda498ba66a8d8a5e3167a58c5f`。

[宿主检查日志](logs/host.log)记录了生产代码 ASan/UBSan 检查及必跑的错误变体：

| 检查 | 成功结果 |
| --- | --- |
| PCM / HDA 回归 | 71 / 36 项，0 失败 |
| AC’97 正常及完成失败分支 | 101357 / 96358 项，0 失败 |
| ES1370 | 253319 项，0 失败 |
| 共享录音层 | 273 项，0 失败 |
| 播放轨迹校验器 | 26 个正反例 |
| 录音轨迹及生命周期校验器 | 24 个正反例 |
| Make 接线 | 377 个片段：376 个可达、1 个明确声明 |

错误变体实际触发失败，包括丢弃录音完成通知、重复计算 AC’97 末尾位置、错误描述符长度、复制正在写入的 DMA 槽、接受未选中设备中断。录音校验器会拒绝静音、交换声道、重复或乱序周期、短录音、错误采样率、重开后复用旧数据、缺失停止事件、没有双工重叠、损坏的输入或播放数据。

[无声卡回归](logs/no-audio.log)通过：无设备和当前不驱动的 virtio-sound 均正常启动，返回无设备状态，Shell 继续工作。

首次完整复验曾被串口日志穿插打断的 `REC_OPEN` 字段误判，实际 PCM 检查通过。现已由两份真实 WAV 文件头验证采样率、声道和格式，由 ADC 启停事件验证两次打开；录音完成与错误标记检查保留。原始误判的 [结果](harness-correction/result.json)和 [日志](harness-correction/serial.log)保留，修正后的三卡完整目标重新运行并退出 0。

## 复现与边界

```sh
make BUILD=build/drivers/audio/capture-verify \
  AUDIO_CAPTURE_ISO=build/drivers/audio/capture-kernel/logit.iso \
  AUDIO_CAPTURE_DISK=build/drivers/audio/capture-template/disk.img \
  test-audio-capture-os
```

前提是已有上述内核 ISO、有效应用磁盘以及支持 D-Bus 的 QEMU 和 GIO 开发库。每次运行创建新的来宾结果目录。验收前已再次核对 [44 份音频源码及输入清单](source-manifest.json)、全部来宾产物哈希，结果见 [verification.json](verification.json)。共享工作区其他模块不是本报告的变更范围。

本轮证明模拟硬件上的 ADC → DMA → 系统调用 → WAV 路径及上述双工行为；尚未进行实卡麦克风录音验证。物理 AC’97 / ES1370 当前均将单声道麦克风路由到两个 ADC 声道；QEMU 可输入独立立体声，不证明物理双麦克风。AC’97 模拟器的 136/255 音量约定与实卡 +12 dB 增益规律不同。未提供输入源选择界面、USB Audio 或多输入混合，现有播放混音器的热拔插后重新绑定限制仍在。
