# 音频驱动与多声卡扩充

本轮新增三个 Intel AC’97 控制器型号，补齐独立输入设备注册和播放设备重新注册的生命周期。三张单卡、两组多卡的最终来宾验收全部通过，共十段一秒 WAV 与输入轨迹逐字节一致。

## 新能力与文件结构

| 控制器 | PCI ID | 本轮处理 |
| --- | --- | --- |
| 82801AA ICH | 8086:2415 | 原有支持回归 |
| 82801AB ICH0 | 8086:2425 | 新增，采用固定双声道引擎 |
| 82801BA/BAM ICH2 | 8086:2445 | 新增，清除继承的 4/6 声道模式并读回确认 |
| 82801CA ICH3 | 8086:2485 | 新增，同样处理声道模式；保留该代保留位 |

型号表和初始化属性集中在 `c/drivers/audio/ac97/ac97_models.h`、`models.c`，同一清单生成 PCI 匹配表，避免设备编号与初始化逻辑漂移。控制器、编解码器、DMA 流、PCI 生命周期仍分别由各自文件负责。依据与精确章节见 [驱动说明](../../../../../c/drivers/audio/ac97/README.md)。ICH4 以后、440MX、VIA、SiS 没有套用这些型号的初始化规则，仍明确拒绝。

HDA 已占用播放时，AC’97 现在可以只注册录音，不会因播放注册失败而拆掉 ADC，也不会初始化另一张卡的混音器。ES1370 原有的独立录音路径加入了相同的组合回归。系统仍分别选择首个成功注册的输入和输出，没有新增设备选择界面。

共享播放层将长期存在的工作线程、信号量、等待队列与当前设备的 DMA 状态和临时缓冲区分开。重复初始化不再重置等待者或泄漏缓冲区；解绑使旧流失效，换用不同采样率、声道数、周期大小的设备时重新准备缓冲区并启动 DMA。过期设备的中断不会推进当前设备。

同时修复两处可观察的数据问题：八声道 F32 输入曾进入按双声道分配的临时缓冲区；小 DMA 环的静音填充可能覆盖正在播放的槽。新增几何检查还拒绝会使 Q16.16 重采样相位溢出的周期大小。应用 ABI 和应用代码均未改变。

测试按职责分目录：`tests/drivers/audio/playback/` 验证共享播放层；`capture/profiles.py` 描述设备组合与各方向时钟，`guest.py` 启动系统并运行应用，`backend.c` 供应/接收 PCM，`oracle.py` 核验文件和音频轨迹。

## 最终来宾结果

所有配置均执行两次 `rec 1`，第二次同时运行 `sndtest ramp 3000 &`。多卡配置使用 **只有输出的 HDA codec**，所以 HDA 无法替第二张卡完成录音。输入和输出分别使用实际采样率，包括 ES1370 输入的 48662 Hz 与 HDA 输出的 48000 Hz。

| 配置 | 输入 / 输出 Hz | 每段录音帧数 | 三秒播放有效帧数 | 结果 |
| --- | --- | --- | --- | --- |
| HDA 单卡 | 48000 / 48000 | 48000 | 144000 | [通过](guest/single/intel-hda/result.json) |
| AC’97 单卡 | 48000 / 48000 | 48000 | 144000 | [通过](guest/single/AC97/result.json) |
| ES1370 单卡 | 48662 / 48662 | 48662 | 145987 | [通过](guest/single/ES1370/result.json) |
| HDA 输出 + AC’97 输入 | 48000 / 48000 | 48000 | 144000 | [通过](guest/multicard/AC97/result.json) |
| HDA 输出 + ES1370 输入 | 48662 / 48000 | 48662 | 144000 | [通过](guest/multicard/ES1370/result.json) |

每组都验证完整录音字节、重新打开后的独立输入区间、录音启停全部位于播放区间内，以及录音停止后播放继续。五份播放轨迹均为 600 次过零、0 个错误步进，并通过振幅、声道极性、频率和相位检查。ES1370 的输出帧数包含共享混音器从 48 kHz 到实际分频率的重采样。

数据由 [QEMU 的公开 D-Bus 音频接口](https://www.qemu.org/docs/master/interop/dbus-display.html)供应，经过模拟硬件 DMA、正常系统调用和来宾文件系统保存。没有访问宿主麦克风，也没有向内核 DMA 环塞入替身数据。`guest/` 保留完整原始输入、实际供应的输入、实际输出、WAV 和日志，可重新运行 PCM 校验器。

旧镜像的同一多卡配置中，HDA 和系统正常启动，但 AC’97 录音返回 `REC_FAIL open=-1`。该结果作为 [前后对照](before.json)保留，原始失败结果未改写。旧 ES1370 组合的录音正确，但那次播放轨迹少了 4096 帧；单次观察不足以区分旧混音逻辑与调度影响，因此不据此声称某项修改的单独因果或性能提升。

## 宿主检查、负对照与构建

[完整检查日志](logs/gates.log)中，PCM 71、HDA 36、AC’97 125540 / 120541、ES1370 253319、录音框架 273、播放框架 200428 个检查全部通过；这些是检查计数，包含逐字节/逐样本断言，不代表同等数量的独立场景。

新增播放测试实际调用生产工作线程和 PCM 转换代码，检查 DMA 环字节。它覆盖不同几何设备间重新注册、阻塞写入时解绑、分配失败回滚、启动失败保留、同步到达的中断、小环和八声道 F32。四组前置错误变体真实失败：重复初始化 2053 个失败、接受错误设备中断 1026 个失败、覆盖当前槽 64 个失败；恢复旧双声道临时缓冲区则在 `eight_channel_float_input → kaudio_thread → pcm_ring_peek` 路径触发明确的 ASan 越界。

AC’97 五组前置错误变体也被检出，包括忽略 ICH2 模式读回及重置其他播放设备。四个受支持型号都通过了独立寄存器模型中的实际播放/录音 DMA、IRQ 和逐样本检查。录音校验器的 52 个正反例覆盖不同输入/输出时钟、静音、错序、错误采样率、旧录音复用、缺少双工和损坏的播放等情况。播放校验器原有 26 个正反例保留。

最终 Make 目标退出 0；接线检查为 378 个片段、377 个可达、1 个明确声明。内核构建通过，未修改应用，所以使用已有的只读应用磁盘模板并为每个来宾复制私有磁盘。无声卡和不支持的 virtio-sound 配置另由 [无声卡日志](logs/no-audio.log)验证正常启动、无设备返回和 Shell 存活。

## 尚未证明的部分

新增 ICH0/2/3 型号通过的是寄存器模型测试；QEMU 的 AC’97 对应原有 2415 型号。新增型号尚未实卡验证，模拟输入也不证明物理麦克风接线和模拟增益。播放层重新注册测试不等于物理热插拔：硬件停机与 DMA 释放仍由驱动确认，隔离后的故障设备不会被自动恢复。现有 `thread_create()` 无返回值，播放层无法检测其内部内存分配失败；这项限制保留在代码和测试说明中。
