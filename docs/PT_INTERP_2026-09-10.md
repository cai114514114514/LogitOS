# 内核 PT_INTERP：2026-09-10

本轮接上 LogitOS 的解释器启动契约。普通内核接受裸 ELF 和 AEX 内嵌 ELF 中的一个 `PT_INTERP`，装载主程序及指定的裸 `ET_DYN` 解释器，从解释器入口开始执行。旧 `ET_EXEC`、静态 PIE 和旧 GUI 入口继续保留。完整用户态动态加载器、共享库符号解析、`dlopen` 和 Linux 二进制兼容层仍属于后续工作。

内核保留主程序的 `AT_ENTRY`、`AT_PHDR/PHENT/PHNUM`、`AT_RANDOM`，另用 `AT_BASE` 传递解释器 load bias。没有解释器时 `AT_BASE=0`。解释器接收相同的 argc/argv/envp/auxv；GUI 仅在 interpreted 分支使用这个栈头，继续遵守 AEX 的栈页数提示及原参数接口。`elf_image.entry` 始终表示主程序入口，新增 `start_entry` 表示第一次执行的位置。无法传递启动栈的旧 scalar loader 接口明确拒绝 interpreted image。

解释器路径必须是 2–128 字节的绝对、NUL 结尾路径，不能有内嵌 NUL、重复或嵌套解释器。解释器文件经过调用者的读和执行权限检查，独立取得和释放页缓存引用；其 `PT_LOAD`、文件范围、入口、TLS 模板和动态表位置继续经过 ELF 结构校验。解释器只接受裸 ET_DYN，不接受 AEX 解释器链或 ET_EXEC 解释器。单对象保留既有 256 MiB 装载上限。

主程序及解释器的动态重定位、TLS 建立、RELRO 收紧由用户态解释器负责，内核不会提前修改它们的重定位目标或安装静态 TLS。没有 `PT_INTERP` 的静态 PIE 仍走原有受限 RELATIVE 重定位路径。这个职责划分对应 [ELF gABI 的程序解释器约定](https://gabi.xinuos.com/elf/08-dynamic.html) 和 [程序头定义](https://gabi.xinuos.com/elf/07-pheader.html)。测试中的 `ld-logit-test.so` 只处理 RELATIVE 与单个静态 TLS 模板，并明确拒绝共享库导入；它是验收程序，没有作为生产加载器安装到普通应用磁盘。

主 PIE 默认在 1 TiB 附近，解释器在 1.5 TiB 附近，使用现有确定性槽位轮换；这不是 ASLR。两对象真实装载跨度及附加元数据发生碰撞时拒绝装载。缺少可选 `PT_PHDR` 描述符时，若程序头表位于实际 LOAD 文件范围内，仍推导它的真实用户地址，不用元数据副本掩盖 load bias。

解释器需要通过 `mprotect` 收紧 RELRO，因此 eager LOAD 同样登记 VMA，并与文件缓存 VMA 保持各自所有权。主程序、解释器的附加元数据页也登记为只读 VMA，防止 mmap 的显式 hint 将它们当作空闲区。单页 GUI 栈不能按 CLI 的两页最小预映射量写到栈区以下；真实负向控制已证明这会覆盖解释器元数据。

`execve` 先在独立地址空间装载两个对象并建立完整新栈，全部成功后才发布新 CR3。失败恢复原空间，保留 TLS、文件描述符、能力和信号状态；成功后退出新空间的 MM guard，再回收旧空间，避免反转锁顺序。原有多线程 exec 拒绝与 sibling 创建互斥仍有效。代价是装载期间新旧常驻映像同时占用内存，不能把此改动描述为峰值内存优化。

实际解释器程序还暴露了旧 fork 的 FP 继承问题：编译器把 envp 初始化数据保存在 XMM0，内联 `int 0x80` 后仍继续使用；原 fork bootstrap 却重置了 FPU。现在把中断入口在执行内核 C 前保存的 FXSAVE 状态复制到子线程独立、16 字节对齐的内核栈，发布前完成复制，bootstrap 恢复后再返回用户态。验收比较 MXCSR、x87 控制/状态、全部 16 个 XMM，并执行 x87 运算验证父子结果。没有逐位比较整个 512 字节 FXSAVE 区域，也没有新增 AVX/XSAVE 支持。

## 本轮证据

最终独立构建和日志目录为 `/tmp/logitos-interp-20260910/final/`，源码固定在同级 `source/`。统一报告为 `ptinterp-acceptance.json`，逐阶段记录命令、退出状态、日志和输入/镜像哈希；只有全部检查通过且声明的源码输入未变化才写入 `passed=true`。

最终结果为 **23 个阶段全部通过，1093 个声明输入未变化，25 个内核/启动/磁盘镜像哈希已记录**。`delivery.json` 另记录固定源码路径、本轮 47 个实现和测试文件与工作区一致、普通 Makefile 接线存在，以及没有遗留本轮 QEMU。普通内核 SHA-256 可从该目录的统一报告查到；浏览器和第三方源文件未由本轮修改。

- 新 loader 主机测试链接真实 `elf.c` 和 `interp.c`：普通与 ASan/UBSan 各 **189 个断言、0 失败、16 次打开/16 次释放**。覆盖路径错误、权限、重复/嵌套解释器、对象碰撞、可选 PT_PHDR、两对象物理分配失败及引用回滚。
- 主机四个控制先于正向执行：错误启动主入口、清零 AT_BASE、内核提前重定位主程序、提前收紧 RELRO，分别由 `START_ASSERT`、`BASE_ASSERT`、`DEFER_ASSERT`、`RELRO_ASSERT` 抓住。崩溃不能代替这些断言。
- 普通内核 BIOS/UEFI × 512 MiB、2 GiB、8 GiB 共 **6 组 PT_INTERP 验收通过**。每组实际执行 raw PIE、AEX PIE、固定 ET_EXEC 的主进程、fork/exec 子进程和 cap_spawn 子进程，另启动普通与单页栈 GUI。均验证主/子线程 TLS、全局和函数指针、参数/环境、凭据、退出结果及文件页内容。
- 最终每组记录 11 次解释器通过、9 次 `PTINTERP_MAIN_PASS`、3 次各类主/子/cap 程序通过标记、两种 GUI 标记和父子 FP 标记。客体串口可能与另一核内核日志交错，因此 runner 同时要求各个下游程序的实际检查结果。
- 示例主程序 entry 为 `0x10040004580`，解释器 base/start 为 `0x18050000000` / `0x18050004400`；下一次同一主程序使用不同 bias。固定 ELF 的 main bias 为 0。主程序加解释器每次保留 6 个实际文件页、2 个缓存区域，另复制 30 页；payload 强制首次读入两对象文件内容，不能仅凭容量日志算通过。

每组在同一进程中执行 132 次失败 exec，涵盖缺失、无执行权限、嵌套与非法格式解释器。第一轮预热后，实测已用物理页如下：

四种单独构建的错误内核先于普通矩阵运行，全部由具体客体断言抓住：

控制源码仅生成在各自 BUILD 内，不覆盖共享源码或普通对象缓存。

本轮重跑既有 BKL 主机套件时，发现 PCI 发布控制依靠 10 ms 延时，可能因线程同时进入锁等待而漏检。修正测试叶子，在映射尚未完成的真实调用边界观察生产代码的 ready 状态；PCI 生产代码未改。原始漏检记录留在 `/tmp/logitos-interp-20260910/reg-host.log`，修正后完整 BKL 主机套件通过。

高堆、普通模块装载和 BKL 各自的 BIOS/UEFI × 三种内存矩阵均通过，共 18 组。8 GiB 的两组高堆压力测试均实际写读校验 **1,342,176,960 字节**、167,772,120 个 64 位字；其中高于 4 GiB 的 arena 为 1,358,954,496 字节。普通内核的 BKL 源码/ELF 结构检查通过，测试内核继续通过同时进入内核与可中断 syscall 断言。MM/FS 客体工作量本次为 277–284 ms，没有同场旧内核基线，不作提速比较。

`final/regression/dma-acceptance.json` 完整通过：宽内存/静态 PIE 六组矩阵，NVMe/AHCI 两固件各两次启动的读写校验，virtio 队列、数据、网络、GPU/光标、RNG 和 balloon，两固件的 e1000/RTL8139、禁 PS/2 的 USB 输入、HDA 播放与捕获、TextEdit/IME，以及正常停止和资源回收。两固件均实际使用 8 个高于 4 GiB 的 virtio 队列；virtio-net 真实传输 32768 字节，FNV-1a 均为 `fb2a9dc5`。HDA 播放从 WAV 核对 48000 帧波形，捕获通过 DMA 哨兵覆盖与停止检查。停止后 coherent、mapping、pin、bounce、quarantine 等计数归零，详细地址及计数保留在该 JSON 和串口日志中。

普通内核另在 BIOS/UEFI、8 GiB、4 CPU 下通过 TextEdit/IME：ASCII 控制、`你好` 候选，以及保存后逐字节相同的 66 字节 `你好，我爱中国。你好吗？女孩输入法二维码西安`。1/2/4/8 CPU 的等待检查通过；线程互斥计数为 24000/24000，2000 次 create/join 后描述符数回到 1，8 个 detached 线程均运行并回收；52 项信号检查和四核 120 次 fork/exec 通过。最终堆并发测试 `T1=5940 ms`、`T4=6340 ms`、4 个不同 CPU、`corruption=0`，满足原有并行门槛；这是本次客体回归值，不是与旧版本的性能对比。

## 重跑与边界

```sh
cd /Users/wangzhe/system/LogitOS
make BUILD=/tmp/logitos-ptinterp-check \
  PTINTERP_APPS_DISK=/Users/wangzhe/system/LogitOS/build/disk.img \
  test-ptinterp-all
```

入口从指定磁盘提取已有应用到私有目录，记录源磁盘和恢复文件哈希，避免重编浏览器或第三方。已有完整应用构建时，可省略 `PTINTERP_APPS_DISK` 并指定 `WIDE_BASE_BUILD=/path/to/apps-build`。本轮用当前 `build/disk.img` 恢复应用；旧高堆/BKL 临时构建在开始时已不存在，未冒充本次性能基线。

首轮 `acceptance/` 执行期间，其他任务修改了共享 Makefile 的浏览器测试接线和两个加密头文件的注释，源码一致性条件不再成立。因此复制源码到独立 `source/`，核对本轮 loader、调度和测试文件后，从该固定副本重新执行整个入口，输出到 `final/`。两次记录保留分开；首次功能通过不能代替最终固定版本验收。在多人同时编辑时，应在固定源码副本或独立 checkout 中运行上述命令。

`test-ptinterp-host` 提供短主机检查，`test-ptinterp-os` 提供新 loader 启动矩阵，`test-ptinterp-all` 另外按顺序运行四个错误内核控制及高堆、模块、BKL、宽内存、静态 PIE、DMA、普通 TextEdit/IME、等待、线程、信号和 fork 压力回归。所有新 fixture 在 `tests/unit/`，客体驱动在 `tests/boot/`，make 接线在 `tests/ptinterp.mk`；未新增第三方依赖或改变许可证位置。

本轮不提供提速结论。普通高堆及低区模块/页表约束沿用上一轮；复用 DMA 报告中的“kernel heap remain low”是旧阶段遗留描述，由高堆报告及本次高堆实测取代。RTL8169 仍只有真实驱动加寄存器/DMA 仿真覆盖；QEMU 结果不代表实体硬件验证。后续步骤是 LogitOS 用户态动态加载器与共享库：符号和依赖解析、动态 TLS、库搜索与生命周期，之后再单独交付运行时 `dlopen`。
