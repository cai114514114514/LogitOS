# M21-P3 — compiler.as: AetherScript compiles itself

The capstone of the language line: the **compiler** (source -> .la bytecode) is
rewritten in AetherScript; the VM stays C (it IS the machine — rustc/Go's
standard meaning of self-hosting). Prerequisites all landed: dict (M21-P1),
LibAether (P2), modern strings/f-strings/comprehensions/multi-assign (M23),
classes/closures/GC/exceptions (M22), `.la` + `as -c` (P3 infra), system access
(M23.5).

## Locked decisions

- **Output**: the exact existing `.la` format — "LAQ1" + u32 AS_BC_VERSION(3),
  recursive fn records (arity, upvalue_count, name, code, tagged consts),
  little-endian. The C VM loads it unmodified (`module_try_la` / `as -c` parity).
- **Compiler state lives in classes** (Lexer, Compiler with `enclosing`), never
  module globals — AetherScript has no `global` keyword (a function cannot
  rebind a module global), so the C compiler's `T/P` file-statics translate to
  `self.` fields.
- **Constants carry their tag**: the const pool is a list of `[tag, value]`
  pairs (K_NIL..K_FN mirror as_bc.c). The language has no `type()`; the
  compiler always knows what it is adding, so introspection is never needed.
- **Functions are dicts** during compilation: `{arity, upcount, name, code:
  [ints], consts: [[tag,v]...]}`; nested defs nest dicts; the serializer walks
  the tree.
- **Bytecode bytes** build as a list of ints; binary file = `"".join([chr(b)
  for b in out])` written via the portable `file_write` native (an ObjStr may
  contain NUL bytes; write length = len(s)).
- **Full language coverage** is the target (it must compile ITSELF, and itself
  uses classes/closures/f-strings/comprehensions). Anything asc.as cannot
  compile that the C compiler can is a bug, not a scope cut.

## New portable natives (S0 — the only C this milestone adds)

`chr(n)` / `ord(s)` (byte building + char classification: the language has no
string ordering, only ==), `file_read(path) -> str|nil` and
`file_write(path, s) -> int` (fopen-based: work on the HOST asc binary AND on
Aether's mini-libc — the fixpoint test runs on the host, so compiler I/O must
not depend on Aether syscalls), `f64bits(x) -> int` (IEEE-754 bits for K_FLOAT
constants; no other way to get them from script), `args() -> [str]` (script
argv from as.c, so `as asc.as in.as out.la` works).

## Stages & gates

- **S0** natives + host tests (test-as).
- **S1** `lib/aslex.as` — the tolerant-free, full lexer (INDENT/DEDENT,
  brackets continuation, f-strings, all operators). Gate: a `-lex` dump mode in
  the C asc + a harness comparing token streams over the whole `fsroot/as`
  corpus — byte-identical type:text:line streams.
- **S2** `lib/asc.as` core — Pratt expressions, statements, functions/locals/
  jumps, the .la writer. Gate (the real one): a snippet corpus (drawn from
  as_test) where `run(.la compiled by asc.as)` output == direct interpretation
  output, host-side, automated.
- **S3** full features: closures/upvalues, classes/super, try/except/raise,
  f-strings, comprehensions, multi-assign, import/from, break/continue,
  compound assign, dict/list literals. Gate: corpus extended to every feature
  family.
- **S4** self-hosting proof:
  - stage1: C `asc -c asc-driver.as` -> the AS compiler runs on the VM;
  - stage2: AS compiler compiles its own source -> asc2.la;
  - stage3: asc2.la (the self-compiled compiler) compiles the same source;
  - **fixpoint: stage2 == stage3, byte-identical** (the classic proof: the
    compiler compiled by itself behaves identically to the compiler compiled
    by the reference).
  Plus on-OS: `/bin/as /usr/as/asc.as` compiles an example on Aether and the
  resulting .la runs.

## Risks

- Jump patching/exact stack discipline must mirror compiler.c precisely; the
  corpus gate (run-output equality, not byte equality vs C) is what catches
  semantic drift while allowing layout differences.
- Interpreted-compiler speed: ~10k tokens of self-source through a Pratt
  parser on the VM; host fine, on-OS gate uses a small input.
