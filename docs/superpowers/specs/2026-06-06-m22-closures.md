# M22.1 — AquaScript 闭包 + lambda（upvalue 模型）

## 动机
AquaScript 有函数/递归/模块,但**嵌套函数不能捕获外层变量**——内层 `def` 引用外层局部
会被当成 global 解析(`resolve_local` 找不到就发 `OP_GET_GLOBAL`),运行时报 undefined。
闭包是"脚本语言 vs 玩具"的分水岭,也是后续**类**(方法 = 绑了 `self` 的闭包)的地基。
本里程碑加**真闭包(按引用捕获)+ lambda 匿名函数**,采用 clox 的 upvalue 模型。

这是 M22「AquaScript 进阶」的第 1 阶段。顺序:**闭包 → GC → 类 → 异常**(硬依赖:类建在
闭包上;GC 紧跟闭包,因为闭包是第一种"逃出栈"的对象,正好逼出 GC、且越晚做要回溯纳入标记的
对象越多)。GC/类/异常各自后续独立 spec。

## 北极星语义（已定）
**真闭包,按引用捕获,包括写。** 计数器闭包必须工作:
```
def counter():
    c = 0
    def inc():
        c = c + 1        # 改的是 outer 的 c(SET_UPVALUE),不是新建局部
        return c
    return inc
f = counter()
print(f(), f(), f())     # 1 2 3
```
两个已定决策:
1. **写被捕获的名字 = 改外层那个变量**(JS/Scheme 风,无 `nonlocal` 关键字)。代价:内层不能用
   赋值"遮蔽"同名外层变量——对 AquaScript 这点简化可接受。
2. **每个 `def`/lambda 都编译成 `ObjClosure`**(没捕获的也是 0-upvalue 闭包),统一调用约定。
   顶层脚本仍直接跑(其 frame 的 closure = NULL;顶层不可能有 upvalue)。

## 架构

### 对象层（`aqs.h` + `object.c`）
- `ObjUpvalue { Obj obj; Value *location; Value closed; struct ObjUpvalue *next; }`
  —— 开放时 `location` 指向栈上活变量;**关闭**时把值拷进 `closed`、`location` 改指 `&closed`。
  `next` 串成 VM 的 open-upvalue 链(按栈地址降序,便于去重 + 关闭)。
- `ObjClosure { Obj obj; ObjFn *fn; ObjUpvalue **upvalues; int upvalue_count; }`。
- `ObjFn` 增 `int upvalue_count`(编译期确定;`aqs_fn_new` 初始化为 0)。
- 新 `ObjType` `O_CLOSURE`、`O_UPVALUE`;`IS_CLOSURE/AS_CLOSURE`;`aqs_closure_new(fn)`、
  `aqs_upvalue_new(Value *slot)` 原型。
- `aqs_free_objects`:`O_CLOSURE` 释放 `upvalues` 数组(不释放 upvalue 对象本身——它们各自在链上);
  `O_UPVALUE` 无额外分配。

### 新增 opcode（`aqs.h` 的 OpCode 末尾追加,不重排）
- `OP_CLOSURE <fn常量>`:其后紧跟 `upvalue_count` 组、每组两字节 `(is_local, index)`。
- `OP_GET_UPVALUE <slot>` / `OP_SET_UPVALUE <slot>`。
- `OP_CLOSE_UPVALUE`(关闭栈顶局部对应的 upvalue,然后弹栈)。

### 编译器（`compiler.c`）
- `Compiler` 增 `struct { uint8_t is_local; uint8_t index; } upvalues[256];`(数量 = `fn->upvalue_count`);
  `Local` 增 `int is_captured`(默认 0)。
- `add_upvalue(c, index, is_local)`:在 `c->upvalues` 里去重;不存在则追加、`fn->upvalue_count++`;
  返回 upvalue 下标;>255 报错。
- `resolve_upvalue(c, name)`:
  - `c->enclosing == NULL` → -1。
  - `local = resolve_local(enclosing, name)`:找到 → `enclosing->locals[local].is_captured = 1`;
    返回 `add_upvalue(c, local, 1)`。
  - 否则 `up = resolve_upvalue(enclosing, name)`(递归):找到 → 返回 `add_upvalue(c, up, 0)`。
  - 否则 -1。**支持跨多层捕获**(upvalue-of-upvalue)。
- 读名字 `variable()`:`resolve_local` → `GET_LOCAL`;否则 `resolve_upvalue` → `GET_UPVALUE`;
  否则 `GET_GLOBAL`。
- 写名字 `store_name()`(顺序很关键):`resolve_local` → `SET_LOCAL`+POP;否则 `resolve_upvalue` →
  `SET_UPVALUE`+POP;否则 `enclosing == NULL` → `DEF_GLOBAL`;否则 `add_local`(新局部)。
  —— 这条让"写被捕获的名字改外层"成立(决策①)。索引赋值 `name[i]=v` 走 `assignment()` 的既有
  路径,其中对 `name` 取值也要先 local→upvalue→global(让 `d[i]=v` 中 `d` 是 upvalue 时也对)。
- `fun_declaration`:编完嵌套 fn 后,发 `OP_CLOSURE <fn常量>`,再逐 upvalue 发两字节
  `(is_local, index)`(取自 `comp.upvalues`),然后照旧绑定(`DEF_GLOBAL`/`store_name`)。
- `end_scope`:被弹出的局部若 `is_captured` 则发 `OP_CLOSE_UPVALUE`,否则 `OP_POP`(原样)。
- **lambda**:把 `fun_declaration` 的"开 Compiler→收参数→编译体→收尾发 OP_CLOSURE+upvalue 字节"这段
  抽成共用 helper `compile_function(name, is_lambda)`;`fun_declaration` 调它(`is_lambda=0`,体是 `block()`)
  并随后绑定名字;新前缀解析器 `lambda_()`(`lambda` 关键字 `T_LAMBDA`)调它(`is_lambda=1`,参数列表无括号、到 `:` 为止,
  体是**单个表达式**编成 `表达式;OP_RET`,名字 `"<lambda>"`),把闭包当表达式值留栈上、不绑定。

### VM（`vm.c`）
- `Frame` 增 `ObjClosure *closure`(顶层脚本 = NULL;`frame->fn` 仍始终有效 = closure->fn 或 script)。
- VM 增静态 `ObjUpvalue *open_upvalues`(`reset_stack` 清空)。
- `call_value` 加 `O_CLOSURE` 分支 → `call_closure(cl, argc)`:校验 `cl->fn->arity`、`frame->fn=cl->fn`、
  `frame->closure=cl`、`slots = sp-argc-1`。保留 `O_FN`→`call_fn`(脚本/兜底)。
- `OP_CLOSURE`:读 fn、`aqs_closure_new(fn)`,for i<upvalue_count 读 `(is_local,index)`:
  is_local → `cl->upvalues[i] = capture_upvalue(frame->slots + index)`;否则
  `cl->upvalues[i] = frame->closure->upvalues[index]`。push 闭包。
- `capture_upvalue(Value *slot)`:沿 `open_upvalues`(降序)找 `location==slot` 复用;否则
  `aqs_upvalue_new(slot)` 并按序插入链。**保证多个闭包捕获同一变量时共享同一 ObjUpvalue。**
- `OP_GET_UPVALUE slot`:`push(*frame->closure->upvalues[slot]->location)`。
- `OP_SET_UPVALUE slot`:`*frame->closure->upvalues[slot]->location = peek(0)`。
- `close_upvalues(Value *last)`:把链上 `location >= last` 的 upvalue 关闭(`closed=*location`;
  `location=&closed`;摘链)。
- `OP_RET`:丢弃帧前先 `close_upvalues(frame->slots)`。`OP_CLOSE_UPVALUE`:`close_upvalues(sp-1); pop()`。

### value.c
- 打印闭包同现在的 `<fn>`(或 `<fn 名>`);upvalue 不对用户可见。truthy:闭包为真;相等:按引用。

## 风险 / 注意
- **`READ_CONST`/`resolve_global` 用的是 `frame->fn`**——保持 `frame->fn` 始终有效(= closure->fn),
  这些既有引用就不用改,改动最小。
- **栈复制移动 upvalue location 失效?** 值栈是固定数组(`stack[STACK_MAX]`),槽地址在函数活跃期间稳定;
  `OP_RET` 关闭后 upvalue 改指自己的 `closed`,之后栈槽复用也不影响。无搬移问题。
- **open_upvalues 链必须在 `OP_RET`/`OP_CLOSE_UPVALUE` 正确摘除**,否则悬空指针。降序插入 + 关闭时从头摘。
- **无 GC**:闭包/upvalue 进 arena,退出回收。这是有意的——M22.2 GC 紧接着把它们纳入标记(open_upvalues
  和值栈里的闭包都是 root)。
- **lambda 体是单表达式**(同 Python),不支持多语句 lambda(要多语句就用 `def`)。
- 不做 `nonlocal`/`global` 声明关键字(决策①让它们不必要)。
- 递归仍工作:`def fib` 绑成 global 闭包,fib 体里引用 fib → global(不是 upvalue),OK。

## 验证
- host `make test-aqs` 新增用例:
  - 计数器闭包 `print(f(),f(),f())` → `1 2 3`(按引用 + 跨调用保持状态)。
  - 闭包捕获参数(`def adder(n): def add(x): return x+n; return add` → `adder(3)(4)=7`)。
  - 两个闭包共享同一变量(都改/读同一 `c`)。
  - 跨两层捕获(upvalue-of-upvalue)。
  - lambda 基本:`f = lambda x: x*2` → `f(5)=10`;lambda 捕获外层;lambda 传给函数(`map` 式)。
  - 回归:现有 `fib`/`while`/`sqsum`/list/dict 等全过(函数现在都走闭包)。
- on-Aqua `make test-aqs-os`:加一个 `closure.aqs` 例子(计数器 + lambda),串口断言标记。
- 不回归:`make test`(内核启动)绿。
