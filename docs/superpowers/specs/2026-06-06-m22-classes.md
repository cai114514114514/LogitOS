# M22.3 — AquaScript 类(classes)

## 动机
AquaScript 已有闭包(M22.1)、mark-sweep GC(M22.2)、dict/list/模块。下一步是**类**——
让用户把数据和行为绑在一起,写出 `class Point:` / `class Animal(Base):` 这样的代码。
这是 M22「进阶」的第 3 阶段(闭包 ✅ → GC ✅ → **类** → 异常)。类排在 GC 之后是因为
类引入三种新堆对象(class / instance / bound method),它们都是 GC 必须正确追踪的——
有了 GC 与其 stress 验证关,这一步才能安全落地。

类也是 M21 自举(用 AquaScript 重写编译器/工具)的实用前提:编译器、AST 节点、符号表
用类建模远比裸 dict 清晰。

## 设计决策(已定,实现照此)

### 语法(Python 风格缩进,clox 血统语义)
```python
class Animal:
    def init(self, name):
        self.name = name
    def speak(self):
        return self.name + " makes a sound"

class Dog(Animal):            # 单继承
    def speak(self):
        return self.name + " barks"

d = Dog("Rex")               # 构造:分配实例,若有 init 就 init(实例, 参数...)
print(d.speak())             # Rex barks   —— 方法在子类覆盖
print(d.name)                # Rex         —— 读字段
d.legs = 4                   # 写字段
```

- `class Name:` 或 `class Name(Super):`,后跟缩进的 `def method(self, ...):` 列表。
  **只支持单继承**(无多继承)。
- 方法的第一个形参是**显式 `self`**(不是隐式 `this`)。这是关键简化:方法就是
  **普通函数**,绕开 clox 那套 "this" upvalue 机制——`self` 只是个普通局部槽。
- **构造**:`Name(args)` 分配一个新实例;若类(含继承链)有名为 `init` 的方法,就以
  `(实例, args...)` 调用它;整个构造表达式求值为**实例**(`init` 的返回值被忽略)。
- 初始化方法名为 **`init`**(clox 风格;**不用** `__init__`)。
- `inst.field`:先查实例字段,命中则返回字段值;否则在类上查方法,命中则返回一个
  **bound method**(receiver 绑定到该实例)。`inst.field = v`:设字段。
  `inst.method(args)`:把方法以 `self=inst` 绑定后再传 `args` 调用。
- `super.method(args)`:调用**父类**的 `method`(绕过子类覆盖)。显式 `self` 下,
  `super.method` 解析出父类方法(一个未绑定的 closure),调用方自己传 self,即
  `super.greet(self)`。super **最后做**(单独一个 task),万一难产,类本体仍能交付。

### 不做(YAGNI)
运算符重载、类变量/静态方法、多继承——全部不做。

## 新对象类型(`aqs.h` + `object.c`)
追加到 `ObjType` 枚举末尾(`O_UPVALUE` 之后,不重排已有项):
```c
O_CLASS, O_INSTANCE, O_BOUND_METHOD
```

```c
/* M22.3 类:方法表是一个 ObjDict(键=方法名字符串,值=ObjClosure)。复用 dict
 * 是为了 DRY —— GC 已经会追踪 dict 的键和值。`super` 仅给 super.method 用;
 * 方法查找走 copy-down(见下),所以普通查找只看本类的 methods 一张表。 */
typedef struct ObjClass {
    Obj obj;
    ObjStr *name;
    struct ObjClass *super;     /* 父类,或 NULL */
    ObjDict *methods;           /* name(str) -> ObjClosure */
} ObjClass;

typedef struct {
    Obj obj;
    ObjClass *klass;
    ObjDict *fields;            /* name(str) -> Value */
} ObjInstance;

typedef struct {
    Obj obj;
    Value receiver;             /* 绑定的 self(实例) */
    ObjClosure *method;
} ObjBoundMethod;
```
配套宏(在 `AS_CLOSURE` 之后):
```c
#define IS_CLASS(v)        (IS_OBJ(v) && AS_OBJ(v)->type == O_CLASS)
#define AS_CLASS(v)        ((ObjClass *)AS_OBJ(v))
#define IS_INSTANCE(v)     (IS_OBJ(v) && AS_OBJ(v)->type == O_INSTANCE)
#define AS_INSTANCE(v)     ((ObjInstance *)AS_OBJ(v))
#define IS_BOUND_METHOD(v) (IS_OBJ(v) && AS_OBJ(v)->type == O_BOUND_METHOD)
#define AS_BOUND_METHOD(v) ((ObjBoundMethod *)AS_OBJ(v))
```
构造函数:`aqs_class_new(ObjStr *name)`、`aqs_instance_new(ObjClass *k)`、
`aqs_bound_method_new(Value recv, ObjClosure *m)`。

**方法查找用 clox copy-down**:`class C(Base):` 时 `OP_INHERIT` 把 `Base.methods`
的所有条目拷进 `C.methods`(子类后续定义的同名方法直接覆盖)。所以运行时方法查找
**只看一张表**(本类 methods),无需走继承链。`super` 指针单独保留,只服务于
`super.method`(显式跳到父类的 methods)。

## 新操作码(追加到 `OpCode` 枚举末尾)
```c
OP_CLASS,         /* operand: 常量索引(类名 ObjStr) -> push 新建空 ObjClass */
OP_INHERIT,       /* 栈: [.. super class] -> 把 super.methods copy-down 进 class,弹掉 super,留 class */
OP_METHOD,        /* operand: 常量索引(方法名) 栈: [.. class closure] -> class.methods[name]=closure,弹 closure */
OP_GET_PROPERTY,  /* operand: 常量索引(属性名) 栈: [.. recv] -> 字段/bound method/模块属性 */
OP_SET_PROPERTY,  /* operand: 常量索引(属性名) 栈: [.. inst value] -> inst.fields[name]=value,留 value */
OP_GET_SUPER,     /* operand: 常量索引(方法名) 栈: [.. superclass] -> 父类方法(未绑定 closure) */
```
- **复用 `OP_INVOKE`**(不新增 `OP_SUPER_INVOKE`):`OP_INVOKE name argc` 已处理
  module/list/dict;新增 instance 分支——若字段里有同名可调用值就调它,否则查类方法、
  以 self=recv 绑定调用(快路径,不实际造 bound method)。
- **`OP_GET_ATTR` 退役并入 `OP_GET_PROPERTY`**:旧的 `.name` 读取(只处理 module)
  改由 `OP_GET_PROPERTY` 处理(module + instance 都管),编译器 `dot()` 与
  `from-import` 改发 `OP_GET_PROPERTY`。`OP_GET_ATTR` 枚举值不删(不重排),仅不再发射。
- `OP_CALL` 已能把 class 当 callee:`call_value` 新增 `O_CLASS` 分支做构造;`O_BOUND_METHOD`
  分支把 receiver 塞进 slot0 再调底层 closure。

## 编译器改动(`compiler.c` + `lexer.c/h`)
- lexer:`class` 关键字(`case 5` 加 `T_CLASS`)。
- `class_declaration()`:`class` NAME [ `(` SUPER `)` ] `:` NEWLINE INDENT (def_method)+ DEDENT。
  发 `OP_CLASS namek`;顶层用 `OP_DEF_GLOBAL` 绑名(嵌套则 `store_name`);若有父类,
  push 父类(变量读)+ push class + `OP_INHERIT`;然后逐个方法:push class,
  `compile_function`(复用现有,留 closure 在栈),`OP_METHOD namek`。
- `dot()`:`.name` 读发 `OP_GET_PROPERTY`(替原 `OP_GET_ATTR`);`.name(args)` 仍发
  `OP_INVOKE`(VM 端扩 instance)。
- 赋值目标新增 `name.field = v` 形式:`assignment()` 在 NAME 后遇 `.` 时,push 接收者、
  consume 属性名、consume `=`、求值 RHS、发 `OP_SET_PROPERTY` 再 `OP_POP`(SET_PROPERTY 留值,
  当语句时弹掉)。`assign_ahead()` 要放行 `.` 不破坏判定(深度 0 的 `=` 仍是赋值)。
- `super`:`super` 作为 prefix —— 解析 `super` `.` NAME,发父类查找。显式 self 模型下,
  `super.method` 求值为父类那个**未绑定 closure**,由调用方传 self。实现:编译期把当前
  方法所在类的 super 作为隐藏 upvalue/局部不可行(无 this 机制),改为**运行时**:
  实例方法里 `self` 是普通局部,`super` 需要拿到"定义此方法的类的父类"。为保持
  "方法即普通函数"的简化,super 用如下编译策略——见下。

### super 的具体机制(task T5,显式 self 版)
clox 用 "this" + 一个隐藏 "superclass" upvalue。我们没有 this,但有显式 `self`。
为了不引入隐藏机制,采用**词法上界**做法:`class_declaration` 编译方法体时,把"当前类名"
记到 compiler 状态(`current_class`,带 `has_super`)。`super` 前缀解析为:发
`OP_GET_GLOBAL <当前类名>` 读到类对象,再发 `OP_GET_SUPER <方法名>`(VM:取该类的
`super`,在父类 methods 里查方法,push 未绑定 closure)。于是 `super.greet(self)`
编译为:GET_GLOBAL CurClass → GET_SUPER "greet" → 求值 self 实参 → OP_CALL 1。
- 仅在 `class ...(Super):` 的方法体内允许 `super`;否则编译错误。
- 顶层类名是全局,`OP_GET_GLOBAL <类名>` 在方法运行时一定已定义(类先于实例存在)。
- 这条路 100% 复用现有 GET_GLOBAL + 一个新 GET_SUPER,无隐藏 upvalue。

## GC 影响(房规:三件套,且追踪上手就做)
**T1 就把三种新对象的 GC 全部接上**(blacken + free_object),后续 task 自然 stress-safe。
- `blacken`:
  - `O_CLASS`:mark `name`、`super`、`methods`(dict 本身已被 GC 追踪其内容)。
  - `O_INSTANCE`:mark `klass`、`fields`。
  - `O_BOUND_METHOD`:`gc_mark_value(receiver)` + mark `method`。
- `free_object`:三者都**只 free 自己的对象**(`free(o)`),不 free 引用到的 dict/closure
  ——methods/fields 这两个 ObjDict 是独立挂在 `g_objs` 上的对象,由 sweep 各自回收。
  (即三者在 `free_object` 落入 `default: break;`,只走末尾 `free(o)`。)
- **roots**:类不引入新的 VM 全局对象容器(类绑在模块全局/局部里,已被现有 root 覆盖),
  所以 `aqs_vm_mark_roots` **无需新增**。

### 构造期的两条 rooting 规则(stress 关会抓漏)
1. **构造函数 ≥2 次 alloc_obj**:`aqs_instance_new` 先 `alloc_obj(instance)` 再
   `aqs_dict_new()`(fields)——两次分配。用
   `aqs_gc_push_disable()/aqs_gc_pop_disable()` 包住,或先把半成品 push 到值栈。
   采用 **push-disable** 包裹(与 `aqs_module_new` 同款,见 object.c 现状)。
   同理 `aqs_class_new`(class + methods dict 两次分配)也包 push-disable。
2. **VM 操作码持有新对象跨后续 alloc**:
   - `OP_CLASS`:`aqs_class_new` 内部已自包 push-disable;新对象建好后**立刻 push** 到栈
     (= 该指令的结果),后续 OP_INHERIT/OP_METHOD 都拿栈顶,天然 rooted。
   - `call_value` 的 `O_CLASS` 构造分支:`aqs_instance_new` 建实例后,**先把实例写回
     callee 槽(slot0)**(替换掉栈上的 class),这样实例立刻 rooted;再决定调不调 init。
     若有 init:把实例作为 self 放到调用窗口、跑 init(普通 call,实例已在栈上 rooted);
     init 返回后实例仍在 slot0 → push 为结果。整个过程实例始终在值栈上。
   - `OP_GET_PROPERTY` 返回 bound method 时:`aqs_bound_method_new` 是单次 alloc,且其
     输入(receiver、method)在 alloc 前都在栈/已 rooted——建好即 push,无跨 alloc 洞。
   - `OP_INVOKE` instance 快路径不造 bound method(直接绑 self 调用),无新分配洞。

GC-stress 关(`make test-aqs-gcstress`,每次分配前都 collect)是这些 rooting 的验收闸,
任何漏 root 都会在那里崩或输出错。

## 风险 / 注意
- **`OP_GET_ATTR` 退役**:必须把 `dot()` 与 `from_statement` 里的 `OP_GET_ATTR` 全部换成
  `OP_GET_PROPERTY`,并让 `OP_GET_PROPERTY` 的 VM 实现覆盖原 module 语义(否则 import 回归)。
  保留枚举项不删,避免重排。已有 import 测试是回归网。
- **构造 init 返回值**:init 的返回值丢弃,构造表达式恒为实例(clox 行为;init 显式
  `return <非nil>` 在我们这里也忽略,文档说明)。
- **字段遮蔽方法**:`inst.x` 先查字段后查方法;若字段名与方法重名,字段赢(可调用字段
  即"方法被字段覆盖")。`OP_INVOKE` instance 分支同序:先看字段里是否有可调用值。
- **super 仅限有父类的方法体**:`current_class.has_super==0` 时用 `super` 编译报错。
- **方法 arity 含 self**:`def init(self, name)` arity=2;`Name("x")` 传 1 个实参,VM 把
  实例补成 self 后凑足 2。bound method 同理:调用 `bm(args)` 时把 receiver 当 self 补进去。
- **递归 dict 复用**:methods/fields 都是 ObjDict,`aqs_dict_set/get` 已就绪;键是
  方法名/字段名(ObjStr,编译期常量池里 dedup 过)。
