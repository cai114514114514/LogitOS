# 两个 CSS 辅助库的独立替换设计

用户要求保留 libwapcaplet、libparserutils 的作用，用独立实现替换；不得照抄、
翻译或改名冒充。LibCSS 引擎继续保留。

**范围更正：** 初版把范围缩成“现有浏览器调用”，省略了独立编解码和 UTF-16
工具。用户质疑后，范围改为核对原公开操作并补齐。旧私有布局和内部缓存机制不继承，
安全性错误不照搬；这些差异必须明说。

## 约束

- 在当前主树修改，不改变其他工作树。
- 不开发或提交新测试，运行已有检查；GenFS 的删除是用户单独授权的例外。
- 初次交付不提交或推送；后续用户已授权分开提交，按独立功能拆分，每笔都能审查和构建。
- 代码按职责分文件，说明“为什么”，公开接口参数具有可读名称。
- 不增加第三方代码库，不保留旧库回退；标准数据单独记录来源与许可。
- 新库位于 c/lib，但只进入 ring-3 CSS/浏览器构建，排除内核自动扫描。

## 结构

字符串库把稳定对象与可扩容索引分开，用开放寻址与回移删除；大小写无关比较
直接处理字节和预先计算的哈希，不创建第二个缓存字符串。公开对象不透明，
调用方不再访问旧字段。

解析库把连续字节、分页容器、Unicode、编码名称、单码点转换、有状态 codec、
输入流分别实现。分页增长不搬动元素。codec 的输入暂存与输出暂存分开；
输入流的原始字节与 UTF-8 消费窗口分开，分块不足与 EOF 分开处理。

编码注册表只回答名称和编号；可用 codec 单独判定。字符映射复用项目已有
WHATWG 数据，名称数据来自 IANA CC0 注册表，没有导入旧库私有表。

## 验收与证明边界

核对 55 个 parserutils 函数入口和 12 个字符串操作，构建实际链接的新库。
保留基线对象用于行为核对，但不读取旧 .c 作为实现模板。运行现有 host 检查、
ASan/UBSan、完整 ISO/disk 构建和 guest 页面，并查看 guest 截图。

临时诊断补查单字节映射、Unicode 往返、分块与容量不足、严格模式、状态重置、
公开类型和 C/C++ 头文件。它们不增加仓库测试文件，也不是长期回归套件。
没做分配失败注入或长时间并发压力，就不能声称这些边界已全面证明。

说明接口覆盖、已观察行为、刻意变化、未验证边界各自是什么。修正旧结论时保留
旧说法及更正，避免下一位读者拿到相互冲突的“完成”声明。
