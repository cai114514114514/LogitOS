# M22.2 — AquaScript 垃圾回收(mark-sweep GC)

## 动机
AquaScript 至今**没有 GC**:所有堆对象串在 `g_objs` 链上,直到程序退出才由 `aqs_free_objects`
一次性释放(arena 模型)。短脚本无所谓,但长跑程序会泄漏:REPL、GUI 程序,尤其是 **M21 自举
编译器**(用 AquaScript 写、跑起来会疯狂分配 ObjStr/ObjFn/dict)。本里程碑加一个 **mark-sweep
GC**,让对象在不可达时被回收。

这是 M22「进阶」的第 2 阶段(闭包 ✅ → **GC** → 类 → 异常)。GC 紧跟闭包,因为闭包是第一种
"逃出栈"的对象(open upvalue 指向栈槽、closed upvalue 自存值),正好是 GC 必须正确处理的难点;
而且越往后做,要纳入标记的对象类型越多。

## 算法决策(已定):mark-sweep,不移动对象
- **不用引用计数**(处理环麻烦、每次赋值都有开销)。
- **不用复制/压缩式**:它会**移动对象**,而 open upvalue 的 `location` 指向**值栈里的活槽**,
  移动堆对象会让这些指针失效——mark-sweep 不移动对象,最契合现有结构。
- 对象已经串在 `g_objs` 单链表上(`object.c`),天然就是 sweep 的遍历列表。

## 架构

### 对象头 + 分配钩子(`aqs.h` + `object.c`)
- `struct Obj` 增 `uint8_t marked;`(`alloc_obj` 里初始化为 0)。
- `object.c` 维护:`size_t bytes_allocated`(粗略计:每次 `alloc_obj` 加 size)、`size_t next_gc`
  (初始 `1<<20` = 1 MiB)、`int gc_disabled`(计数器)。
- **`alloc_obj` 在创建新对象之前**:`if (!gc_disabled && (AQS_GC_STRESS || bytes_allocated > next_gc)) gc_collect();`
  —— 在新对象诞生前触发,所以新对象天然不会被这一轮误回收;输入对象都还在 root 上。
- `gc_collect()` 末尾:`next_gc = bytes_allocated * 2`(至少保留一个下限,如 1 MiB)。

### 标记:gray-stack 工作表(非递归)
- `gc_mark(Value v)` / `gc_mark_obj(Obj *o)`:`o->marked` 已置则返回;否则置位 + 推入 **gray 栈**
  (一个 growable `Obj **gray` + `gray_count/gray_cap`,用 realloc,**不是** GC 对象)。
- `blacken(Obj *o)`:按类型标记其引用——
  - `O_FN`:`name`(ObjStr)+ `consts[0..kcount)` 里的每个 Value。
  - `O_CLOSURE`:`fn` + `upvalues[0..upvalue_count)` 的每个 ObjUpvalue。
  - `O_UPVALUE`:`closed`(关闭时是值;开放时是 NIL,标记无害)。
  - `O_LIST`:`items[0..count)`。
  - `O_DICT`:每个活 entry 的 `kstr`(若 AQS_DK_STR)+ `val`。
  - `O_MODULE`:`name` + `vars[0..count)` 的 `name` + `val`。
  - `O_STR` / `O_NATIVE` / `O_PTR`:无子对象(O_NATIVE 的 `name` 是 C 字符串,非 GC 对象)。
- **用工作表而非递归**:避免深对象图(长 list、深 dict、链式闭包)把 C 栈压爆。

### 根(roots)—— 来自闭包终审清单
`gc_mark_roots()` 标记:
1. 值栈 `[stack, sp)` 每个 Value;
2. 每个 `frames[i].fn` 和 `frames[i].closure`(i ∈ [0, frame_count));
3. `open_upvalues` 链上每个 ObjUpvalue;
4. `builtins[0..nbuiltins)` 的 `name` + `val`;
5. `modules[0..nmodules)`(含正在运行的脚本所在模块)。
- 这些 root 是 vm.c 的 static。**设计:object.c 提供 `gc_collect` + `gc_mark_obj(Obj*)` +
  `gc_mark_value(Value)`(+ gray 栈 + sweep);vm.c 实现 `void aqs_vm_mark_roots(void)`(标记上面 5 类
  root,调 `gc_mark_*`),在 `aqs.h` 声明;`gc_collect` 直接调它**。不用 weak —— vm.c 在 host 单测和
  Aqua 构建里都恒被链接(`AQS_CORE` 含 vm.c),普通 extern 即可。

### 清扫(sweep)
- 把现有 `aqs_free_objects` 的 per-object 释放抽成 **`free_object(Obj *o)`**(free 子分配 + free 对象,
  扣 `bytes_allocated`)。
- `gc_collect` 的 sweep:遍历 `g_objs`,`marked` 的清零(留到下轮);未标记的从链上摘除并 `free_object`。
- `aqs_free_objects`(退出清理)改为对每个对象调 `free_object`(行为不变,仍全清)。

### 两个安全点
1. **编译期关 GC**:`aqs_compile` 和(VM 运行中 `import` 触发的)`aqs_compile_module` 全程
   `gc_disabled++ … gc_disabled--`。编译会 new ObjStr/ObjFn,但此刻它们还没挂上任何 root;
   编译完成后产物立即被 push/run/存入模块(在下一次 GC 前已可达),所以这个窗口安全。
2. **VM 操作中途**:GC 只在 `alloc_obj` **建新对象前**触发;每个分配操作的输入都在栈上(rooted),
   list/dict 的内部填充走 realloc(不经 alloc_obj、不触发 GC)。已审分配点:`str_concat`(OP_ADD)、
   `OP_MAKE_LIST`、`OP_MAKE_DICT`、`aqs_dict_keys/values`、字符串索引的 `aqs_str_copy`、`OP_CLOSURE`
   —— 无"未 root 的 C 局部跨 GC"的洞(字符串索引在 alloc 前已 memcpy 出源数据)。

### 内建:`gc()`(+ `gc_stats()`)
- object.c 维护 `int live_objects`(`alloc_obj` 里 ++,`free_object` 里 --)。
- `gc()`:强制一次 `gc_collect()`,**返回本次回收掉的对象数(int)** = 回收前 live − 回收后 live。
- `gc_stats()`:**返回当前存活对象数 live_objects(int)**。测试用它断言"造一堆垃圾→gc()→存活集回落"。
- 两者在 vm.c 注册为 builtin native(像 print/len/range);takes 0 args。

## 正确性手段:GC-stress 模式(关键)
- 编译期开关 `AQS_GC_STRESS`(宏):置位时 `alloc_obj` **每次分配前都 gc_collect()**。
- 任何**漏标的 root** 在 stress 下会立刻表现为崩溃 / 错误输出 —— 这是验证 GC 无 use-after-free
  的标准做法(clox DEBUG_STRESS_GC)。
- Makefile 加 `test-aqs-gcstress` 目标:用 `-DAQS_GC_STRESS` 重新编译 aqs 核心 + 跑同一套
  `tools/t/aqs_test.c`。**全部 95+ 用例在 stress 下也必须全过。**

## 风险 / 注意
- **漏 root = use-after-free**:靠 stress 模式 + 全套用例兜底。最易漏的是 builtins(print 等 native)
  和 open_upvalues —— 清单已列全。
- **gray 栈本身不是 GC 对象**(realloc 管理),GC 结束清空;它在 GC 期间是临时工作区。
- **共享 upvalue**:一个 ObjUpvalue 可能在多个闭包的 upvalues[] 里(去重),mark-sweep 天然处理
  (标记幂等);sweep 不经数组释放共享 upvalue(它在 g_objs 链上单独 free)。
- **bytes_allocated 是粗略值**(只算 alloc_obj 的对象大小,不含 items/entries 的 realloc)——足够驱动
  阈值,不求精确。
- **`gc_disabled` 必须是计数器**(可重入:import 里再 import → 嵌套编译)。

## 验证
- host `make test-aqs`:现有 95 + 新增 GC 用例(`gc()` 后 `gc_stats()` 下降;大量临时对象不增长存活集;
  闭包/upvalue 在 GC 后仍可用;dict/list 元素 GC 后仍在)。
- **host `make test-aqs-gcstress`:同一套用例在"每次分配前 GC"下全过**(揪 root 漏标)。
- on-Aqua `make test-aqs-os`:`gc.aqs`(循环造大量垃圾 + gc_stats 验证存活集稳定)串口断言。
- 不回归:`make test`(内核启动)绿。
