## M23 — Modern string tooling + expression sugar for AquaScript

### Motivation (the locked perf problem)
`s = s + x` in a loop is O(n^2): each `OP_ADD` calls `str_concat` (vm.c:103-109) which mallocs `a->len+b->len` and copies the whole accumulator, and `aqs_str_take` (object.c:39-44) then **eagerly re-hashes** the entire result. Measured 20k/40k/80k concats = 0.19/0.73/2.91s (quadratic). M23 does NOT make `+` faster (no ropes). It adds the modern tooling to build strings in O(total) (`sep.join(list)`) plus the rest of a modern string/expression surface, and removes the redundant per-concat hash (lazy hash).

The feature set is LOCKED to the six items below. No additions.

---

### Feature 1 — String methods (via OP_INVOKE)
String method calls compile with zero compiler changes: `dot()` (compiler.c:248-255) already emits `OP_INVOKE name argc` for any receiver. A new `else if (IS_STR(recv))` branch is added to `op_INVOKE` (vm.c, after the `IS_DICT` block ending vm.c:636, before the `IS_INSTANCE` branch at vm.c:637), mirroring the list `.append` pattern (vm.c:601-606). Method dispatch uses `name_eq` (vm.c:100-101). Stack protocol for every method: `recv = peek(argc)` is the string; compute the result first, then `sp -= argc + 1; push(result)`.

Methods (all build the result with a single malloc + memcpy, then `aqs_str_take`; lists via `aqs_list_new`+`aqs_list_push`):
- `sep.join(list)` — **the perf fix.** `sep` is the receiver string. Arg is a list of strings. One pass: sum each item length + `sep->len*(count-1)`, single malloc, memcpy each item with `sep` interleaved. Error if argc!=1, arg not a list, or any item not a string.
- `s.split(sep)` — `sep` a non-empty string: return a list of the substrings between non-overlapping occurrences of `sep` (Python semantics: "a,,b".split(",") -> ["a","","b"]; trailing sep yields a trailing ""). `s.split()` (argc 0): split on runs of ASCII whitespace (space/\t/\n/\r/\f/\v), skipping leading/trailing whitespace and collapsing runs (Python str.split() with no arg). Returns a fresh ObjList of fresh ObjStr slices via `aqs_str_copy`. Error if argc>1, sep given but empty, or sep not a string.
- `s.strip()` — argc 0; trim leading+trailing ASCII whitespace; fresh ObjStr (may be empty). 
- `s.upper()` / `s.lower()` — argc 0; ASCII-only case fold ('A'-'Z' <-> 'a'-'z'); fresh ObjStr same length.
- `s.replace(old, new)` — argc 2; `old` non-empty string, `new` any string. Replace all non-overlapping occurrences left to right. First pass counts occurrences to size the buffer exactly, second pass writes. Error if argc!=2, args not strings, or old empty.
- `s.find(sub)` — argc 1; `sub` a string. Return INT first start index of `sub` in `s`, or -1. Empty `sub` returns 0 (Python). Error if argc!=1 or arg not a string.
Unknown method name -> `runtime_error("string has no method '%.*s'", name->len, name->chars)`.

ASCII-only is intentional and consistent with the existing byte-oriented string model (indexing in vm.c:550-554 is byte-based; CJK web text lives in the kernel, not aqs).

### Feature 1b — `str(x)` builtin
A global native converting any Value to its `print` representation (no quotes around strings). Implemented as `native_str` in vm.c, registered via `aqs_define_native("str", native_str)` in `aqs_run` (vm.c:829-834, before `aqs_gc_pop_disable`). It calls the new `value_to_cstr(Value, char*, int)` (value.c) into a stack buffer then returns `OBJ_VAL(aqs_str_copy(buf, len))`. `str("hi")` -> "hi" (identity-ish; returns a copy), `str(42)` -> "42", `str(3.5)` -> "3.5", `str(true)` -> "true", `str(nil)` -> "nil", `str([1,2])` -> "[1, 2]" (matches list print).

### Feature 2 — f-strings
Syntax: `f"text {expr} more {a+b}"` (also `f'...'`). `{{` -> literal `{`, `}}` -> literal `}`. A hole `{expr}` holds ANY expression. **No format spec**: a `:` at hole top level (not inside nested brackets/parens) is a compile error "format spec not supported in f-string".

Tokenization (lexer): add `T_FSTR` to `TokType` (lexer.h, before `T_EOF`). In the identifier branch (lexer.c:99-102): after scanning an identifier, if it is exactly 1 char `f`/`F` and the next char is `"`/`'`, scan the quoted body like a normal string but emit `T_FSTR` with `start/len` = raw interior (between quotes, holes intact). The scan must (a) treat `{{`/`}}` as two literal chars, (b) on a single `{`, descend into the hole tracking `{}`/`()`/`[]` depth AND skip over `'...'`/`"..."` string literals inside the hole (so `f"{ ',' }"` and `f"{ {1:2} }"` work) until the matching depth-0 `}`, (c) keep honoring backslash escapes for the outer string. Unterminated -> existing "unterminated string" error.

Compilation (compiler.c): `rules[T_FSTR] = (ParseRule){ fstring, 0, PREC_NONE }` in `init_rules`. `fstring()` walks the raw token text producing an alternating chain of text-constant pieces and hole values:
- A text run (with `{{`/`}}` reduced) -> `emitConst(OBJ_VAL(aqs_str_copy(seg,n)))`.
- A hole -> copy the hole substring to a malloc'd NUL-terminated buffer, `aqs_lex` it, save `T`/`P`, set `T`=hole tokens / `P`=0, `expression()`, restore `T`/`P`, free; then wrap the value in a `str()` call so the result is always a string. (Reject a top-level `:` in the hole as the no-format-spec error.)
- Chain pieces with `OP_ADD` (string concat). For an f-string with no holes, emit a single text constant. For an empty f-string `f""`, emit `emitConst("")`.
The `str()` wrap is emitted as a normal global call to the `str` builtin: emit `OP_GET_GLOBAL str`, then the hole value, then `OP_CALL 1` — but to keep the operand order correct with `OP_ADD` chaining, build the result left-to-right: push piece0, then for each subsequent piece push it and `OP_ADD`. (Concretely: emit first piece; for each following piece emit it then `OP_ADD`.) `str()` of a hole = `GET_GLOBAL str` BEFORE the hole expr, hole expr, `CALL 1`.

### Feature 3 — Ternary `a if c else b`
A postfix conditional expression. New precedence level `PREC_TERNARY` inserted between `PREC_NONE` and `PREC_OR` (compiler.c:135-138). `expression()` base precedence (compiler.c:366) changes `PREC_OR` -> `PREC_TERNARY`. `rules[T_IF] = (ParseRule){ 0, ternary_, PREC_TERNARY }` in `init_rules` (T_IF currently has no rule; `if_statement` is reached only via statement dispatch, so no conflict). `ternary_()` (consequent `a` already on stack):
```
parse_precedence(PREC_OR)        ; eval c -> [a, c]
else_j = emitJump(OP_JUMP_IF_FALSE)   ; peeks c, no pop (vm.c:465)
emit(OP_POP)                     ; true: drop c, keep a
end_j  = emitJump(OP_JUMP)
patchJump(else_j)
emit(OP_POP)                     ; false: drop c
emit(OP_POP)                     ; false: drop a
consume(T_ELSE, "expected 'else' in conditional expression")
parse_precedence(PREC_TERNARY)   ; eval b (right-assoc nesting) -> [b]
patchJump(end_j)
```
No new opcodes. Reuses emitJump/patchJump.

### Feature 4 — List comprehension `[expr for var in iter]` with optional trailing `if cond`
Single for-clause only (nested fors deferred). Detected inside `list_literal()` (compiler.c:200-209): scan ahead from the current cursor at bracket depth 0 (track `[]`,`()`,`{}`) for a `T_FOR` before the matching `T_RBRACKET`; if present, take the comprehension path instead of the comma-list. Lowering (always uses locals, regardless of top-level/function — see feasibility note 2):
```
begin_scope()
emit2(OP_MAKE_LIST, 0)                 ; empty accumulator
acc = add_local("", 0)
expression()  is NOT pre-parsed; instead:
consume after detection: the element expr is parsed INSIDE the body (see below)
; parse: <elemexpr>  is the text before 'for' -> but it must run per-iteration,
; so structure as: skip elem text position, parse `for var in iter`, then in the
; loop body re-parse the elem expr.
```
Because the element expression precedes `for` in source but must execute in the loop body, the implementation parses in source order using a saved cursor: record `elem_P = P` (cursor at the element expr), scan forward to the `T_FOR`, then parse `for var in iter` setting up the iteration (mirroring for_statement: `OP_ITER`, hidden seq + idx locals, `var` local), then at the loop body set `P = elem_P`, `expression()` (the element), optionally `if cond` -> `JUMP_IF_FALSE` to skip the append, then append to `acc` (GET_LOCAL acc; the elem value; OP_INVOKE append/1 — or GET_LOCAL acc then a direct list push sequence; use OP_INVOKE "append" to reuse vm.c:602), advance idx, loop. After the loop, `P` is left just past the element expr; consume the `for ... [if ...]` tail tokens (they were already parsed for setup) — to avoid double-consume, the cleanest order is: parse the `for`/`in`/`iter`/optional `if cond` FIRST (advancing P past them), THEN jump P back to elem_P for the body parse, and after the body restore P to the post-tail position. Concretely the function records both `elem_P` (start of element) and, after parsing the clause header + optional guard expression into a TEMP (compiled into the body), the `tail_P` to resume at `]`.

Simpler equivalent actually emitted (the recommended shape):
1. `elem_P = P` (cursor at element expr start).
2. Advance P past the element expr WITHOUT compiling: do a depth-0 scan to the `T_FOR` (the same lookahead already used to detect the comprehension can return this index) and set P there.
3. `consume(T_FOR)`, `consume(T_IDENT)` (var), `consume(T_IN)`, `expression()` (iter) -> stack; `emit(OP_ITER)`; reserve hidden `seq`+`idx` locals + `var` local; record optional guard: if `match(T_IF)` set `guard_P = P` and skip its expression to the `]` via depth-0 scan, set `tail_after = P`; else `tail_after = P`.
4. Emit loop header (idx<len test, JUMP_IF_FALSE exit), body: SET var = seq[idx]; if guard present `{ saved=P; P=guard_P; expression(); JUMP_IF_FALSE skip; P=saved }`; element `{ saved=P; P=elem_P; expression(); P=saved }`; `emit OP_INVOKE append 1` onto acc (after GET_LOCAL acc swap — see plan for exact op order); idx++ ; loop; exit.
5. `consume(T_RBRACKET)`; leave acc on stack (GET_LOCAL acc) as the expression result; `end_scope()`.

Optional `if cond` guards the append only. `var` is block-scoped (does not leak). No new opcodes.

### Feature 5 — Multiple assignment / unpack
`a, b, ... = e1, e2, ...` (N targets = N RHS values) and `a, b, ... = <list>` (unpack a list). NO tuple type added. for-loop unpacking (`for k,v in`) is DEFERRED.

Detection: `assign_ahead()` (compiler.c:382-393) ALREADY returns 1 for `a, b = ...` (first token is T_IDENT; a depth-0 `=` exists; commas don't change depth). So `statement()` already routes to `assignment()`. The change is inside `assignment()` (compiler.c:395): after consuming the first `T_IDENT` name, if `check(T_COMMA)`, switch to multi-target mode (only bare-identifier targets; no `.field`/`[i]` targets in a multi-assign — error if a non-identifier target appears).

Multi-target lowering:
1. Collect target name tokens: first name, then while `match(T_COMMA)` `consume(T_IDENT)` -> array of N tokens.
2. `consume(T_ASSIGN)`.
3. RHS: parse first `expression()`. If `match(T_COMMA)` follows -> **tuple form**: parse remaining expressions (total M). If M != N -> compile error "assignment count mismatch". All M values are now on the stack (evaluated before any store -> `a,b=b,a` swaps). Store top-down: for i from N-1 downto 0, `store_name(targets[i])` (store_name consumes the top of stack via SET_*/POP or DEF_GLOBAL). Because store_name pops, storing in reverse index order with the last value on top assigns correctly.
4. Else **list form** (single RHS): the RHS list value is on the stack. Store it into a hidden local `tmp` (add_local; the value becomes its slot — note: at top level there is no enclosing fn, but a hidden local still lives on the value stack as a script-frame slot, so this works; to be safe and uniform the list form always wraps in begin_scope/end_scope so tmp is reclaimed). For i in 0..N-1: `emit2(OP_GET_LOCAL tmp); emitConst(INT_VAL(i)); emit(OP_INDEX_GET); store_name(targets[i])`. `OP_INDEX_GET` bounds-checks (vm.c:547-548) -> "list index out of range" if the list is shorter than N. (Over-long lists are not rejected — documented limitation, see feasibility note 4.) After storing, `end_scope()` pops `tmp`.

The tuple form's "store top-down" must be exact: with values v0..v_{N-1} on the stack (v_{N-1} on top), `store_name(targets[N-1])` consumes v_{N-1}, then `store_name(targets[N-2])` consumes v_{N-2}, etc. — so store targets from last to first. store_name for a NEW top-level name emits OP_DEF_GLOBAL (consumes top); for an existing local emits SET_LOCAL+POP; matches.

### Feature 6 — Lazy ObjStr hash (perf)
Add `uint8_t hashed;` to `ObjStr` (aqs.h:48): `typedef struct { Obj obj; int len; uint8_t hashed; uint32_t hash; char *chars; } ObjStr;`. `aqs_str_take` (object.c:42) stops calling `hash_str`; sets `s->hashed = 0; s->hash = 0`. New non-static accessor (declared in aqs.h, defined in object.c):
```
uint32_t aqs_str_hash(ObjStr *s){ if(!s->hashed){ s->hash = hash_str(s->chars,s->len); s->hashed = 1; } return s->hash; }
```
Route every `->hash` READER through it:
- object.c:118 (aqs_module_slot): both `m->vars[i].name` and `name`.
- object.c:162 (key_hash): `AS_STR(k)`.
- object.c:165 (key_match): both `e->kstr` and `AS_STR(k)`.
- vm.c:50 (builtin_slot): both `builtins[i].name` and `name`.
`aqs_value_eq` (value.c:29-31) uses memcmp, not hash — unchanged. dict/module/builtin behavior stays identical (same hash values, just computed lazily). This removes one full string hash per `str_concat`/`aqs_str_copy`, halving the per-concat constant.

### Scope & deferrals (explicit)
- No ropes / no faster `+` (perf comes from `join` + lazy hash).
- f-strings: no format spec (`{x:.2f}`); `{{`/`}}` literals only.
- List comprehension: single for-clause, optional single `if`; no nested fors, no multiple ifs.
- Multiple assignment: bare-identifier targets only; tuple form is strict N=N; list form errors only on too-few (too-many silently ignored); no for-loop unpacking; no tuple type.
- String methods: ASCII-only case/whitespace; byte-oriented (consistent with existing string indexing).
