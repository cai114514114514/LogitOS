# M27 — Ports

Executes §P1 of `2026-08-05-aetherscript-2-language-design.md`. Its gate, stated
there: *"the `.as` shell runs the `test-shell` suite that `/bin/sh` passes today"*.
It does — `make test-shell-as`, on the same ISO and disk as `make test-shell`.

## What was built

| §P1 asks for | Built as |
|---|---|
| `O_PORT` (kernel handle + kind) | `ObjPort` — fd, kind, **ownership**, its own read cursor |
| `O_PROC` | `ObjProc` — an argv and a `->next`; a pipeline IS its head stage |
| `O_REGION` | **not** M27. §5's table puts regions and their bounds-checked slices in M28 with capabilities, and `O_PORT`'s `cap` field waits for the same milestone. |
| `\|>` | `OP_PIPE` |
| `->` / `<-` | `OP_REDIR_OUT` / `OP_REDIR_IN`, on new `T_ARROW` / `T_LARROW` |
| `with` scopes | `OP_WITH_BEGIN` / `OP_WITH_END` + a VM with-stack |
| iterable ports | `OP_ITER` rebases the port's cursor; `OP_LEN`/`OP_INDEX_GET` answer from it |

Five opcodes, appended (never inserted — the enum order is the `.la` ABI);
`AS_BC_VERSION` 3 → 4. Four tokens. One new file, `c/apps/as/as_port.c`.

### The three things that could not have been a library

1. **`run()` does not start anything.** A pipeline's fds are wired between stages
   that must both already exist; an eager `run()` has thrown that moment away. So
   `|>` is an operator over unstarted stages and `as_proc_start` does the whole
   chain in one fork/dup2/exec pass.
2. **Release is deterministic.** `with` is a compiler-emitted scope, released on
   the bottom of the block, on `break`, on `continue`, on `return`, and on a
   raised exception — the last two by unwinding the VM's with-stack, which a
   library cannot reach. `with` on a command means *start at entry, wait at exit*,
   so both resource kinds obey one rule.
3. **A port is its own iterator.** `for x in seq` compiles to `OP_LEN` +
   `OP_INDEX_GET`, so the VM itself had to learn that a stream answers "how many
   items are known to exist" (pull at most one more line) rather than a length.
   The `len()` *builtin* still refuses a port: the loop asks a question a stream
   can answer, `len(p)` asks one it cannot.

### Ownership, and the fd table

`ObjPort.owns` is the field that matters. fd 0/1/2 arrive already open from
whoever spawned the process; a port over one of them detaches on `close()` and is
never `close(2)`d, never counted, never finalized. CLAUDE.md records the
`wm_launch` fd 0/1/2 collision as a live hazard of this system; this is where the
language declines to repeat it.

**A dropped port does something defined:** the collector's finalizer closes an
owned handle and increments a counter readable from script as
`port_stats()["finalized"]`. Because a LogitOS process gets **16** descriptors
(`proc.h NFD`) while the collector's own threshold is 1024 objects, "eventually"
was not good enough — so `acquire_fd()` treats a failed `open`/`pipe` as a reason
to collect and retry exactly once. `fsroot/as/examples/ports.as` opens 64 ports
and closes none *on the machine*; all 64 succeed, which is only possible if the
backstop works. A dropped **process** is reaped with `WNOHANG` and counted as an
orphan if still running — a finalizer that blocked could hang the collector on a
child that never exits, which is worse than a zombie.

## The shell

`fsroot/as/examples/ash.as`, ~190 lines against `c/apps/coreutils/sh.c`'s 971.
No `fork`, no `dup2`, no `waitpid`, no fd arithmetic anywhere in it. The
execution core is a fold:

```
cmd = run(stages[0])
for i in range(1, len(stages)):
    cmd = cmd |> run(stages[i])
if infile != nil:   cmd = cmd <- infile
if outfile != nil:  cmd = cmd -> outfile
return cmd.wait()
```

`cd`/`pwd` are the one place still going through the old `syscall()` keyhole: a
working directory is not a port. That belongs to M28, and is left visible rather
than hidden.

**Statement rule worth knowing:** an expression statement whose *outermost*
operation is `|>`, `->` or `<-` is a **command statement** — the compiler gives it
the scope `with` would have given it, so it starts and is waited for. Without
that, the spec's own `run(..) |> run(..) -> "out.txt"` line would build a pipeline
and silently drop it. `run(x)` on its own stays a value.

## For the executable-format line: what M30 will need from `.aex`

M30 wants `as -c --native` to emit a real `.aex`, *"legitimate precisely because
we own the ABI, the ELF/aex loader, and the page tables."* That is not this
milestone, but the format is being decided now, so here is what a **compiler**
needs that a **linker** does not. None of it is a request for a feature; it is a
request that these stay possible.

1. **Emittable in one pass, with no back-patching of a fixed-size header.**
   A code generator streams. If the header carries totals (segment count, sizes,
   a checksum over the image), either allow them to be written last into a
   reserved prefix, or put them in a trailer. A format that requires knowing the
   image size before the first byte forces the compiler to buffer the whole
   program.
2. **No external linker in the loop.** The prize is `as -c --native` producing a
   runnable file directly. If `.aex` requires relocation processing that only
   `ld.lld` performs, the milestone becomes "emit ELF, then shell out", which is
   a different and much weaker claim on a machine whose point is that we own both
   sides.
3. **A load address the producer chooses, or position independence.** Today each
   app links at a distinct base and CLI programs share `0x50000000`. A compiler
   emitting `.aex` per program cannot hand-assign bases the way the Makefile
   does. Either the header declares the base and the loader honours it, or the
   image is position-independent and the loader relocates.
4. **Room for a per-image payload the loader ignores.** AetherIR-compiled code
   still needs its constant pool, and later a debug-line table mapping bytecode
   offsets to source lines (the traceback in `as_traceback` is a real diagnostic
   and should survive going native). A named, optional, loader-ignored section is
   enough; a fixed set of segments is not.
5. **Version the header, and reject a mismatch loudly.** `.la` already does this
   (`AS_BC_VERSION`, and `test-selfhost-fixpoint` asserts the mismatch is a hard
   failure). An `.aex` that silently loads an image built for an older ABI is the
   same class of bug that the `roots_bundle.inc` dependency gotcha was.

Point 1 and point 3 are the two that are expensive to add later. **This is a
written note, not an agreed decision** — no reply has been received from the
format line at the time of writing.
