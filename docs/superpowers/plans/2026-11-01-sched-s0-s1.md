# LogitOS 调度器 S0 / S1 Implementation Plan

> **For agentic workers:** 这是实施计划，不是实现记录。执行者先读完整设计，再读本头部和自己的 Task；按 checkbox 逐项 TDD。Sol 实现，Astra 审查（风格违规也是 BLOCKING），Claude 在沙箱外跑门并提交。本文不授权执行 S2 或后续调度策略。

**Goal:** 在保持 HEAD 调度规则的条件下，建立能追溯每个输入结局的共同观测底座，分别取得 B-HEAD / B-input 基线，并建立不参与调度决策的拓扑和容量模型。

**Architecture:** 八条线路。记录器、输入记录、回执集合、帧时钟、硬件探查分别放在小文件中；现有文件只留接线。S1 的容量版本是观测对象，不写 `vtime`、不改变 `pick_min_locked()`、不选择 LP。实验程序通过单独的诊断入口使用同一份生产解码/建模代码，host 仅替换硬件边界，guest 证明真实二进制走了这些路径。

**Tech Stack:** C11 / x86-64、现有 clang / lld / nasm、Python 3、QEMU TCG；macOS arm64 host 的纯逻辑测试不执行本机 CPUID/MSR。

**Spec:** `docs/superpowers/specs/2026-11-01-hetero-interactive-sched-design.md`，第六版（附录 F）。旧计划按第五版/附录 E 写成；本次保留纠正说明，以第六版正文及附录 F 为准。本文只规划 S0/S1，不把后续阶段的协议提前实现。

**Verified baseline:** `main`，`4bc4819cfb2a9e126f6592226e6e2754052c134c`；当前设计SHA256=`371f28c3f10ce1bcb0c41486733e7582ea00a7268aeba8923a4146971b657527`。设计文件未跟踪也必须读取当前内容。以下代码file:line按该HEAD核实，`.hw/hw-run.py`按本地现存文件核实；实现前复查HEAD/status/mtime/锚点，不凭旧行号覆盖别人修改。

## Global Constraints

- **STYLE（硬规则）**：注释密度匹配周围代码；每个新增函数（包括 static / inline / 测试辅助函数）都有说明用途及 WHY 的注释；寄存器、位号、魔数、超时、硬件顺序注明 Intel SDM 卷/节/修订号及设计节号。硬件引用以设计指定的 2026-09、`325384-093US` 为基准；CPUID 对照同版 Vol. 2A 的 CPUID leaf/subleaf 表，MSR 对照同版 Vol. 4 的具名寄存器条目。不得套用旧版 §14.6/14.9 代替 Vol. 3B §17.6。
- 一行一条语句，正常缩进、括号、空行；不挤函数、不串逗号/分号；描述性名字，不用 `V2`、`next` 或 `x_x_X` 式长缩写。适当拆文件，每文件一个职责。只改本 Task 的 owned files，不用 `sed`，不建 scratch / backup / debug / stray 文件。纠正旧事实时在原注释旁保留旧结论及纠正理由。
- 在原树上实施，不自行创建分支/worktree。此次审查只修改本计划和 `.hw/sched-tracks.json`。新测试限本线路列出的精确文件；已有测试的必要接线/规格修正也逐文件列入 own，禁止目录通配扩大权限。`tests/` 被忽略是预期，不 force-add；产物全进独立 `BUILD`。
- **S0/S1 不改调度行为**：保留全局环、CFS 权重/虚拟时间、旧唤醒锁存、周期 PIT/LAPIC、`in_kernel` 抢占条件、TLB 入口检查。禁止提前加 EEVDF、每核队列、通用 resched IPI、新 idle 策略、HWP/EPP 调频、生产切换 HRESET 或租约。S0 依规格改变的是共同 GUI 基础设施：帧节奏、正确的两级合并/回执，以及 B-input 的输入/损伤/动画/维护统一等待；这些调用既有阻塞/唤醒 API，不能改变其调度规则。旧句“唯一变化是输入唤醒”不完整，按 §10.1/F9–10 撤回。B-HEAD 共用合并规则但保留旧等待，分开报告 GUI 基础设施行为与观测成本。
- `wm.c` 仅 `frame` 线路拥有；新逻辑放 `wm_frame.*`、`wm_work.*`、`wm_route.*`、`wm_receipt.*`。现有文件仅接输入、损伤、flush、动画/维护、关闭、整帧提交和等待的钩子；不改合成算法、图层或样式。队列/回执锁按 §7.4.8 修正，不以“保持旧锁协议”为由拒绝新增寿命保护。
- **UART 事实**：38400 baud 的 `kprintf` 会持 IRQ-off 锁，另有工作修串口非阻塞。本计划不依赖该修复、不改串口；每事件不得输出到 console。原始事件进 flight recorder / 不覆盖日志；实验内摘要进 HUD 或强制 ring-only 的 klog；不能只用 `KL_DEBUG` 假定永不输出，因为 `klog_console_level()` 可以升到 DEBUG。测量窗内禁止主动导出/console dump，记录任何既有 console 活动为干扰，重跑而非删慢样本。
- 原始 TSC 与单调 ns 都保存，跨 LP 比较带偏移及不确定区间；不用 host wall clock 作性能数据。不用 `time_mono_ns()` 的跨核 clamp 证明 TSC 同步。不变 TSC / ARAT / MWAIT / HFI 各自门控，不能由 CPU 型号或另一特性推定。
- 必要事件丢失、输入日志满、集合存储满、导出截断、未排空引用均令该实验 `INVALID`，不输出通过指标。普通 flight 环可覆盖但必须计数；不覆盖的 input records 不随令牌/队列槽复用而回收。
- 所有模型/QEMU记录、报告及提交说明带 **`not verified on X79-VG4 hardware`**；14700KF 同时写 `not verified on i7-14700KF hardware`。只有实际板上运行的证据可以改成 `hardware=X79-VG4` 或 `hardware=i7-14700KF`，带日期、镜像/源码 SHA、原始记录 hash，不能凭 HUD 截图推断延迟或能耗已验证。
- S0/S1 无性能撤回条件；测不到就记录 pending/unsupported，不能把逻辑 PASS 当阶段出口。`ε` 是观测覆盖内最长区间，`ε_np` / `D_ack` 到 S2b 才冻结；S0 不宣布确定性上界。§13 的 N2 定位、是否采样 E-only 线程仍开放；不实现采样迁移。σ 是否按类别区分由 S1 数据决定，不预先拍板。

## Review Focus

1. 观察装置看的是实际 guest 二进制，输入从 IRQ 起算而不是下半部/应用回执才起算；USB polling 输入单列来源，不冒称硬 IRQ 时间（S0a/d）。
2. 两级输入队列的合并/驱逐不能吞逐输入对象；未铸造、旧 app 无回执、关闭窗口、超时与完成竞争不改变分母（S0a/b/c）。
3. EDID 144 Hz 而活动 60 Hz、只有 GOP 几何、模式切换、错过多个边界、idle 无 damage 都须有确定结果；现有 100 Hz timer 的误差如实报告（S0c）。
4. 旧 CPU 查询不存在的 CPUID 叶会返回别的叶；HFI 16 位 row、共享 row、无 FREE 暂存槽、READING/旧版本引用必须有边界和交错门（S0d、S1a/b）。
5. 相关样本、+∞、RAPL 回绕、IRQ-off 测量自递归、SMT 历史覆盖都不能得到漂亮却无效的数字；sigma/migration 的 UNKNOWN 与真实零分开（S0a/e、S1c）。

`logit_sched_observe.h` 统一 command：`BEGIN=1, STOP=2, STATUS=3, READ=4, PROBE=5, MODEL=6`。request header 固定 `{uint32_t size, version; uint64_t run_id;}`，version=1；READ 追加 `{uint32_t stream, lp; uint64_t cursor, user_buffer; uint32_t capacity, copied; uint64_t next_cursor, gap_first, gap_last, final_seq; uint32_t flags, reserved;}`，stream=TRACE/INPUT/GROUPS/METADATA。每读者独立 cursor；返回完整 record 或明确 GAP/RETRY/FINAL，复制到私有缓冲再 copyout，不能把长输出塞 klog。BEGIN 追加 `{uint64_t input_capacity, group_capacity, manifest_hash[4], manifest, manifest_entries; uint32_t baseline, flags;}`；manifest 每项含 ordinal/event_hash、预定 input_class/source 以及 reducer ID/version、目标窗口/捕获代际、按钮/mods/允许类型，全部复制校验后封存；实际样本不符 INVALID。baseline=TRACE_ONLY/B_HEAD/B_INPUT。input/group 各至多1048576项，checked arithmetic、分配失败/坏指针/非法长度零副作用。BEGIN/STOP 限 root；READ 限 owner/root。无活实验的池有界，满计 observation_lost。

STOP 是状态机：关闭本 run 新输入准入，沿旧 timer 等每个原期限并排空回执/组/超时请求；再请每个生产 LP 在本地 irqsave 下关 trace 会话并 release ACK 最终 published_seq。等全 LP ACK、离线导出核对尾水位、所有 READ 引用归零才回收；未 ACK 报 PENDING/INVALID，保留内存且拒绝同代 BEGIN。生产者检查会话与写入都在本地 irqsave 内；READ 在会话控制锁内取得会话引用。不在持锁区等待，不依赖 S0d 才有的 IPI：S0a 的既有 IRQ/调度观测点处理关闭请求，未进这些点的 LP 保持未确认。

GROUPS必须可在停止后重建每个完成证明：实验owner给每个已发布组另持一份归档引用，直至INPUT/GROUPS均导出并确认才释放。STOP先排空的是非归档消费者；不能提前释放组再把已复用的slot/gen当历史。归档也受group_capacity限制，满则INVALID，不能只留下代表seq。record中的completion随终态一次写入；DONE/COALESCED_DONE必须有持引用提交快照的frame/group证据，APP_DONE/EXPIRED可无display证明。S0b核验reducer与state/surface后才调用finish，用户不能直接指定结局。观测host增加归档读后释放/完成证据夹具，`GROUP_ARCHIVE_EARLY_FREE`→`ASSERT group_history_exportable`、`INPUT_DROP_PROOF`→`ASSERT input_completion_proof`；完整导出释放owner后组引用也须全零。

provider kind 固定 `FRAME_METADATA=1, PROBE=2, TOPOLOGY=3, CAPACITY=4, CALIBRATION=5, SOUND_METADATA=6`。control 在已拥有的 `sched.c` 的 sched_init 末尾初始化，之后静态生命周期；各 provider 在首次会话前的控制初始化/本模块启动点登记一次，注册与 BEGIN 同控制锁，活会话拒绝登记。未登记返回 unsupported；S0a 不链接未来模块。S0c 在 wm 初始化登记 frame，S0d/S1 在 control 初始化登记，S0e 在 mixer 初始化登记 sound。HUD 只取快照，不持模块锁回调另一个模块。普通镜像不自动运行诊断基准。

记录 kind 固定为 `IRQ, WAKE, SWITCH, READY, MIGRATE, INPUT, OUTCOME, CAPACITY, TIMER, IRQOFF, KERNEL_SECTION`；S0 只产生已经存在的事件，未来 token/lease 类别留空。WAKE 路径 reason 为 `OBJECT/ASYNC_ID/TIMEOUT/NEW`；记录成功唤醒与无操作分别计数。READY→首次实际运行计算 latency；SWITCH 在实际提交和 incoming 位置关联，不把“选中”当“运行”。
