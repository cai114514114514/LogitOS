## 保留旧结论与更正

原结论：“未使用的 codec 和 UTF-16 接口刻意不提供。”
更正：用户并未授权缩减公开功能，已经补齐；55 个 parserutils 函数入口可用。

原结论：“IANA 表完整就足以保留编码名称。”
更正：部分历史调用名称不在当前 IANA 别名栏。现在独立补回已观察名称，
保留 262 个基线可查询编号；历史自定编号与 IANA 数据分开。

原结论：“分块 @charset 缺陷属于旧 LibCSS，留待以后。”
更正：在完整输入契约下它是实际缺口，已经修正，并观察到部分声明从提前 OK
变为 NEEDDATA，完整声明正确确定编码。

原结论：“普通可扩容缓冲足以作为解码窗口。”
更正：它会释放或移动尚未消费的 peek 指针。现在保留旧窗口到消费完成，
覆盖增长、插入和压缩；代码不再依赖消费者恰好不用旧指针。

原结论：“通用流可以把零码点替换掉。”
更正：U+0000 合法；追加与插入现均保留，CSS 专用预处理属于消费者。

## 约束与裁定

- 只使用公开契约、调用方、标准数据和基线二进制行为；不使用旧 .c 作模板。
- 不恢复 lwc 的私有缓存、手工销毁机制或二进制对象布局。
- 不复现非法 Unicode、错误 UTF-16 代理项和未知错误名称虚假成功。
- 原来不改 GenFS；用户后续明确要求删除，已删除其三项未跟踪残留，其他测试未动。
- 无新增测试文件；一次性诊断不等于持久专项回归。
- 初版表述“10 个新库对象”，补齐后为 17 个 C 文件。
- tools/license_audit.py 的旧注释仍写“三个 CSS vendor 库”；其逻辑仍有效，
  不扩大修改审计/测试工具。
- 最终修复经过独立复查，没有新阻塞项。malloc 失败仅审查代码，
  未做故障注入；长期并发压力也未做。

## 分开提交

原计划等待提交授权。用户随后明确要求“提交，分着”，按以下顺序执行。

1. 停止新增测试提交的忽略策略：仅 .gitignore。
2. 字符串库替换：新实现、对应 LibCSS 调用、该库构建和通知迁移、旧库删除。
3. 解析库替换：新实现、注册数据生成器、对应头依赖、构建和通知迁移、旧库删除。
4. LibCSS 分块编码探测修复：探测实现与相关说明。
5. 汇总报告：跨上述改动的核对结果与证明边界。

每笔提交包含自己的说明并保持可构建。共享文件使用精确路径与分块暂存，
不得 git add -A，不把无关修改合入。GenFS 残留原本未跟踪，没有 Git 删除补丁。
初次交付没有暂存、提交或推送；本次授权仅用于上述本地提交，没有推送。
