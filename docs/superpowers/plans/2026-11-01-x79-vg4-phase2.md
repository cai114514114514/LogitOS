## Review Focus

1. **中断从来没送到的真机情形**：X79 上至今没观察到任何 INTx，EHCI 靠 10 ms 轮询。每条改中断的线路都必须在收不到中断时自动退回轮询，并打印一行能在 HUD 上看到的诊断，而不是卡住。
2. **在 AP 上等待 I/O**：MSI 只发给调用 `dev_irq_request` 的那颗核，别的核上 `hlt` 等待会多等一个 AP 节拍（1.6–5.4 ms）。
3. **关中断的启动阶段**：`kmain` 在 IF=0 下运行；任何启动自检的等待都必须临时开中断，否则必然误判「没有中断」。
4. **ISR 上下文**：`prt` 合并后 EHCI 的 `usb_hc_irq` 也会从硬中断里运行，其中不能有 `delay()` 或睡眠。
5. **固件共享的 I/O 口**：Super I/O / HWM 端口与 SMM、AML 共用，任何写入都必须先确认固件不占用。

### Task P0：第 8 轮审计的四项修复（线路 `nct`）

**来源：** Astra 第 8 轮审计（`.hw/out/r8.json`），审的是 `3552ac4db`（NCT6779 只读硬件监控）、`741595bdf`、`8dec81f10`、`f2b60ab81`、`72aefd11e`。两项阻断、两项次要，全部在这条线路里修。

**目标：** NCT6779 的访问严格符合「只读，只允许写 HWM 索引口和 bank 寄存器 0x4E，并且必须恢复」；与固件（SMM/AML）共用这组 I/O 口时不再可能写错寄存器；HUD 不再把有效的封装温度显示成 n/a；LAPIC 定时器校准不再被一次 SMI 带偏。

**文件归属：**
- 修改：`c/drivers/board/nct6779.c`、`c/drivers/board/nct6779.h`
- 新建：`c/drivers/board/nct_acpi.c`、`c/drivers/board/nct_acpi.h`（uACPI 查询，编译选项由 Claude 在 Makefile 里加好）
- 修改：`c/kernel/diag/hwhud.c`（**只改** `lines_thermal()` 里封装温度的有效性判断，约 `hwhud.c:267`）
- 修改：`c/kernel/cpu/irq/lapic.c`（**只改** `lapic_timer_calibrate()`，约 `lapic.c:355–380`）
- 修改：`c/kernel/init/power.c`（**只加一行**：`power_boot_worker()` 里 AML 初始化成功之后调用 `nct6779_acpi_gate()`）
- 测试：`tests/hw-nct.mk`、`tests/hw/nct/**`；`tests/unit/x2apic_run.py` 和它编译的 LAPIC 主机测试源文件（只加用例，不删）

**接口：**
- 产出：`int nct6779_acpi_gate(void);`——在 AML 命名空间加载之后调用一次；返回 0 表示允许直接访问 HWM，负值表示固件占用、永久禁用直接访问。
- 产出：`int nct_region_conflict(const struct nct_io_region *r, int n, uint16_t base, uint16_t len);`——纯函数，供主机测试；`struct nct_io_region { uint16_t start; uint16_t len; }`。
- 保持不变：`nct6779_find()`、`nct6779_read()` 的签名和返回约定；`board.c:92`、`hwhud.c:273` 两个调用点不改。

#### 修复 1（阻断）：Super I/O 逻辑设备选择寄存器必须恢复

`nct6779.c:44` 选择 LDN 0x0B（写配置寄存器 0x07）之后，在所有退出路径上都没有写回原值，包括设备未启用和芯片 ID 不符这两条拒绝路径。

- 进入配置模式后，先读出 CR 0x07 的原值；所有退出路径（成功、设备未启用、ID 不符、任何错误）都在退出配置模式之前写回原值。用一个单一出口（`goto out`）实现，不要在每个分支各写一遍。
- 主机测试：模型初始 CR 0x07 = 0x00；三条路径（成功、LDN 0x0B 未启用、ID 不符）各跑一次，断言结束时选择寄存器等于初始值，并且整个过程中对 0x07 以外的配置寄存器零写入。
- 负对照 `NCT_NEGCTL_NO_LDN_RESTORE`：去掉写回，上面的断言必须变红。

#### 修复 2（阻断）：与固件协调，或者拒绝直接访问

`nct6779.c:63` 的索引/数据两步操作没有任何与固件的协调；SMM 在「写索引 0x4E」和「写 bank 字节」之间改了索引，就会把 bank 字节写进别的 HWM 寄存器，事后恢复 bank 也撤销不了这次写。关中断挡不住 SMM。另外 `:73` 的快照没有在 `board_init` 和 HUD 之间串行化，两个读者交错时可能把对方的临时 bank 4 当成原值保存下来，最后装回去的是错的 bank。

采用 Linux 的做法（`drivers/hwmon/nct6775-platform.c` 在 v6.12 里对 HWM I/O 区间调用 `acpi_check_resource_conflict()`，冲突时默认拒绝加载）：

- **固件占用检查**：`nct_acpi.c` 用 uACPI 遍历命名空间里所有 SystemIO 类型的 OperationRegion，收集 `(start, len)`，交给 `nct_region_conflict()` 判断是否与 HWM 的 I/O 区间（HWM 基址起 8 个字节，索引口 base+5、数据口 base+6）重叠。重叠就记一行 `[nct] HWM I/O 0x%x claimed by ACPI OperationRegion %s: direct access disabled`，从此 `nct6779_read()` 永远返回 `-EBUSY`。
- **时机**：`board_init()` 在 AML 初始化之前运行（`power.c` 的 `power_boot_worker()`）。所以 `board_init()` 里只做芯片发现（读 ID，带修复 1 的恢复），不读 HWM；HWM 读取在 `nct6779_acpi_gate()` 返回 0 之前一律返回 `-EAGAIN`。`power_boot_worker()` 在 `initialize_aml_locked()` 成功之后调用一次 `nct6779_acpi_gate()`；AML 初始化失败时不调用，HWM 保持禁用（宁可不显示风扇和温度，也不冒写错寄存器的风险）。
- **操作系统内部串行化**：一把自旋锁 `nct_lock`（`spin_lock_irqsave`）包住每一次完整的「保存 bank → 选 bank → 读 → 恢复 bank」事务，`board_init` 和 HUD 都经过它。快照只在锁内取、锁内用。
- 主机测试：(a) `nct_region_conflict()` 的边界用例：完全包含、部分重叠（只盖住 base+5 或 base+6）、相邻不重叠、长度为 0；(b) 两个读者在模型里交错，结束时 bank 寄存器等于最初的值；(c) 门未打开时 `nct6779_read()` 返回 `-EAGAIN` 且零次端口访问；(d) 门因冲突关闭后返回 `-EBUSY` 且零次端口访问。
- 负对照 `NCT_NEGCTL_NO_ACPI_GATE`（跳过冲突检查）和 `NCT_NEGCTL_NO_LOCK`（去掉 `nct_lock`），分别让 (d) 和 (b) 变红。
- HUD 对 `-EAGAIN` 显示 `nct pending`，对 `-EBUSY` 显示 `nct firmware-owned`，不再显示成读数失败。

#### 修复 3（次要）：HUD 的封装温度有效性

`hwhud.c:267` 要求 `IA32_PACKAGE_THERM_STATUS` 的 bit 31，而这一位是保留位，不是 Reading Valid（Intel SDM Vol. 3B, Figure 16-33；`thermal.c:50–52` 已经按这个写对了）。去掉 bit 31 的判断，改为和 `thermal.c` 相同的规则：`g_ptm` 为真且 TjMax 非零、`tj >= 读数` 时显示温度。主机或 guest 测试里加一个 bit 31 = 0 的封装状态值，断言 HUD 行显示温度而不是 `n/a`；负对照 `HUD_NEGCTL_PKG_BIT31` 恢复旧判断，断言变红。

#### 修复 4（次要）：LAPIC 校准的端点夹逼

`lapic.c:367` 的校准端点没有夹逼，并且只取一次样本：SMI 落在「启动计数器」和「读 t0」之间，或「读 t1」和「读 TMRCUR」（`:372`）之间，都会把 TSC 区间之外的 LAPIC 计数算进来。一次 10 ms 的端点延迟能让测出的频率翻倍，而且仍然落在合理范围内。

- 每个端点都用前后两次 TSC 夹住：`a = tsc; 写 TMRINIT; b = tsc` 和 `c = tsc; cur = 读 TMRCUR; d = tsc`。夹逼宽度 `b − a` 或 `d − c` 超过 `tsc_hz / 100000`（10 µs）的样本作废。
- 测 5 个有效样本，取中位数；最多尝试 15 次。有效样本不足 3 个时不采用测量值，打印 `[lapic] timer calibration disturbed (%d/%d samples): AP ticks keep the fixed counts`，退回现有的固定计数。
- 主机测试（x2apic 的 LAPIC 主机测试里）：模型在某一个样本的任一端点注入 10 ms 延迟，结果与真实频率的偏差 < 1%；所有样本都被干扰时退回固定计数。负对照 `LAPIC_NEGCTL_UNBRACKETED`（不检查夹逼宽度、只取一个样本）让偏差断言变红。

### Task P1：AHCI 中断与排队命令（线路 `ahci`）

**先读（调查结论，计划建立在这些事实上）：**

1. `tests/hw-ahci.mk` 和 `tests/hw/ahci/run.py` **已经存在**（上一轮“固件没配置的端口”的主机模型，`tests/hw.mk` 第 6 行已经 `-include tests/hw-ahci.mk`）。本线路在同一个片段和目录里**扩展**，`run.py` 一个字不改、必须继续通过。它靠正则抽取 `port_needs_reset(uint32_t det, uint32_t sig)`、`link_ms`、`port_link_reset(volatile uint8_t *pr, uint32_t *sig)` 和单行宏 `P_SCTL/P_SSTS/P_SERR/P_SIG/P_TFD/P_CMD/CMD_FRE/TFD_BSY/TFD_DRQ/SPIN_INIT/SIG_SATA`，这些名字和签名文本不许动；现有负控 `AHCI_NEGCTL_SIG_ONLY`、`AHCI_NEGCTL_NO_COMRESET` 保留。
2. **块层今天不能让同一介质同时有两条请求。** `blk_submit()` 遇到在途请求先 `poll_locked(prior)` 驱动到完成（`BLK_NO_INTERLOCK` 是它的负控，`make test-blk-async-negctl`），`struct blkdev` 只有一个 `inflight`；所有调用者（logitfs → bcache → `blk_read/blk_write` → `blk_wait`）都是同步自旋，只有 `c/kernel/mm/reclaim/swap.c` 的 `dev_io` 是异步（单条）。页缓存读路径没有预读，写回 `bcache_sync()` 逐个 4 KiB 同步 `blk_write`。所以：只做驱动不会有任何收益。最小块层改动 = ① `blkdev` 允许每介质 N 条在途（默认 1，旧行为和旧负控原样保留）；② 重叠范围/屏障规则；③ 批量入口 `blk_dev_batch/blk_write_batch`；④ `bcache_sync()` 改用批量写回。读路径、预读、swap 并发不在本任务内。
3. `ahci_init()` 在 `blk_init()`（`kmain.c:193`，挂载根盘之前）里运行，早于 `smp_init()`（`kmain.c:285`），那时 `lapic_ready()` 为假，不能申请 MSI。因此：根盘挂载全程轮询（这本身就是“轮询回退”的 guest 证据），中断由 `kmain.c` 里 `dev_probe_all()`（`kmain.c:293`）之后新增的一行 `ahci_irq_attach();` 晚期接上。
4. 诚实的预期：块层仍然举着 `g_ata_busy` 不可抢占地等，MSI 只能把 `pause` 自旋换成 `hlt`，不能把 CPU 让给别的线程。本线路交付的是机制、真机自检和实测数字，不承诺“修好桌面卡顿”。

```c
unsigned ahci_ncq_depth(uint32_t cap, uint32_t ncq_words);   /* ncq_words = id[75] | id[76]<<16; 0 = NCQ 不可用，否则 2..31 */
static int  ahci_slot_alloc(struct ahci_port *p, int ncq);   /* 最低空闲数据槽，没有则 -1 */
static int  ahci_issue(struct ahci_port *p, unsigned slot);
static int  ahci_check(struct ahci_port *p, unsigned slot);  /* 1 完成 0 在跑 -1 失败，一次观察不循环 */
static int  ahci_begin(struct ahci_port *p, unsigned slot, const struct ahci_cmdspec *s);
static int  ahci_step(struct ahci_port *p, unsigned slot, int expired);
static uint32_t ahci_port_irq_collect(struct ahci_port *p);  /* 读 PxIS，原子或进 is_latched，再回写 PxIS；ISR 和轮询共用 */
static void ahci_isr(void *arg);                             /* arg = struct ahci_ctl*，每个 HBA 一个 */
static int  ahci_recover(struct ahci_port *p, int cause);    /* AHCI_RC_TFES / _TIMEOUT / _FATAL */

static void ahci_blk_idle(void *ctx);

```
`struct ahci_port` 新增（块层驱动状态都放在槽里）：`struct ahci_slot { struct ahci_cmdspec cur; struct dma_mapping *mapping; uint64_t map_token; struct blk_req *req; uint64_t deadline; uint8_t attempt, state; } slot[32]; uint32_t nslots, qdepth, ncq_words, active_mask, ncq_mask; uint32_t is_latched, irq_events, irq_seen; struct ahci_stats st;`（`irq_events/is_latched` 是 ISR 与轮询共享的唯一状态，全部用 `__atomic`）。`blk_req.tag = 槽号`，一个请求超过 1 MiB 分块时复用同一个槽。`ahci_run(struct ahci_port *p, const struct ahci_cmdspec *s)` 和 `port_identify(struct ahci_port *p)` 的签名不变（`storage_hardware_test` 夹具桩了前者）；`ahci_run` 使用内部槽 `nslots-1`。

**设计要点（实现者按此写，不是代码）：**
- 槽布局：元数据一次连续分配 `0x800 + nslots*0x100` 向上取整到页（`nslots = CAP.NCS+1`；NCS=31 时 12 KiB，NCS=0 时仍 4096，与旧测试一致）。`+0x000` 命令表头（槽 n 在 `n*32`），`+0x400` 接收 FIS，槽 n 的命令表在 `0x800 + n*0x100`，PRDT 在表内 `+0x80`。`ahci_bring_up` 里 `memset(p->dma, 0, 4096)` 改成元数据全长。
- NCQ 深度：`qdepth = min(nslots − 1（留一个槽给 IDENTIFY/FLUSH/READ LOG 内部命令）, (id75 & 0x1f) + 1, 31)`；需要 `CAP.SNCQ`、`id76 ∉ {0x0000, 0xFFFF}` 且 bit 8、`nslots ≥ 2`，且深度 ≥ 2；否则 `qdepth = 1`，走今天的 READ/WRITE DMA EXT，行为不变。型号前缀黑名单表 `ahci_ncq_horkage[]`（初始为空，仅留注释说明来自 Linux `ata_device_blacklist` 的 `ATA_HORKAGE_NONCQ`）；编译开关 `AHCI_NONCQ`、`AHCI_NOIRQ` 是产品配置宏，不是负控。
- NCQ FIS（读 0x60 / 写 0x61）：`fis[0]=0x27, fis[1]=0x80, fis[2]=cmd, fis[3]=扇区数低8, fis[4..6]=LBA[23:0], fis[7]=0x40（不置 FUA）, fis[8..10]=LBA[47:24], fis[11]=扇区数高8, fis[12]=槽号<<3, fis[13]=0（PRIO 必须为 0，QEMU 会告警）`；表头 `5 | (写?1<<6:0) | (nprd<<16)`。发射顺序：`barrier()`，先 `P_SACT |= 1<<slot`，再 `P_CI |= 1<<slot`。NCQ 命令在队列非空时不等 `TFD.BSY|DRQ`（H:CheckBusy 由 HBA 自己做）；队列为空时保留现有 `wait_clear`。FLUSH/IDENTIFY/READ LOG 是非排队命令：队列非空时驱动返回 `BLK_E_AGAIN`，块层先排空再重试。完成判定：NCQ 看 `P_SACT` 位清零，非 NCQ 看 `P_CI` 位清零；PRDBC 检查只保留给非 NCQ。
- 中断：`ahci_irq_attach()` 对每个 HBA：确认所有端口队列为空；`dev->cap_msi` 为真才 `dev_irq_prefer(DEV_IRQ_MSI)` + `dev_irq_request(dev, ahci_isr, ctl, "ahci")`（之后还原 prefer），结果 `irq_mode != DEV_IRQ_MSI` 就 `dev_irq_release()` 并保持轮询。顺序按 `ahci_init_controller`：每端口 `PxIS`、再 `HBA IS` 清零 → 写 `PxIE = AHCI_PXIE_DEFAULT` → `GHC.IE = 1`（`ahci_prepare_controller` 的“IE 必须为 0”保持不变）。ISR 只做：读 `HBA IS` → 对置位端口 `ahci_port_irq_collect()`（读 PxIS、原子或进 `is_latched`、回写 PxIS）→ 最后回写 `HBA IS` → 若 `HBA IS` 仍非 0 最多再循环 4 次；`irq_events++`。ISR 绝不拿 BKL、不拿 `blkdev.gate`、不分配、不碰 DMA 映射。`ahci_check()` 总是先 `ahci_port_irq_collect()` 再看 `is_latched`，所以关中断（轮询回退）时同一条路径照常工作，8000 ms 单槽 deadline、`AHCI_RETRIES=8`、`SPIN_INIT/SPIN_CMD` 一个不改。
- 等待：`ahci_blk_idle()` 在 `irq_armed` 时 `cli; if (irq_events == irq_seen) { sti; hlt（紧邻） } else sti`，不武装时 `pause`；100 Hz 定时器给每次 hlt 加上 10 ms 的上限，所以不会出现丢唤醒的永久睡眠。
- 启动自检：`ahci_irq_selftest()` 武装后发一条只读 IDENTIFY，用 `link_ms()` 计时最多 50 ms，看 `irq_events` 是否增加：增加则打印微秒数并保持武装；没增加则 `PxIE=0; GHC.IE=0; dev_irq_release()`，打印 `NO INTERRUPT` 并留在轮询。`ahci_ncq_selftest()`（仅 `qdepth ≥ 2`）：从 `lba = 2048*i`（`i=0..15`，超出 `nsectors` 的跳过）读 16 段 × 8 扇区，一次用 `blk_dev_batch`、一次逐条串行，比较数据完全一致，打印两个耗时和 `max in flight`；这是只读的，可以在真机根盘上跑。
- 错误恢复 `ahci_recover()`（TFES/HBFS/HBDS/IFS 或 `TFD.ERR` 或槽超时）：① `port_stop`（ST=0 等 CR 清零，卡住则沿用现有“隔离并 panic”）；② 读 `P_SACT`/`P_CI`，已清零的槽按成功完成并 `dma_mapping_complete` + 解映射（**必须在 `dma_device_quiesced` 之前**，否则 token 被清、完成被拒）；③ 记录并清 `PxSERR`、`PxIS`；④ `TFD.BSY|DRQ` 仍置位则：`CAP.SCLO` 时设 `PxCMD.CLO` 等其自清，否则 `port_link_reset()` COMRESET；⑤ `dma_device_quiesced` → `dma_device_resume` → `dma_buffer_submit(metadata)` → `port_start`；⑥ 若恢复前 NCQ 在途：在内部槽用 READ LOG EXT 读日志页 10h（FIS：`fis[2]=0x2F, fis[4]=0x10, fis[5]=0, fis[9]=0, fis[7]=0x40, fis[12]=1, fis[13]=0`，一条 512 字节 PRD，不置写位），按 `ata_eh_read_log_10h` 解析：`NQ`（byte0 bit7）置位或日志读取失败 → COMRESET，全部在途命令 `attempt++`；否则故障 tag = `byte0 & 0x1f`，只有该 tag 的 `attempt++`，其余在途槽原样重发、不计次；⑦ 重发时对每个槽先 `dma_mapping_submit` 再按 SACT→CI 顺序发射；⑧ `attempt ≥ AHCI_RETRIES` 的终态失败沿用现有语义：`port_quiesce`、端口保持停止、`dma_dev.blocked` 不解除，其余在途请求也以 `-1` 结束（见末尾风险）。超时：先 stop/start 重发（现有行为），同一槽第二次超时才 COMRESET。连续 3 次 NCQ 恢复后 `qdepth` 降为 1，`blk_set_queue_depth(p->block, 1)`，打印 `ncq disabled after repeated errors`。
- 块层规则（`blk_submit` 在 `m->gate` 内）：`while (m->ninflight >= max(1, m->queue_depth)) poll_locked(oldest)`；`BLK_OP_FLUSH` 先排空全部在途；新请求范围与在途**写**重叠，或新写与在途**读**重叠，先把冲突的那条驱动到完成（读读重叠允许）；驱动返回 `BLK_E_AGAIN` 且 `ninflight > 0` 时驱动最老一条后重试；`queue_depth == 1` 时与现在逐字等价，`BLK_NO_INTERLOCK` 仍然只让那 3 条检查变红。`req_finish` 从链表摘除；`blk_dev_offline` 的排空循环改成“直到链表为空”。`blk_wait` 的自旋循环里 `ops->idle ? ops->idle(ctx) : BLK_RELAX()`。`blk_dev_batch` 沿用 `blk_wait` 的纪律（`g_ata_busy` 先加再 `sti`，结束还原），栈上最多 16 条 `blk_req`，用户态指针返回 `BLK_E_NODMA`（调用者回退到逐条同步）。
- `bcache_sync()`：把脏块攒成最多 16 段的 `blk_span`（每段 `SPB=8` 扇区，4 KiB）调 `blk_write_batch`，成功的段清脏位并 `st.writebacks++`，失败的保持脏位等下次（与 `flush_one` 现语义一致），最后的 `blk_flush()` 不变；`flush_one()` 本身不改（`claim()` 里的逐块驱逐写回仍是同步的）。

### Task P2：真正的 EHCI 周期调度，和不响应的键盘（线路 `ehci`）

**背景（都已在代码里核实过，不是推测）：**

1. `c/drivers/usb/ehci.c` 里每个中断端点独占整帧：`configure()` 用 `frame_owner[1024]` 找相位，把端点自己的 QH 直接写进 `e->frames[f]`，`qh->link=EHCI_END`，没有树、没有带宽表、没有 TT 记账；C-mask 在调用处写死 0x1c。
2. 每次重新挂起（re-arm）任何一个中断端点，都要把**整个**周期调度停掉：`int_arm()` 清 `CMD_PSE`，`periodic_service()` 在 `STS_PSS` 还没清零时直接返回，真正的重建要等下一次 `events()`（EHCI 定时器）。`pit.h` 里 `TIMER_HZ 100`，注释写明粒度是 10 ms，所以一次重新挂起要一到两个 tick。结论只靠代码就能得出：单个端点每秒最多交付约 50 个报告，而且挂起期间键盘、鼠标、hub 全部停摆。这是桌面卡顿的确定原因。
3. `configure()` 只把 QH 的 `link/next/alt` 设成 END，`ep` 和 `caps` 保持全零（设备地址 0、端点 0、Mult=0，EHCI 1.0 section 3.6 把 Mult=0 列为保留值），却立刻把它链进帧列表；`ehci_qh_init()` 要到第一次 arm 才被调用。配置了但没 arm 的端点（比如键盘接口 1 被 `hid_probe` 以 `ROLE_NONE` 拒绝）会永远带着一个全零 QH 留在运行中的调度里，还泄漏 4 KiB。
4. `clear_halt()` 对非 BULK 端点一律返回 -1，`hid_poll()` 忽略错误只管重新 arm。键盘的中断 IN 如果回 STALL，或者 split 每次都 XactErr，qTD 会以 Halted 完成，`int_poll()` 记一次 `errs`，端点被重建、重新 arm，然后无限重复，永远没有一个报告。面板上已经有 `errors` 和 qTD/QH token，但还没有人看过键盘那一行。
5. 键盘 QH 的编码和 Linux v6.12 `qh_make()` 逐字段一致，**已排除**：EPS=低速、Mult=1、hub 地址在 22:16（`d->tt_hub->addr`）、端口在 29:23（`d->tt_port`，Linux 对单 TT hub 也用 hub 端口号）、周期 QH 的 RL=0、DTC=0（数据翻转位在 QH overlay 里）、CERR=3、IOC；S-mask 0x01 加 C-mask 0x1c 等于 Linux TT_NEWSCHED 的 `check_intr_schedule`（C-split 在 uframe+2 到 min(uframe+4,7)）。`usb_enumerate_child()` 的 `tt_hub/tt_port/tt_multi` 也正确。
6. 键盘发 `SET_IDLE(24)`（96 ms）。合规键盘即使没按键也会每 96 ms 发一个报告，所以“键盘零个报告”意味着要么 `SET_IDLE` 被拒绝（`hid_probe` 把结果丢掉了，没有日志），要么中断 IN qTD 从未完成。单靠“PSE 被切断”只会丢一小部分报告（键盘 split 窗口是八帧里的一帧、五个微帧，每次切断约 7.5%），解释不了零。所以本任务**不假装找到了单点根因**：先去掉代码里确凿存在的两个缺陷（整调度停 PSE、全零 QH 提前入链），补上第三个很可能的（STALL/XactErr 永久不恢复），再加上能在真机上一次启动就区分各种可能的诊断（第 9 步的判读表）。
7. hub 自己的状态端点现在根本没有配置：`usb_hub.c` 的 `hub_probe()` 从不调用 `usb_configure_interface()`。所以“hub 状态端点与键鼠共存”在生产代码里还不存在，要作为一个**非致命**的附加项加进去。
8. 现有测试看不到这些：`tests/unit/ehci_test.c` 的 `time_mono_ns()` 让 PSS 立即跟随 PSE，没有任何东西遍历调度；`tests/hw/usb/input_test.c` 只用了 `ehci_hw.h`，从不链接 `ehci.c`。

**设计一句话：** 周期调度改成 Linux 的做法：公共的、可在宿主上单测的纯逻辑（带宽表、TT 预算、S/C-mask、周期树）放进新的头文件 `ehci_sched.h`；`ehci.c` 里每个端点一个完整初始化的 QH，永远不为了 arm 或 configure 去停 PSE；re-arm 用 dummy qTD 交换（Linux `ehci-q.c qh_append_tds`），摘除 QH 用“先摘链、再等 ≥1125 µs”（Linux `ehci-timer.c EHCI_HRTIMER_UNLINK_INTR`）；PSE 只在第一个端点入链时打开、最后一个端点摘除后延迟 10 ms 关闭（Linux `EHCI_HRTIMER_DISABLE_PERIODIC`）。

**5. 实现 `ehci.c`（只在本步改生产代码）。**

- [ ] `configure()`：对每个中断端点 `ehci_ps_make` → `ehci_sched_tt(hub 地址, port, multi)` → `ehci_sched_admit`（失败则整个端点失败，不碰任何硬件状态，不停 PSE）→ 分配 arena（QH@0、qTD A@128、qTD B@192、payload@256）→ **先完整** `ehci_qh_init`（现有签名，S/C-mask 来自 `ps`）并把 `next` 指向 dummy qTD A（`ehci_qtd_dummy`，token=HALTED）→ `dma_wmb()` → `ehci_ptree_link` → `intr_count++`，从 0 到 1 时才置 `CMD_PSE` 并等 PSS（唯一的一次，`pse_toggles++`）。任何失败路径都 `ehci_sched_release` 并释放 arena 之外的所有状态；arena 没有 free，所以必须在 `ehci_sched_admit` **成功之后**才分配（避免泄漏）。
- [ ] `int_arm()`：若 `armed` 直接返回 0；否则按 Linux `qh_append_tds` 的次序：填好当前 dummy（`ehci_qtd_fill_in`，其 `next` 指向另一个 qTD，那个 qTD 先被 `ehci_qtd_dummy` 重置），`dma_wmb()`，最后才写当前 dummy 的 token（Active）。不读写 `USBCMD`，不等 `PSS`，不在这里重写 QH。
- [ ] `int_poll()`：qTD 仍 Active 返回 -1；完成则复制 `qh->token` 的低 8 位和翻转位到诊断字段（不读已释放的 DMA），按位计入 `err_*`；成功则 `cur ^= 1`，返回 payload。`p->toggle` 不再使用（硬件维护）。出错时调用 `ep_recover`。
- [ ] `ep_recover()`/`periodic_tick()`：错误端点置 `EP_UNLINKING`，`ehci_ptree_unlink`，记下 `unlink_ns`；`periodic_tick()` 在 ≥1125 µs 之后用 Linux `qh_update` 的方式刷新 overlay（`next=当前 dummy`，`alt=END`，`token &= TOGGLE`），重新 `ehci_ptree_link`；STALL 单独排 `stall_work`。`device_close()` 同样先摘链再等 ≥1125 µs（线程上下文，用现有 `delay()`）才 `memset` 端点。对 LS/FS 端点摘链前先置 `EHCI_QH_INACTIVATE` 并等一帧（EHCI 4.12.2.5），等待用模型时间，不用 tick。

### Task P3：ACPI 中断路由与多 IOAPIC（线路 `prt`）

**决定（依据代码证据）：采用“AML 就绪后重新路由已经在线的 INTx”，不把 AML 提前。** 证据：`c/kernel/init/kmain.c` 的顺序是 `pci_init()` → `smp_init()`（其中 `ioapic_init()`）→ `dev_probe_all()`（驱动此时调用 `dev_irq_request`），之后才 `wm_run()`；`sched_init()` 在 `c/kernel/gui/wm.c` 的 `wm_run()` 里（约 5343 行），`kernel_power_start()` 在同一函数后面（约 5414 行）。`power_acpi_native_start()`（`c/drivers/power/acpi/native.c`）要求 `sched_current_thread() && time_ready()`，还要排工作队列；`power_acpi_start()`（`c/drivers/power/acpi/devices.c`）里 `uacpi_namespace_load()/uacpi_namespace_initialize()` 可能睡眠、可能跑数秒。所以 `dev_probe_all()` 时根本没有可用的解释器，把它挪到前面等于重排整个启动。因此：探测时仍按“RCBA → 固件中断线”先接上，AML 就绪后由 `pci_intx_reroute_all()` 逐设备搬家。搬家复用现有、已被测试的 `intx_release()` + `intx_setup()` 生命周期（先关设备 INTx、再屏蔽 RTE、排空在途 ISR、释放向量，然后在新 GSI 上重建），不新造底层状态。电平中断不会丢：设备在 `PCI_CMD_INTX_DIS` 期间保持内部状态，重新使能后仍然拉线；再加一次“补发”调用成员处理函数，覆盖边沿（TCG 变通）和芯片组锁存的情况。

优先级固定为：`_PRT`（AML）> RCBA（PCH `DxxIR`）> 固件中断线。三者不一致时用 `_PRT`，并打印一行 `CONFLICT`。未在 X79-VG4 实机验证：本任务只有宿主模型和 QEMU 证据，无法证明 `_PRT` 或 RCBA 哪个更接近机器真实接线，所以日志要把两者都留下来。

### Task P6：串口控制台的整行输出（线路 `console`）

**背景（Claude 在最终合并结果上查明）：** `test-ahci-sector` 在合并结果上 3 次失败 3 次，数据其实逐字节正确，失败是因为 guest 打印的 `STORGATE-ok image across reboot byte-exact` 被内核的 `[wm] anim …` 日志从中间截断，例如串口上出现 `STORGATE-ok[wm] anim open  win 0 p 145 rect 118 75 98image across reboot byte-exact4 600 …`。`test-as-a3-only` 的 `EVENTS-READY` 被拆开也是同一原因。

原因：`kprintf` 持有 `printf_lock`（`c/kernel/diag/kprintf.c`，`kprintf_console_enter()`/`kprintf_console_leave()`）写完整条消息；而用户程序写串口控制台的路径 `c/kernel/exec/fd/file.c:160` 逐字符调用 `serial_putc()`，不拿这把锁，所以内核消息能插进用户输出的任意字节之间。

**Files：**
- `c/kernel/exec/fd/file.c`：只改串口控制台的写路径（约 `:150–160`）。用户写入按行输出：每一行（到 `\n` 为止，包括 `\r\n` 转换）在 `kprintf_console_enter()`/`kprintf_console_leave()` 之间写出，所以内核消息只会落在两行之间。这把锁会关中断，所以单次持锁的输出要有上限：超过 `CONSOLE_LINE_MAX`（建议 160 字节，注释写明为何这个长度在 38400 波特下的关中断时间可以接受，并引用 `kprintf.c` 里同一把锁已经覆盖整条消息的先例）的行分块输出，块之间释放锁。回显路径（`:150–152`，单字符）不变。

**门：**

### Task P7：HDA 输出路径经过混音器（线路 `hda`，为 L7 准备）

**背景（Claude 在 `989d3c591` 上读代码查明）：** X79-VG4 的板载编解码芯片是 Realtek ALC887（`docs/hw/X79-VG4.md`）。`c/drivers/audio/hda.c` 选输出路径时（约 `:620–645`）只认「引脚的连接表里直接列着 DAC」这一种形状；找不到就退回「第一个 DAC + 第一个输出引脚」。QEMU 的 `hda-output` 是单跳，所以现有的门都通过。ALC88x 系列的输出引脚（线路输出 0x14、环绕 0x15、中置/低音 0x16、侧环绕 0x17、前面板耳机 0x1b）连接的是混音器 0x0c–0x0f，混音器再连 DAC 0x02–0x05；Linux `sound/pci/hda/patch_realtek.c`（v6.12）的初始化会打开混音器上 DAC 那一路的输入放大器并设置引脚的连接选择。现在的代码在 ALC887 上会退回到 DAC 0x02 + 第一个输出引脚，既不设连接选择，也不打开混音器输入，结果很可能是寄存器都写了但没有声音。采集路径已经能走两跳（`try_capture_path()`），输出路径要做到同样的水平。

**Files：**
- 新建 `c/drivers/audio/hda_route.c`、`c/drivers/audio/hda_route.h`：**纯函数**的输出路径搜索，不依赖内核头文件，内核和主机测试编译同一份源文件（不要再写一份「移植版」，`tests/unit/hda_capture_graph_test.c` 头注释里写的漂移风险就是这样来的）。输入是一张内存里的 widget 表（nid、类型、widget cap、pin cap、默认配置 `cfg`、连接表、输入/输出放大器能力），输出是一条路径：引脚、途经的混音器或选择器、DAC，以及每一跳需要设置的连接选择下标和需要打开的放大器。
- 修改 `c/drivers/audio/hda.c`：输出部分改为先读出整张 widget 表，交给 `hda_route` 选路径，再按结果发出动词（连接选择 `0x701`、放大器 `0x3`、引脚控制、EAPD、电源）。采集路径不改。
- 测试：`tests/hw-hda.mk`、`tests/hw/hda/**`。

**引脚优先级（写进注释并引用来源）：** 只考虑默认配置的连接性不是「无连接」（bits 31:30 ≠ 01）且具备输出能力的引脚。按默认配置的设备类型排序：线路输出（0x0）> 扬声器（0x1）> 耳机（0x2）> 其它；同类型里按默认关联号（bits 7:4，0 和 0xF 排在最后）升序、再按序列号（bits 3:0）升序，这与 HDA 规范 1.0a 第 7.3.3.31 节对关联/序列的定义以及 Linux `snd_hda_parse_pin_defcfg()` 的做法一致。搜索深度最多两跳（引脚 → 混音器/选择器 → DAC，或引脚直连 DAC）；没有可达 DAC 的引脚跳过，全部不可达时返回错误，**不再猜**第一个 DAC。同一 DAC 只分配给一个引脚（本任务只驱动一个输出，但函数要能返回第一选择之外的候选，供以后的多路输出）。

**门：**
- `test-hw-hda-host`（依赖 `test-hw-hda-negctl`）：用三张 widget 表跑 `hda_route`：(a) QEMU `hda-output` 的单跳图，结果与现在的行为相同；(b) ALC887 的图（nid、连接表、默认配置值按公开的 ALC887 codec 转储或数据手册填写，在测试文件里注明来源），断言选中线路输出 0x14、经过混音器 0x0c、DAC 0x02，连接选择下标正确，混音器上 DAC 那一路输入被打开；(c) 所有输出引脚都标成「无连接」的图返回错误。另外在主机上用一个记录动词的假 `codec_cmd` 跑 `hda.c` 的输出设置（如果做不到在主机编译 `hda.c`，就把「路径 → 动词列表」也放进 `hda_route.c` 并测试它），断言发出的动词序列包含引脚连接选择和混音器输入放大器的解除静音。

### Task P8：swap 换入预留耗尽和无 swap 时的回收活锁（线路 `oom`）

**背景（P5 的写手用 GDB 定位，Claude 在 `989d3c591` 上复核）：** 这两个问题是 P5 记录的「已定位的 mm 缺陷」。用户已决定 mm 的重新设计排在调度之后；本任务**不是** mm 重设计，只修这两个让门变红的缺陷，改动要小。
1. **换入预留耗尽杀进程**：`c/kernel/mm/reclaim/reclaim.c` 的 `reclaim_swapin()`（约 `:674–720`）两次 `pmm_alloc_reserve_any()` 都返回 0 时直接 `c_swapin_fail++; return 0;`，`fault.c` 的 `MM_FAULT_SWAP` 分支（约 `:593`）于是把这次缺页记为普通的 decline，进程被杀，尽管机器上还有可丢弃的页。`SWAPBUS=ahci` 的运行出现过 1 次这样的失败。
2. **无 swap 时回收活锁**：`test-swap-negctl` 在压力下反复打印 `[reclaim] 290 frames free and nothing reclaimable (scanned …)`，既不宣布内存耗尽，也不让 OOM killer（`c/kernel/mm/reclaim/oom.c`）杀掉施压的进程，直到测试超时。负对照要求的是：工作负载失败、内核和 shell 存活（`tests/boot/run-swap-test.sh` 的 `noswap` 分支：不得出现 `MEMPRESS-OK`，必须出现 `MEM_ALIVE` 和 `LogitOS x86_64`）。

**要求：** 先找到根因再改（写手可用 GDB，像 P5 那样）。换入时预留耗尽，应当和匿名缺页一样走「为内存不足而 decline」这条路径（`fault.c` 里 `g_oom_decline` 的约定），让 OOM 的处理决定杀谁，而不是杀掉恰好在换入的进程；回收在「空闲帧低于水位且一轮扫描没有任何进展」时必须在有界的轮数内放弃并交给 OOM，界限写成常量并在注释里说明取值理由。不要改水位、预留大小、swap 格式或页缓存。

**Files：**
- 修改：`c/kernel/mm/reclaim/reclaim.c`、`c/kernel/mm/reclaim/oom.c`、`c/kernel/mm/reclaim/oom.h`、`c/kernel/mm/virt/fault.c`（只改 `MM_FAULT_SWAP` 分支和 OOM decline 的判定）、`c/kernel/mm/phys/pmm.c`（只在需要暴露预留状态时）。
- 测试：`tests/hw-oom.mk`、`tests/hw/oom/**`。

**门：**

### Task P4：更快的合成器（线路 `gfx`）——暂缓，本轮不执行

**目标：** 先在真机上量出桌面卡顿到底花在哪，再改最大的几块。已知数据：硬件面板上合成平均 2.8 ms、最坏一帧 234 ms。平均值不是卡顿的原因，卡顿来自两类东西：(a) 每次鼠标移动都整块重合成（见下面的事实 1）；(b) 偶发的长帧（原因未知，S0 加仪表后才能定位）。所以本任务分七段，S0 到 S2 是必做，S3 到 S6 按依赖顺序做，每一段单独能合并。

**已查实的现状（均已在 `hw/x79-vg4` 上 grep 过，实现者不必再证明，但要用 S0 的数字来确认）：**

1. 光标：`hw_cursor`（`c/kernel/gui/wm.c`，第 2923 行）等于 `fb_cursor_image(...) == 0`，而 `fb_cursor_hw()` 在 `c/kernel/gui/fb/fb.c` 里是 `using_gpu && virtio_gpu_cursor_ready()`。X79-VG4 只有 UEFI GOP 帧缓冲，所以 `hw_cursor` 为 0。结果：每个鼠标样本都走 `dirty_cursor(omx,omy); dirty_cursor(x,y)`（64 像素光标盒 +1），再整套 `render_layers` + `render_top` 里的 `draw_cursor_back`，光标盒碰到菜单栏、Dock 或任何窗口玻璃标题栏时，`dmg_expand` 还会把矩形长成整块玻璃面板重新磨砂。`wm.c` 里的注释给过代价：玻璃约 102 到 205 ns/像素，普通像素约 30 ns/像素（那是开发机和 QEMU 的数，不是 X79）。
2. 并行：`GFX_NCTX=4` 不在 `Makefile`，而在 `tests/fluid_perf.mk` 第 43 行（`CFLAGS += -DGFX_NCTX=4`）。所以 `PAR_NW = 3`，`par_start()` 起 `min(smp_cpu_count()-1, 3)` 个 `wm-band` 线程（栈 64 KiB），合成最多 4 个线程，在 20 线程的 E5-2670 v2 上只用了 4 个。`par_render` 要把帧切成 `2*(par_nw+1)` 个水平带，但玻璃面板的采样范围不可切（`wm_bands.h` 的 `nocut`），一块整宽的菜单栏或 Dock 面板就是一个带，所以加线程不一定缩短关键路径。`par_frame_ok()` 在有窗口动画、Expose、锁屏时返回 0，回到串行。
3. 玻璃：`fb_liquid_glass` → `ol_display_liquid_glass` → `liquid_glass_impl`（`c/lib/gfx/effects/openlogit_material.c`）每帧每块面板都重新 `glass_blur` + `glass_render`，没有任何缓存（`wm_glass.c` 末尾 `wm_glass_tick` 写着 “none yet”）。`glass_blur.c` 是逐像素 `unpack`/`display_rgb`，THICK/ULTRA 各 3 遍、横纵共 6 遍，纵向遍按列走。
4. 像素循环：`ol_display_blit_surface`、`ol_display_fill_rect`、`ol_display_blend_rect`、`rr_blend_span`、`ol_display_blit_glyph`、`ol_display_blit_glyph_a`（文字走这个，`c/kernel/gui/text.c` 第 354 行）、`ol_display_blit_argb`、`ol_display_blit_surface_alpha` 和 `wm_internal.h` 里的 `blit()` 都是标量循环，每通道一次 `/255`。内核 `c/lib/string.c` 的 `memcpy` 是 8 字节循环，`memmove` 是逐字节循环。
5. SSE：内核 `CFLAGS` 带 `-msse -msse2`（`Makefile` 第 280 行），`c/boot/long.asm` 打开 `CR4.OSFXSR/OSXMMEXCPT`，每条中断路径（`c/boot/isr.asm` 的 `isr_common`、`c/drivers/core/irq.c` 的 `irq_stub_common`、`kprof_isr`、`kdiag.c`、`c/kernel/cpu/power/mce.c`）都有 `fxsave/fxrstor`；`context_switch`（`c/boot/switch.asm`）只存被调用者保存的寄存器，而 XMM 全是调用者保存的，所以线程切换不需要处理 XMM。`c/lib/nn/matmul.c` 已经在内核里用 `<emmintrin.h>`。结论：**内核线程里直接用 SSE2 是安全的，不需要 `kernel_fpu_begin`**。线程栈对齐已由 `sched.c` 的 `top - 8` 保证；SIMD 局部数组保持在 512 字节以内（带线程栈 64 KiB）。
6. AVX：`c/boot/long.asm` 显式清 `CR4.OSXSAVE`，`cpu_avx_usable()`（`c/kernel/cpu/cpufeat.c`）固定返回 0，中断、`enter_user.asm`（`fxrstor [r13]`）、`thread_fork` 的 512 字节 `user_fxarea`、信号帧（`c/kernel/exec/signal/ksigframe.c`）全是 FXSAVE 格式。Ivy Bridge 的 AVX 只有 256 位浮点，没有 256 位整数指令；像素内核是整数运算，AVX 只带来三操作数编码，且 IVB 的存储端口每周期 16 字节，256 位存储没有吞吐收益。**决定：本阶段不启用 AVX。** 将来若要做，前置条件是把上面所有保存路径迁到 XSAVE/XRSTOR（区域大小取 CPUID.0Dh:0 的 ECX，64 字节对齐，EDX:EAX 传状态掩码），这是单独的一项改动，不在本任务内。
7. SSSE3/SSE4.1 只用于函数级 `__attribute__((target("ssse3")))`/`("sse4.1")` 的可选变体，用 `cpu_has(CPU_SSSE3)`/`cpu_has(CPU_SSE41)`（`c/kernel/cpu/cpufeat.h` 已有这两个枚举）同一判断的 CPUID 位决定；基线内核仍是 `-msse2`。收益很小（`pshufb` 做 alpha 广播、`pmovzxbw` 代替 unpack），只有 S2 的基准证明有 10% 以上收益时才加。

#### S3：玻璃模糊（SIMD，位精确）

参考：现有 `glass_blur.c` 本身就是参考（`average(sum,count) = (sum*reciprocals[count]) >> 16`）。向量化用的恒等式：窗口和最大 `255*41 = 10455`（最宽的单遍窗口 `2*GLASS_BLUR_RADIUS_MAX+1 = 41`），装得进 u16；`PMULHUW(sum, recip)` 精确等于 `(sum*recip)>>16`，只要 `recip < 65536`，即 `count >= 2`；`count == 1`（宽或高为 1）单独处理为 `sum`。

设计：
- 纵向遍：行优先，对每个 `x` 维护一个 u16×4（R、G、B、第 3 字节）的列和数组（放在 `OL_DS_GLASS2` 缓冲的尾部），每次处理 4 个像素；进入行 `y+r+1` 加、离开行 `y-r` 减，`count` 对整行相同，`recip` 是广播量；输出前把第 3 字节清 0（`display_rgb` 的语义）。读源、写目标分开（两块缓冲乒乓），所以不再需要现有代码里的“最近 radius+1 个原值环”。
- 横向遍：沿 `x` 有递推依赖，改成同时处理 4 行（两个 `v8u16`，每个装两行的 4 通道和）：每步各行取进入和离开的像素，一次加减，一次 `pmulhuw`，一次打包，4 次 32 位存储；高度余数用 2 行、1 行的尾部。
- 乒乓：总遍数 `P`（REGULAR 为 2，其余为 6），第 `i` 遍写入 `(P-1-i)` 为偶数则 `glass_buf` 否则第二块，保证**最后一遍落在 `display->glass_buf`**，`glass_render` 不用改。第二块缓冲分配失败就整体回 `glass_blur_ref`。

#### S4：玻璃记忆（对同样的背景不再重算）

原理与正确性：`liquid_glass_impl` 的输出像素只取决于（采样框内的背景字节、面板几何、色调、不透明度、材质、目标尺寸、通道位置），`prepare_samples` 保证采样框包含面板框。所以“采样框字节完全相同 + 键相同”就一定得到相同输出，**与谁上报了损伤无关**（Dock 的图标悬停、光标盒这类“在玻璃上面”的变化不会让记忆失效，真正改了背景才会失效）。这比按损伤失效精确，代价是每次一遍 `memcmp`，约等于读两遍采样框（Dock 约 0.9 MB，比一遍模糊便宜一到两个数量级）。

Add `-arch x86_64 -msse2 -mno-sse3` builds of simd_test, blur_test and string_test, run under Rosetta (the finding says arch -x86_64 works on this Mac), plus an SSE4.1 build, all inside test-hw-gfx-host. If Rosetta is missing, fail with a clear message rather than skip silently. Guard every inline cpuid with #if defined(__x86_64__).
2. S5 tuning can run before SMP. fb_present_bench() runs at kmain.c:279 and smp_init() at :285, and g_par_present is registered later. If the first present covering at least half the screen happens before fb_set_present_par() is called, have_smp=0 is fixed for good and ALLCPU is never measured. Tune only once g_par_present != NULL && smp_cpu_count() > 1; until then use MOVSB and do not latch a pick.

For the Dock sweep, count only cursor-caused damage (a new dirty-reason counter) or compare against the hover-only composite count. Also list the guest-only control kernels (GFX_NEGCTL_CURSOR_RECOMPOSE, GFX_NEGCTL_SIMD_VERIFY_OFFBYONE) with their own BUILD dirs in the gate. They are not in test-hw-gfx-negctl, so state where they run.
4. Glass memo: memset the glass_memo_key to zero before filling it. A byte copy of the material struct carries padding bytes, so memcmp would miss nondeterministically (wasted work, not wrong pixels, but it breaks the exact hit/miss counts in memo_test). Never call ops->alloc/release (kmalloc) while holding the memo spinlock; allocate first, then publish under the lock.
