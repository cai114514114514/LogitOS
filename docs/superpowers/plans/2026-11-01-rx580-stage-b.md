# RX 580 阶段 B：让微码真正装进显卡（实施计划）

> 设计：`docs/superpowers/specs/2026-11-01-rx580-driver-design.md` 第 4 节。前置：B0 固件交付已合并（`ae0616f95`：根盘 + U 盘启动模块 + SHA256 固定）。
> 流程（用户 2026-11-01）：Sonnet 写，Claude 审查、跑门、提交。QEMU 没有 Polaris，真实证据只来自 X79-VG4。

**目标：** 在真机上看到：VBIOS 来自 EFI ROM 映像（不是 BAR0）→ 显存保留清单与独占 arena → 安全密钥 → SMU 微码加载完成（SRAM `0x47e`）→ SDMA0 环在屏幕外完成填充与非恒定拷贝并读回一致。**第一次上真机只到自检为止，不安装呈现钩子**；画面仍由 CPU 呈现。

## 全局约束

- 已有代码（`c/drivers/gpu/amd/polaris/**`，约 4.3k 行）只修不重写；它的模型测试全部保持通过。
- 每一步打一行串口日志并上 HUD（`[amd-b] stage=… result=…`），失败就停在那一步，不影响桌面。
- 开关：U 盘 ESP 上存在 `\LOGIT\NOGPU` 文件，或内核以 `HWHUD` 以外的配置构建时，阶段 B 整体跳过（默认：HWHUD 镜像里开启）。
- 只认 Polaris10 系列（`67df`、`6fdf` 等，A0 收拢的 `polaris_device_known()`）；其余设备只读。
- 不接管内存控制器（GMC）：保持 GOP 留下的平面映射；README 现有的「拒绝无法确认的布局」规则不放宽。

## Task B1：VBIOS 来源（引导加载器 + ACPI VFCT）

- 加载器：`ExitBootServices` 之前，对每个显示类（class 0x03）PCI 设备用 `EFI_PCI_IO_PROTOCOL` 的 `RomImage`/`RomSize`（UEFI 规范 14.4）把 ROM 拷进 `EfiLoaderData`，以启动模块交给内核，名字 `vbios-SSSS:BB:DD.F`（4 位十六进制段、2 位总线、2 位设备、1 位功能，小写，取自 `GetLocation`）。
- 内核：`resource/device.c` 的 `discover_vbios()` 优先用匹配本设备 BDF 的 `vbios-*` 模块；其次 ACPI `VFCT` 表里匹配 BDF 的映像；都没有就不解析（BAR0 不再作为来源）。校验 0x55AA、ATOM 头和长度，越界拒绝。
- 门：主机测试（模块与 VFCT 两种来源、BDF 不匹配、截断与签名错误）；QEMU OVMF guest：std-VGA 的 ROM 作为 `vbios-0000:00:02.0` 模块出现并被正确列出；负对照：去掉 BDF 匹配、去掉长度检查各让一项变红。

## Task B2：A0 只读显示扫描 + 显存保留清单 + arena

- `polaris/display/crtc.c`（新）：6 个 CRTC（`vid.h` 偏移）读 `CRTC_CONTROL.CRTC_MASTER_EN`、`GRPH_ENABLE`、`GRPH_CONTROL`、`GRPH_PRIMARY_SURFACE_ADDRESS(_HIGH)`、`GRPH_PITCH`、时序寄存器；找出 GOP 用的 CRTC 并与 GOP 帧缓冲核对；用 `CRTC_STATUS_FRAME_COUNT` 实测刷新率。只读。打印 `[amd-dce] …`，HUD 一行。
- 保留清单：所有激活 CRTC 的扫描输出（pitch × 高度，向上取整到 64 KiB）、VBIOS `VRAM_UsageByFirmware`、VGA 模式时的 VGA 分配（`gmc_v8_0_get_vbios_fb_size`）。
- arena：在 CPU 可见 aperture（BAR0）内、所有保留区之外，选 2 MiB 对齐、大小为 `polaris_runtime` 计算出的需求的窗口；记下 MC 地址与 CPU 地址的对应，并用现有的映射回调核对。
- 门：主机测试（模拟寄存器文件：单 CRTC、双 CRTC、VGA 模式、保留区挤满时拒绝、aperture 不够时拒绝），负对照：漏算一个 CRTC 的扫描输出 → arena 与之重叠的断言变红。

## Task B3：安全密钥、所有权与自检运行

- 安全密钥：经 SMC 间接寄存器读出（参考 `polaris10_smumgr.c`、`smu7_smumgr.c` v6.12 的判断），决定 `polaris10_smc.bin` / `polaris10_smc_sk.bin`；读不出就停在这一步。
- 所有权：`bootfb.c` 从被动认领转为独占租约（禁止其他驱动绑定、在 reboot/S5 前静默）；资源描述填完整后调用已有的 `polaris_runtime_start()`，参数要求「只自检、不安装呈现钩子」（若入口没有这个模式，加一个显式参数，不改变现有模型测试的默认行为）。
- 打印每个阶段（`[amd-polaris-runtime] stage=… failed_stage=… error=…` 已有）并上 HUD。
- 门：现有 19 个 Polaris 模型门全部通过；新增主机测试：密钥两种取值选对文件、自检模式下绝不调用 `fb_set_native_present`；负对照：自检模式下仍安装钩子 → 变红。QEMU：无 Polaris，启动不退化（`test-hw-board-guest`、`test-hw-fwwire-guest`）。

## Task B4（第二次上真机之后）：SDMA 接管呈现

- 前提：B3 在真机上自检通过；A1 硬件光标已合并（否则软件光标会因 `native_present` 退出）。
- 补 pitch 感知的 `LINEAR_SUB_WINDOW` 拷贝；安装钩子；呈现计数和失败隔离上 HUD。

## 顺序

B1 与 B2 互不依赖，可并行；B3 依赖二者。每完成一个就合并、打镜像，B1+B2 合并后的镜像即可在真机上先看到 VBIOS 来源、CRTC 扫描和 arena（全部只读）。
