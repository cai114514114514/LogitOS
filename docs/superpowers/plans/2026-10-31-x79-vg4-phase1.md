# X79-VG4 第一阶段实施计划

> **For agentic workers:** 每条线路由 Mac 上的 `hw-run` 调度器交给一个 Codex `gpt-6.1-sol`（较弱模型，high）写代码，再由 `gpt-6-astra`（强模型，xhigh）只读审计；Claude 在合并前做最终检查。agent 只读本文件里“全局约束”、“复核重点”和自己的那一节，加上设计文档。步骤用 `- [ ]` 标记。

**Goal：** 不依赖真机，把 X79-VG4 首启需要的启动介质、芯片组识别、RTL8168G、USB 输入、显示分辨率和诊断报告做到宿主模型 / QEMU 全绿，第二阶段直接上真机。

**Architecture：** 6 条互不重叠的线路（T1–T6），每条有独占文件、独立 `BUILD` 目录和自己的 `tests/hw-<线路>.mk`。Task 0 先搭好调度器和测试汇总入口，Task 7 合并、出镜像、写真机操作说明。

**Tech Stack：** C（内核 / 驱动）、NASM、Python 3（`tools/`）、PowerShell 7（Windows 安装脚本）、QEMU + OVMF、Codex CLI。

**Spec：** `docs/superpowers/specs/2026-10-31-x79-vg4-bringup-design.md`

## 全局约束

- 分支 `hw/x79-vg4`，仓库 `~/LogitOS`。
- 并行线路各自在 `~/LogitOS/.hw/wt/<线路>` 下的临时 worktree 里工作，基于 `hw/x79-vg4` 开分支 `hw/x79-vg4-<线路>`。`.hw/` 加进 `.gitignore`；线路合并后，它的 worktree 立即删除。
- agent 不执行 `git commit`、`git push`、`git checkout`、`git reset`、`git stash`。提交由调度器完成，只提交本线路的独占文件。
- 构建一律加 `BUILD=build-hw-<线路>`。
- 按用户 2026-10-24 的规则，`/tests/` 整个被 gitignore，新测试只留在本地、不提交。线路结束后，调度器把 `tests/hw-<线路>.mk` 和 `tests/hw/<线路>/` 拷回主仓库的工作区。
- 新的测试目标只写进本线路的 `tests/hw-<线路>.mk`，不改 `Makefile`。`Makefile` 在 Task 0 一次性加上 `-include $(wildcard tests/hw-*.mk)`。
- 每条线路必须提供 `test-hw-<线路>-host`。这个目标要依赖 `test-hw-<线路>-negctl`，而负控必须真的会变红（删掉或改坏被测代码时失败）。Task 0 的 `test-hw-x79` 汇总所有线路，并接进现有的测试套件，不能留下没人跑的目标。
- 不删除、不跳过任何已有测试目标，`tests/audit-unwired.baseline` 也不许新增条目。
- 已有的回归必须保持通过：`test-x79-host`、`test-ehci-host`、`test-usb-hub-host`、`test-hda-x79-host`、`test-nic-drv`、`test-uefi-load-policy-host`。
- 注释和提交说明遵守 `TRANSPARENCY.md`：只有宿主模型或 QEMU 证据时，写“未在 X79-VG4 实机验证”。
- 新加的 PCI ID 必须在代码注释里写明依据（Intel 6 系列 PCH 数据手册、Linux 驱动中对应的表）。
- LogitOS 根分区的 GPT 类型 GUID 固定为 `6c6f6769-7466-4a73-9a2b-58373956b434`，`tools/` 和内核用同一个常量。
- 目标机器的 ID：
  - SATA `8086:1c02`；
  - EHCI `8086:1c26` 和 `8086:1c2d`；
  - 速率匹配集线器 `8087:0024`；
  - HDA `8086:1c20`，位于 00:1b.0；
  - SMBus `8086:1c22`；
  - 网卡 `10ec:8168` rev `0x0c`，子系统 `10ec:0123`；
  - GTX 1050 `10de:1c81`，它的 HDMI 声音 `10de:0fb9`；
  - 键盘 `24ae:4056`，鼠标 `18f8:1286`。

## 复核重点

1. **写错磁盘**：`install-root.ps1` 遇到多块未分配空间，或者未分配空间不在 C: 之后、C: 被 BitLocker 加密、磁盘是动态磁盘时，必须拒绝并说明原因（T1 的负控覆盖每一种）。
2. **未知芯片版本**：RTL 的 XID 不在支持列表里时，必须打印 XID 并拒绝绑定，不能按 8168G 硬上（T3 负控）。
3. **复合 HID 只有一个接口能用**：键盘复合设备的第二个接口（多媒体键）报告格式不认识时，第一个接口必须照常工作（T4 负控）。
4. **显示器没有 EDID 或 EDID 坏了**：回退到最大的 32 位模式，并在串口写明原因；不能黑屏（T5 负控）。
5. **根盘没挂上**：`hwreport` 在根盘不可用时照常把报告和 `[hw] milestone root FAIL` 打到串口，然后走内核现有的挂载失败路径，`hwreport` 自身不能卡住启动。`LOGIT_BOOT_OK` 的语义不变：只有启动成功才输出（T6 负控）。
