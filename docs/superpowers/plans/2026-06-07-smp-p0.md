## Feasibility / hazard analysis (from grounding)

VERIFIED AGAINST REAL CODE (line anchors confirmed). Key corrections to the grounding follow.

== BKL hand-off through context_switch — the #1 risk, exact ownership ==
context_switch (switch.asm:17-36) pushes rbp,rbx,r12,r13,r14,r15,pushfq; saves rsp to [rdi]; loads rsi; popfq,pop r15..rbp; ret. Three resume targets:
(1) EXISTING thread previously suspended inside schedule(): resumes at the instruction AFTER `context_switch(...)` in sched.c. It still holds g_sched_lock. It releases g_sched_lock there. The BKL is NOT touched by schedule(); it stays held by the core for the whole IRQ/syscall and is released by interrupt_handler's exit. Consistency holds because the incoming thread was last suspended inside an IRQ/syscall path that itself acquired the BKL and will release it on its own exit. This is "implicit transfer": only one core ever holds the single BKL, and whichever thread is running on that core when the IRQ/syscall unwinds does the release.
(2) NEW user thread first run via ring3_bootstrap (enter_user.asm:19): the context_switch ret lands here with r15=entry,r14=ustack still in regs (popped by context_switch). It holds g_sched_lock AND the BKL is held by this core. It must release BOTH before iretq to ring3. SOLUTION: insert `call sched_unlock_new_thread` as the FIRST instruction of ring3_bootstrap (before `mov rdi,r15`). sched_unlock_new_thread() does spin_unlock(&g_sched_lock); spin_unlock(&g_bkl). FEASIBLE: r15/r14 are callee-saved across the C call (SysV) so they survive; the call only touches the two spinlocks. After the call, IF will be set by enter_user's iretq frame (0x202) regardless, so we DO NOT use irqrestore here — use bare spin_unlock for both. Confirmed enter_user pushes RFLAGS=0x202.
(3) NEW forked child first run via fork_ret (enter_user.asm:31): context_switch ret lands at fork_ret with rsp pointing at the copied struct registers frame. Insert `call sched_unlock_new_thread` as the FIRST instruction of fork_ret (before `pop r15`). FEASIBLE: a call pushes+pops a return address (net rsp delta 0), so the subsequent `pop r15` is still correct; the regs frame below is untouched; child gets IF from its iretq (cr->rflags inherited from parent, which had IF=1). Bare unlocks, same as (2).

== execve is NOT a hand-off hazard (CORRECTION to grounding) ==
The irq-syscall grounding flagged "execve calls enter_user without BKL release". FALSE. Verified exec.c:73-167: proc_execve REWRITES the syscall frame `r` in place and returns normally; the iretq happens in isr_common's tail, so the BKL is released by interrupt_handler's normal syscall-exit path. exec.c:164 (thread_create_user) is in proc_SPAWN, a different function, not execve. No special handling needed for execve. Note exec.c:154 does `sti` mid-execve (IF on while loading) — under BKL this is fine: a timer IRQ arriving there will spin on the BKL (held by this core) which is exactly correct; but it could self-deadlock if the same core's IRQ tries to re-acquire the BKL the core already holds. MUST audit: this `sti` (and the SYS_HTTP_GET `sti`) means an IRQ can fire on a core that already holds the BKL → ticket-lock self-deadlock. RESOLUTION: BKL must be acquired with spin_lock_irqsave (IF cleared while held) so the holding core cannot be interrupted into BKL re-acquire; the deliberate `sti` inside execve/http_get then re-enables IF AFTER the BKL is held — those IRQs land on a DIFFERENT core's view? No — sti is local. So a local timer IRQ WILL fire while this core holds the BKL → self-deadlock. RESOLUTION for P0: keep the existing `sti`-around-blocking-fetch behavior working by making interrupt_handler re-entrancy-aware via per-cpu in_kernel depth: if this_cpu()->in_kernel>0 on IRQ entry, the core already holds the BKL — do NOT re-acquire (just run the handler, which for the timer means SKIP schedule() to avoid re-entrant switch, EOI, return). Simplest correct P0 rule: interrupt_handler checks `if (this_cpu()->in_kernel) { /* nested: already hold BKL */ run handler body WITHOUT acquire/release and WITHOUT schedule() } else { acquire; in_kernel=1; body; in_kernel=0; release }`. in_kernel lives in struct cpu (already in the spec). This makes the execve/http_get `sti` windows safe (nested IRQ runs under the already-held BKL, no double-acquire) while still allowing net_poll/timer to fire. This is the precise mechanism; documented in Stage 6.

== Per-CPU current via LAPIC id ==
this_cpu() scans g_cpus[].lapic_id vs lapic_id() (lapic.c:38 = MMIO read of LAPIC_ID>>24). O(MAXCPU<=8), called under BKL on fast paths — acceptable. CONSTRAINT: lapic_id() needs the `lapic` MMIO pointer set (lapic.c:9), which lapic_init() establishes (idempotent after BSP). So in ap_entry, lapic_init() MUST run before the first this_cpu() call. RISK confirmed and ordered correctly in Stage 4.
ORDERING HAZARD (CORRECTION to grounding): sched_init() is called from wm_run() (wm.c:930), which runs AFTER smp_init() (kmain.c:61 then :66). But APs started by smp_init() call this_cpu()/schedule() immediately. So g_cpus[] MUST be populated by smp_init BEFORE the APs run, and BSP's g_cpus[0].current must be valid before any AP enters schedule(). RESOLUTION: (a) BSP percpu init (g_cpus[0].index/lapic_id + load BSP per-cpu GDT/TSS) happens in gdt_init() at kmain.c:31 — but lapic_id() isn't available then (lapic mapped only in smp_init via lapic_init). So gdt_init builds g_cpus[0] by index 0 unconditionally (no this_cpu); g_cpus[0].lapic_id is filled in smp_init AFTER lapic_init() (smp.c:103), before the SIPI loop. (b) this_cpu() falls back to &g_cpus[0] until lapic_id is registered — correct for the BSP-only window between gdt_init and smp_init. (c) CRITICAL: AP scheduler entry must be GATED so APs do not enter schedule() until sched_init() has built the global ring with at least the WM thread. Since sched_init runs in wm_run AFTER smp_init returns, smp_init's AP bringup must NOT let APs reach schedule() yet. RESOLUTION: ap_entry parks on a `volatile int g_sched_ready` flag (sti;hlt loop, NO BKL) until wm_run's sched_init() sets g_sched_ready=1; only then does each AP create its idle thread and enter schedule(). This makes the AP-start ordering safe without reordering kmain. Documented in Stage 4.

== Per-core TSS/GDT ==
struct tss is currently file-local in gdt.c:19-27; struct gdt_entry/gdt_ptr at gdt.c:5-17. percpu.h must embed struct tss, so these move to gdt.h (gdt.h currently only declares gdt_init/tss_set_rsp0). Verified gdt.h:1-20. gdt_flush.asm:17-25 does lgdt+reload data segs but NOT CS — its comment (gdt_flush.asm:7-8) relies on per-core GDT slot1 (kcode) being byte-identical to the boot/AP-trampoline GDT (0x00AF9A000000FFFF, set_seg(1,0x9A,0x20)). Confirmed consistent, so APs need no far-jump to reload CS. tss_set_rsp0 (gdt.c:83) writes the single global tss; becomes this_cpu()->tss.rsp0. Called from sched.c:180 and :211. After ltr loaded the per-core TSS descriptor, writing rsp0 in the struct needs no ltr reload (CPU reads rsp0 live on each ring3→0 trap). FEASIBLE.

== IRQ re-entrancy while holding BKL ==
spin_lock_irqsave clears IF before spinning (prevents a core spinning with IF=1 from taking its own timer IRQ into the same lock = self-deadlock). Confirmed required. The deliberate `sti` windows (execve exec.c:154, SYS_HTTP_GET in wm_gui_syscall) re-enable IF while the BKL is held → handled by the in_kernel nesting rule above. schedule()'s old cli/sti (sched.c:165,186-187) is REPLACED by spin_lock_irqsave/spin_unlock_irqrestore(&g_sched_lock,flags); the trailing sti at sched.c:187 is deleted. schedule() MUST be __attribute__((noinline)) so the per-thread `flags` local lives in each thread's own frame (the post-context_switch irqrestore uses the INCOMING thread's flags — correct because each thread's schedule() call brackets its own IF state).

== thread_exit static discard race ==
sched.c:194 `static uint64_t discard` is a single global — two cores in thread_exit() clobber it. Move to a per-cpu field (struct cpu.exit_discard) or use a local (never read back since thread_exit never returns). Use `this_cpu()->exit_discard`.

== timer_tick cross-core race ==
APs use LAPIC timer at vector 32 (same as BSP PIT IRQ0 path); interrupt_handler irq==0 calls timer_tick() (pit.c global tick counter). Under BKL, only one core runs interrupt_handler at a time → tick counter safe. But to avoid multiple cores each advancing wall-clock ticks, gate timer_tick() to BSP only: `if (this_cpu()->index==0) timer_tick();` — all cores still call schedule(). Confirmed pit timer_tick is BSP semantics.

== Present revert ==
fb.c:172-182: g_par_present defaults NULL; fb_present_rect falls back to fb_copy_rect when NULL. So simply DELETE smp.c:162 fb_set_present_par(smp_present) and the benchmark block (smp.c:148-163). No fb.c change. vector-240 path (interrupts.c:45-49) becomes dead; make it a no-op (lapic_eoi+return) since no IPI-240 is sent after revert.

== LAPIC timer calibration ==
lapic_timer_init(uint8_t vec, uint32_t count) (lapic.c:67) — div-by-16, periodic. count is uncalibrated; pick empirically under -smp 4 TCG so preemption is visible (start ~10000000, tune). This is the only genuinely empirical knob in P0.

## Implementation plan

=== M25 P0 IMPLEMENTATION PLAN (ORDERED) ===
Big Kernel Lock SMP: spinlocks + per-CPU state + AP scheduler + 1 global runqueue + BKL + context-switch/BKL hand-off + BSP-only present.

All line anchors are against the code as it exists today. Build after every stage. Some stages are only end-to-end testable together (noted). Default check between stages: `make` (kernel still links/boots single-core; QEMU default is NOT -smp so most stages boot uniprocessor first) then `make test` (-smp 4, asserts AETHER_BOOT_OK).

    while(dead_threads){ struct thread*t=dead_threads; dead_threads=t->next; if(t->stack)kfree(t->stack); kfree(t); }

    struct thread*next=NULL, *s = prev->next, *start=s;

      spin_unlock_irqrestore(&g_sched_lock, flags);
    }
