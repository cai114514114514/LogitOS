# AetherScript 3：语言规则与当前实现边界

版本 3 在原有 `c/apps/as/` 中实现，入口仍为 `as`。它是静态类型、原生提前编译的独立语言，不依赖 Python 运行时。宿主构建工具使用 LLVM 和 LogitOS 已有的 AEX 打包器；生成的程序不携带解释器。

本文把已经执行验证的行为与尚未交付的语言设计分开记录。不能用“支持版本 3”代替完整语言、GC、调试器或 Studio 开发闭环的验收。

最终迁移目标已收紧为只支持 A3：A1/A2 的引擎、缓存、标准库和工具链入口全部退出。下文保留的“A2 暂时保留”是迁移过程的历史状态，不是最终兼容承诺；只有完整功能迁移和宿主/来宾验收通过，才能报告这项目标完成。

A2 到 A3 按语言能力和标准库功能迁移，逐项状态见
[功能对照与验收](AETHERSCRIPT_A2_TO_A3.md)。A1 到 A2 的源码迁移不能替代这项工作。

## 1. 版本与入口

后续语言版本统一采用 **3.x**，通过兼容的小版本补齐能力和修复问题，不再规划新的大版本语义重构。当前实现仍处于开发阶段，不能据此宣称完整 3.0 已交付。

当前原生文件第一行声明：

```python
# aether: 3.0
```

`# aether: 3` 是 `3.0` 的别名；尚未实现的显式小版本（如 `3.1`）会被拒绝，避免旧编译器冒充支持未来能力。导入的模块同样需要声明。

原计划“冻结并保留版本 1、2”已被新的迁移决定取代：**A1 支持删除，A2 暂时保留**。显式 A1 源码和格式 5 的 A1 `.la` 均拒绝执行并给出迁移提示。无声明的旧源码按 A2 检查整数规则执行；A2 继续使用格式 6 的 `.la`，该格式编号与语言版本独立。静态模块不能直接导入 VM 模块。工程配置选择版本、配置与文件声明冲突诊断仍待实现。

原生可执行程序入口为 `main() -> i64` 或 `main() -> None`，不接收参数。`i64` 返回值交给平台退出状态；运行时失败优先返回 1。程序参数、标准库入口适配尚未完成。

## 2. 类型、作用域与函数

已实现的基础类型：`i8/i16/i32/i64`、`u8/u16/u32/u64`、`f32/f64`、`bool`、`str`。当前宿主和来宾均为 64 位，`isize/usize` 对应 `i64/u64`；32 位目标尚未实现。

- 无目标类型的整数字面量默认为 `i64`，浮点默认为 `f64`。
- 带目标类型的整数直接检查该类型的范围，包括 `u64` 最大值和 `i64` 最小值。
- 十进制前导零不改变进制：`010` 是 10；`0xff` 是 255。
- 局部变量首次赋值推断类型，之后赋值不能静默改变类型。
- 整数与浮点、有符号与无符号整数之间不隐式转换。
- 非下划线开头的模块级函数必须声明所有参数类型和返回类型。
- 私有函数可从调用推断参数，从可达的 `return` 推断返回类型；它只有一个静态签名，不按调用自动产生重载。
- 无调用且无法推断参数的私有函数要求注解。仅根据函数体反向推断参数的完整约束求解尚未实现。
- 返回类型尚未确定的递归调用要求显式注解。显式声明签名的递归可以原生运行。
- 无返回值的调用不能赋值给变量，`None` 当前只能作为返回类型。

后续修正：无返回值调用仍不能赋值；`None` 字面值现在可存储，值类型名为 `NoneType`。`Optional[T]` 用存在标记和内联 T 表达可空值，明确上下文接受 T 或 None；`-> None` 继续表示无返回结果。局部值经过判空可在相应控制流路径当作 T 使用，赋值/循环/异常路径会清除可能过期的事实。细则与验证见 [迁移记录](AETHERSCRIPT_A2_TO_A3.md)。

循环规则补充：`for item in source` 的 source 在进入循环前只求值一次，
因此可以使用进入时已经成立的 Optional 非空证明。循环持有选中的迭代
对象；循环体把原 source 改成 None 并触发 GC，也不能释放仍在遍历的
对象。循环体和反复求值的 while 条件继续检查回边，不沿用可能失效的
非空事实；这不允许在第二轮读取已被置空的原变量。

```python
# aether: 3
def _double(value):
    return value * 2

def main() -> None:
    print(_double(21))
```

在同一程序中再调用 `_double(1.5)` 会产生类型错误。

所有读取必须经过确定初始化检查。`return`、`break`、`continue` 分别记录控制流出口，已终止的路径不参与后续初始化合并。循环可能执行零次，其内部赋值不能单独证明循环外变量已经初始化。

类支持单继承 `class Child(Base):`，父类必须已声明或导入。字段必须显式声明，继承字段不能重名；方法重写必须保持参数和返回类型。子类可以作为父类引用使用，调用仍选择对象的重写方法。`super.method` 选择词法父类实现，支持绑定方法和闭包捕获。构造、初始化异常、容器不协变的完整规则及测试边界见 [原生类与构造器](AETHERSCRIPT_A2_TO_A3.md#原生类与构造器)。

旧实现只接受导入、结构体和函数声明。现已补齐带初始值的模块变量及 `global` 重绑定，检查仍不执行用户模块。模块初始化只在生成的原生程序入口执行，具体次序和提前读取规则见第 8 节。

条件表达式 `a if condition else b` 检查分支类型一致，只执行选中分支。字符串支持比较、`in` 和单参数 `.find()`，沿用原来的字节偏移及空串查找规则。旧说明中的“尚未覆盖分配、拼接”已经过时：动态字符串支持拼接、重复、索引、slice/sub、split/join/replace、strip 和 ASCII 大小写；转换和格式化字符串仍待实现。

### 泛型函数

```python
def identity[T](value: T) -> T:
    return value

def total[T: Number](values: Slice[T]) -> T:
    result = T(0)
    for value in values:
        result += value
    return result
```

调用根据实参推断类型参数，包括固定数组到切片的借用。每组具体类型生成独立原生函数，同类型重复调用复用实例；跨模块、递归调用同样经过检查。

无约束的 `T` 可传递和返回，但不承诺算术操作。内置 `Number` 约束允许整数/浮点数值操作，`Integer` 进一步允许整数位运算、移位和乘方。模板即使没有调用也检查函数体；不能通过调用另一个泛型偷偷加强约束。`T(0)` 显式构造该数值类型，避免让整数常量隐式混入浮点运算。实例化后仍检查具体位宽的溢出及借用逃逸。

泛型函数的参数和返回类型必须声明，最多 8 个类型参数。当前支持调用推断，尚不支持调用处显式类型实参、自定义协议和泛型结构体。展开深度和总实例数有上限，超过时给出诊断。

## 3. 数值行为

系统内建的 `SYS_*`、`EV_*`、`LST_*` 和 `CAP_*` 常量是 i64 值。
它们取自 LogitOS 的目标 ABI，不取宿主操作系统的编号，也不是随上下文改变
类型的字面量；需要其他位宽时使用显式转换。用户的模块/函数声明、局部变量、
参数和闭包捕获优先于内建名称。读取常量不执行系统调用，也不授予 capability。

| 操作 | 已执行验证的规则 |
| --- | --- |
| 整数 `+ - *`、取负 | 超范围产生 `OverflowError` |
| 整数 `/` | 向零截断；除零产生 `ZeroDivisionError` |
| 整数 `%` | 与向零截断的商一致 |
| 最小有符号整数 `/ -1`、`% -1` | 产生 `OverflowError` |
| `wrapping_add/sub/mul` | 明确选择按类型位宽回绕 |
| 整数 `<<` | 移位数必须在 `[0, 位宽)`；结果必须可表示 |
| 整数 `>>` | 有符号数算术右移，无符号数逻辑右移 |
| 整数 `**` | 指数必须非负，检查乘法溢出，`0 ** 0 == 1` |
| 非法移位数、负整数指数 | 产生 `ValueError` |
| 显式数值转换 | 转换前检查目标范围，非法转换产生 `ConversionError` |

整数乘方采用平方求幂。不会计算最后一次已经不需要的平方，例如 `i8` 中 `100 ** 1` 必须成功。调试与发布模式使用相同检查，不启用 fast-math。浮点乘方尚未实现。

`range(stop)`、`range(start, stop)`、`range(start, stop, step)` 在 `for` 中使用，停止值不包含在结果内。正负步长均可，步长为零产生 `ValueError`。内部宽计数器允许最后一步越过停止值，不能因此发生回绕或把有效范围变成无限循环。

## 4. 值布局与借用

```python
struct Point:
    x: f64
    y: f64

def sum(values: Slice[i64]) -> i64:
    total = 0
    for value in values:
        total += value
    return total
```

- `struct` 按值复制，字段必须声明，构造时初始化全部字段。
- 结构体身份包含所属模块；不同模块可以各自声明不同的 `Point`。
- 通过 `from module import Point` 显式导入类型；仅加载模块不会把其中所有类型加入当前作用域。
- `Array[T, N]` 内联存储同类型元素；数组字面量需要目标类型。
- 索引带边界检查，负索引当前视为越界，不采用 Python 的尾部索引语义。
- 数组可在函数调用处借用为只读 `Slice[T]`。修改 `slice[0].field` 或更深层字段同样被拒绝。
- 当前禁止返回包含借用切片的值，包括结构体、数组内嵌的切片；完整的所有者生命周期签名仍待实现。
- 循环计数器和取地址所需临时值在函数入口分配，不随循环迭代积累栈空间。

当前资源限制包括：64 个模块、512 个函数、256 个类型、每函数 256 个局部变量、单源码 1 MiB、每个字面量/调用最多 32 个元素/参数。它们是编译器实现限制，不是无限扩展能力的承诺。

更正：综合标准库会在泛型实例化前耗尽上述 256 项类型表。类型表现扩为 1024 项固定地址存储（包含泛型参数和复合模式），由同一分配入口检查容量，超限保留首个诊断。其他限制不变；这仍是明确的实现上限。固定地址避免递归检查持有的类型指针因扩容失效。

### 显式 ABI 字节记录

`layout` 现在支持模块级、编译期固定的声明：

```python
# aether: 3.0
Header = layout("header", 8, [
    ["code", 0, 2, "u"],
    ["payload", 2, 6, "s"]
])

def main() -> None:
    header = Header()
    header.code = 42
    header.payload = Bytes("ok")
```

大小为 1..65535，字段最多 32 个。名称、偏移、宽度、种类必须是字面量，
超出范围、重复字段、无法访问的字段名称在编译期报错；不支持运行时布局工厂。
`i/u` 的宽度必须为 1、2、4、8，分别对应定宽有符号/无符号整数；`p`
固定为 8 字节的 u64 原始地址；`s` 是固定宽度的字节字段。允许非对齐与
重叠字段，当前原生目标使用小端存储。

`Header()` 分配清零、非移动、GC 管理的固定记录；赋值共享同一存储，
普通 `struct` 仍按值复制。字段整数的溢出规则与其定宽类型一致。字节字段
读取返回独立 Bytes，保留尾部 NUL；写入 Bytes 后将剩余空间填零，超长
写入抛 ValueError 且不修改旧内容。文本必须显式 `Bytes(text)` 转换。

记录支持 Buffer 的长度、字节索引/写入、负下标、迭代和成员检查；
`Bytes(record)` 拷贝为不可变快照。`unsafe` 中的 `addr(record)` 指向
载荷首字节，`mem2str/mem2cstr` 使用记录长度检查边界。p 字段不会成为
GC 根，写入原始地址的代码必须另外保持所指对象存活。

`str/print` 展示 C 布局名和各字段值，固定字节字段使用 Bytes 的十六进制
表示，避免将任意二进制作为终端文本。Any 和容器中的记录保持同样表现。

同一记录的引用可放入 List/Dict/Optional/Any 或捕获到闭包；类型身份包含
声明模块，相同字段布局的不同声明不能隐式互换。编译器结构化符号输出
包含这些类型声明及其源码位置。完整标准库 ABI 包装和 Studio 服务仍需
独立迁移，不能由这一项的通过推断全部完成。

后续更正：原路径 `abi.as` 已重写为 A3，31 个记录和全部调用包装共享上述
类型系统。标准库现有 13 个 A3 模块，仍待迁移 `asc/sys/gui/image`。

再次更正：`sys.as` 随后也已原地重写为 A3，现有 14 个 A3 标准库模块；
剩余 `asc/gui/image`，不能把临时旧缓存视为最终保留范围。

后续更正：`image.as`、`gui.as` 也已原地重写，当前 16/17 个标准库模块
为 A3，剩余 `asc.as`。`guidemo.as` 保留原来的弹球和按键退出行为，
使用显式 main、Optional 判空及事件字段的定宽转换。

### 图片和窗口库

`image.Image` 持有固定 RGBA Buffer，`at(x, y)` 按 0xRRGGBBAA 返回像素，
索引和构造尺寸都会检查边界。`decode` 保留 5/10/20 MiB 重试策略，失败
调用的局部所有者先退出，再回收。内存不足保持 MemoryError 类型并补充
文件名及请求字节数；调用者持有的图片仍占用同一进程堆，预算不是保证。
`probe` 保留 `[format, size]` 形状，显式返回 List[Any]；调用者使用 cast。
相对路径先规范化为绝对路径，权限预检仍不能代替内核的 capability 检查。

`gui.blit` 接受 ByteStorage 并验证源尺寸和容量，目标坐标与 ABI 定宽字段
使用检查转换。`text_px` 保留带长度的 UTF-8 视图；布局中的地址字段不承担
GC 保活，参数所有者保持到同步调用结束。`poll` 返回 Optional[Event]，
仍复用原事件记录，下一次成功轮询会改变先前返回对象的字段。

文字测量 ABI 使用 `(px << 2) | face`，face 的低两位分别为 mono/bold。
`gui.measure(s, px, mono)` 保留原参数名，但该参数传递两位字体标志；
与内核绘制使用同样的字号和字体。旧描述中 `(px << 1) | mono` 已修正，
它曾使 A3 查看器按半字号计算宽度，造成换行和右对齐错误。

原生临时根过去一直保留到函数返回，导致连续换图时旧容量无法回收。
`backend/llvm/roots.c` 现在在语句结束后清除该语句的临时根，保留局部变量、
闭包和全局根，也保留外层循环的迭代源及尚未求值完成的调用参数。
这不是完整变量活跃性分析；具名局部所有者仍按其现有作用域保持存活。

### 现有描述符的作用域包装

`with stream = port(fd):` 为已有描述符建立借用包装器。作用域退出、异常
或显式 close 仅释放包装器，原描述符由原持有者负责关闭。0/1/2 沿用继承
标准流权限；其他描述符需要 CAP_RAW。`.kind()` 对 0/1/2 保留 `tty` 名称，
这是历史分类，即使标准流被重定向也一样，不是终端检测结果。

包装器只检查整数范围及权限，实际 read/write 检查描述符是否存在、方向
是否允许。不能依赖当前 mini-libc 的 F_GETFL 判断，因为它尚未查询内核。
借用读取不会预读超过调用需要的字节，避免包装器关闭后丢失原持有者的数据；
借用 line 为此按字节读取。拥有文件的普通 Port 仍保留 4 KiB 缓冲。
裸 fd 共享内核偏移；不要与另一个已经预读的包装器交错操作。包装器仍禁止
复制、返回、装箱、存入容器或闭包捕获。原先“管道进程尚未交付”的范围中，
匿名管道现已实现如下；完整所有权转移和进程组合仍须继续迁移。

### 匿名管道的双端所有权

```python
with reader, writer = pipe():
    writer.write("hello\n")
    writer.close()
    assert reader.line() == "hello"
    assert reader.line() is None
```

`pipe()` 无参数，要求 CAP_PROC，按顺序绑定只读端和只写端。必须提供两个
不同的作用域名称；它不返回可复制的 List 或元组。分配失败或系统调用失败
不发布任何端点，已分配的包装器立即释放。两端都使用 Port 方法，kind 为
`pipe`；方向错误报告 IOError。离开作用域按 writer、reader 的顺序释放，
包括 return、break、continue 和异常。显式 close 后再次清理不会重复关闭。

读端关闭后写入报告 IOError。原生程序初始化时忽略 SIGPIPE，让 write 返回
错误并进入语言异常与清理路径；原始 exec 系统调用保留系统的信号继承规则。
后续高级进程启动器须在外部命令中恢复默认 SIGPIPE，不能把语言的处理方式
无意间传给整个外部管道。管道容量有限，同一线程先写超过容量再读会阻塞；
大数据生产者需要与消费者同时运行。这里只交付匿名管道，未完成 run/管线组合。

### 原生命令与进程所有权

更正前一节的阶段限制：run、管线组合和重定向现在也已原生实现，规则如下。

`run("echo", "hello")` 和 `run(["echo", "hello"])` 返回 `Command`。
构造时复制参数列表，尚不创建子进程；字符串不经 shell 拆分，空实参、空格
和 UTF-8 原样保留。参数中不允许 NUL，最多 256 项，至少一项。

```python
def main() -> None:
    command = run("echo", "hello") |> run("cat")
    print(command.out())
    assert command.wait() == 0

    with process = run("echo", "scoped").start():
        print(process.pid())
```

`|>` 将尚未启动的左侧管线接到一个尚未链接的右侧单独命令，最多 32 段；
`<-` 设置头部输入文件，`->` 设置尾部输出文件。禁止环路、重复重定向、
越过输出重定向继续连接，以及对已启动管线重新组合。赋值保存描述；独立
的组合/重定向表达式语句执行并等待，例如 `run("echo", "data") -> path`。
裸 `run(...)` 表达式仍只构造描述。

| 方法 | 语义 |
| --- | --- |
| `wait() -> i64` | 必要时启动，等待所有段，返回最后一段退出码；重复调用读缓存 |
| `out() -> str` | 仅启动前调用，捕获尾部 stdout，等待所有段；最多 64 MiB，严格 UTF-8 |
| `pid() -> i64` | 当前段 PID，启动前为 -1 |
| `status() -> i64` | 当前段已回收的退出码，尚未回收为 -1；不主动轮询 |
| `argv() -> List[str]` | 当前描述持有的参数列表；启动时再校验并复制给子进程 |
| `start() -> Process` | 只用于直接的 with 获取表达式 |

`out()` 不能与尾部文件重定向并用，不能重复捕获；非零子进程退出码仍允许
读取其 stdout，再通过 wait/status 查询。常规退出返回程序退出码；信号
终止返回 128 加信号号。执行文件失败的子进程退出码为 127。

Command 是受 GC 管理的描述，能存入同类型容器和作为参数传递；Process
是唯一资源所有者，只能存在于 with 作用域。两种获取写法
`with process = command:` 和 `with process = command.start():` 均在进入
时启动，在正常结束、return、break、continue、异常退出时等待所有子进程。
当前不支持复制、聚合、捕获或跨函数转移 Process；外部 Command 别名不能
重复取得同一运行中的所有者。启动失败会清理已经启动的本管线子进程。

构造/启动均检查 CAP_PROC，重定向使用已有文件能力和路径约束。这里的
原生命令不提供额外系统权限，也不依赖 VM 或模型服务。

### 端口统计

`port_stats() -> Dict[str, i64]` 返回独立、可修改的统计快照。修改返回字典
不会改变运行时计数；已取得的快照也不会随之后的开关文件而变化。

| 键 | 含义 |
| --- | --- |
| `open` | 当前未关闭、由 Port 所有的文件描述符数量，匿名管道每端计一个 |
| `closed` | 成功关闭的所有型端口累计次数 |
| `close_errors` | 关闭所有型端口时报告错误的累计次数 |
| `finalized` | GC 关闭端口的次数；A3 使用确定性作用域释放，因此为 0 |
| `orphans` | 旧 GC 最终化发现的孤儿端口数；A3 不使用此最终化机制，因此为 0 |

借用 `port(fd)` 不取得描述符所有权，包装器的建立和关闭均不增加这些计数。
重复 close 不重复计数。close 即使报错也先消费所有权，避免之后的作用域
清理再次关闭可能已经重用的 fd。这些数值不代表进程中所有系统描述符，
例如命令启动器内部临时管道不属于 Port 统计。

### 原始整数指针

`i8ptr(address)`、`i16ptr(address)`、`i32ptr(address)`、`i64ptr(address)`
接受 u64 地址，分别产生 `Ptr[i8]`、`Ptr[i16]`、`Ptr[i32]`、`Ptr[i64]`。
指针是直接保存的机器地址，不是 GC 对象。`addr(pointer)` 取回 u64 地址。
构造、取地址、下标读写及内存转文本均要求词法 `unsafe:` 和当前 CAP_RAW。
嵌套函数必须声明自己的 unsafe 块；外层块不自动授权其函数体。

```python
def main() -> None:
    storage = buffer(8)
    unsafe:
        words: Ptr[i32] = i32ptr(addr(storage))
        words[0] = 1000
        words[1] = 337
        print(words[0] + words[1])
```

下标为 i64，按元素字节宽度计算偏移，支持指向分配内部时的负下标。
缩放及地址加减检查溢出，解引用零地址报告 ValueError。未知分配边界不做
伪造的 bounds 检查：调用者负责地址有效性、可写性及所有者存活。指针不
保持 GC 所有者存活，不能把裸地址当成后续 Region 的受检查借用视图。

读取产生声明的定宽整数，赋值检查该类型范围。非对齐访问以 alignment 1
生成代码；不会把旧版越界整数写入的截断行为暗中带入静态赋值。需要位模式
截断时应先显式计算目标值。普通赋值先算右侧，复合赋值只求一次指针和下标，
先读取旧值再计算右侧；右侧改变指针变量也不改变本次写入的位置。

Ptr 可用于函数、泛型 Integer 参数、容器、闭包、Optional 和显式 Any。
相同指针类型的相等比较比较地址，不读取其目标；没有长度或顺序关系。
当前 pointee 限定为 Integer，管理对象和浮点元素报 AS3812。完整 C ABI、
显式 alloc/dealloc、Region 移动和安全借用规则仍是独立的未完成项。

后续修正：`alloc(byte_count: i64) -> Ptr[u8]` 与 `dealloc(pointer) -> None`
已有原生实现，两者均要求词法 `unsafe` 与调用时实际持有的 `CAP_RAW`。
正数长度分配零初始化的手动内存；零或负数产生 ValueError，分配失败产生
MemoryError。此内存不属于 GC，不进入 gc_live_bytes/gc_stats，也不会在
普通局部变量离开作用域或异常时自动释放。调用者须在正常及异常路径显式
释放；需要确定性作用域所有权的 Region 仍是独立的未完成项。

`dealloc` 接受任意已支持整数元素的 Ptr，但地址必须是当前手动分配的起始
地址。空地址、内部地址、GC 存储和不再登记的地址产生 ValueError，不交给
系统 free；权限撤销产生 PermissionError，且不会先释放内存。转换指针的
元素宽度不转移或复制所有权。

旧 VM 通过共享指针对象将释放后的地址改为零；A3 指针为直接复制的地址值，
释放不会修改其他别名。释放后不得解引用别名；若分配器后来复用了相同地址，
旧别名与新分配无法通过裸地址区分，登记表不提供生命周期安全保证。跨 C ABI
分配或 GC 内存也不能交给 dealloc。原生运行时诊断仍定位到原 alloc/dealloc
表达式；它们不会静默转入 VM。

Region 的运行时准备（尚非源码功能）：`runtime/region.c` 已提供独立于 GC
的唯一字节区域、空目标槽移动、移动源清空和显式释放；`region_borrow.c`
提供多个共享借用或一个独占借用，以及父借用上的嵌套借用。独占父视图在
子借用存活时暂停访问；存在借用时拒绝移动或释放所有者。失败不先修改已有
所有权。区域保持固定长度，沿用旧 buffer/region 的零初始化和 64 MiB 上限。

这些是内部 C 运行时契约。它们不代替编译期的移动、借用逃逸、循环与异常
路径检查；`region()` 的 A3 源码入口、Slice/MutSlice 接入仍未交付。旧 VM
把 region 当作 Buffer 别名的行为仍不能作为迁移后的实现。

后续修正（2026-09-16）：A3 已接入以下受检查的源码所有者子集：

```python
with owner = region(16):
    owner[0] = 42
    with moved = owner.move():
        moved[0] += 1
        assert len(moved) == 16
    # 此处读取、写入、len(owner) 或再次 owner.move() 均报 AS3402。
```

- `region(size: i64)` 只允许直接用于 `with` 获取唯一所有者。长度允许
  0 到 64 MiB，零初始化；非法长度报 ValueError，分配失败报 MemoryError。
  这是普通内存所有权操作，不要求 unsafe 或 CAP_RAW。
- 下标是 i64，允许负数从末尾定位；读取返回 i64 字节，写入只接受
  0..255，越界报 IndexError。普通赋值先求右侧，复合赋值只求一次下标，
  先读取旧值再求右侧，最终按一个字节写入。
- `.move()` 只能直接用于另一个 `with` 的右侧；成功后源不可再使用，
  失败不消耗源。目标退出时释放，源退出时清理空槽；同名嵌套绑定允许。
- 正常退出、return、break、continue 和异常都逆序释放。Region 不属于
  GC，也不进入 GC 分配统计。生成器持有独立清理槽，不用普通引用复制
  或 GC 扫描冒充唯一所有权。
- 分支出口取仍存活所有者的交集；循环计算回边的固定点，捕获块合并
  各潜在抛出位置的所有权状态。因此循环第二轮重复移动以及异常后使用
  可能已移动的源都报 AS3402。当前分析不利用常量条件或异常类型排除
  不可达路径，可能保守拒绝需要这些证明的代码。
- 复制、容器/字段保存、Any 装箱、闭包捕获、跨函数传参/返回和作用域外
  使用仍被拒绝。Slice/MutSlice、安全借用及跨调用所有权协议继续待迁移；
  不能从内部 C 借用接口推断这些源码能力已经交付。

后续修正（2026-09-16，安全视图接入）：Region 现在支持显式半开范围
`owner.borrow(start, stop) -> Slice[u8]` 和
`owner.borrow_mut(start, stop) -> MutSlice[u8]`，两者都必须直接用于
`with view = ...`。下例是已接入原生路径的写法：

```python
def increment(data: MutSlice[u8]) -> None:
    data[0] += 1

def main() -> None:
    with owner = region(4):
        with writable = owner.borrow_mut(0, 4):
            writable[0] = 41
            increment(writable)
        with readable = owner.borrow(0, 1):
            snapshot = Bytes(readable)
        assert owner[0] == 42 and snapshot[0] == 42
```

- 范围满足 `0 <= start <= stop <= len(parent)`，不截断越界范围；空视图
  有效。视图沿用 Slice 的零起点下标规则，负下标和越界报 IndexError。
  元素为真正的 u8，写入按 u8 的编译期字面量范围和运行时溢出规则检查。
- 多个共享借用可并存；有共享借用时所有者可读但不能写、移动或释放。
  独占借用期间所有者不能读写。len 只读取不变的长度，仍可使用。
- with 绑定的视图可再次 borrow；只读父视图不能产生可变子视图。可变
  父视图在子视图存活期间暂停数据访问；多个只读子视图可并存，独占子
  视图排除兄弟视图。退出、return、break、continue 和异常都先释放子
  记录，再释放父记录，最后释放 Region。
- 视图支持索引、循环、推导式、解包、成员查询和格式化。Bytes(view)
  拷贝为独立的不可变字节对象；后续写入或释放原区域不会改变快照。
- Slice 和 MutSlice 可传给已声明类型的函数、泛型及函数值。调用的
  借用持续至返回；可变参数独占。`f(view, view)` 若授予两个可变参数
  同一视图则报 AS3403；较早的可变实参也禁止后续实参访问同一视图。
  需要读取后再传参时，先在调用前保存标量值。
- with 视图不可复制到普通局部变量，也不能保存到聚合、装箱、捕获或
  返回。只读参数可在函数内部形成只读别名，但不能逃逸该调用；可变
  参数不能复制或重新绑定。这些限制防止原始 data/length 脱离借用记录。
- 编译器保留独立清理记录，Slice/MutSlice 值本身仍为 data/length。
  显式 borrow 目前分配一条小型运行时记录；调用参数借用只需编译期
  检查，不为每次传参额外分配记录。记录和 Region 均不属于 GC。
- 借用冲突的 AS3403 同时输出冲突访问、原借用/先前实参的位置、修复提示和源码
  校验值。运行时的字节边界错误仍指向实际索引表达式。

仍未交付：对普通 Slice/MutSlice **函数参数再次调用 borrow**、GC 容器的
借用入口、借用所有者/视图跨调用返回的显式生命周期协议。参数目前没有
传递不透明清理记录，因此再次借用会明确报错；不能从普通 data/length
伪造一条具有所有者信息的记录。

### 字节存储协议与 ABI 调用

`ByteStorage` 是泛型只读协议，接受 Bytes、Buffer 和 layout 记录；
`MutableByteStorage` 只接受后两者。泛型函数体按声明的协议检查，不能因为
当前调用传入 Buffer 就允许只读协议写入。具体实例仍直接生成原生操作，
不新增动态值包装。它们支持长度、字节索引、遍历、成员检查、解包、推导式
以及 Bytes 快照；`addr/mem2str/mem2cstr` 仍要求 `unsafe`。

str 的索引语义不同，因此不满足这两个协议；原始数据传递使用显式
`Bytes(text)`。ABI 的文本参数则接受 str：拒绝内嵌 NUL，并复制为有尾部
NUL 的 Bytes，具名临时变量保持 GC 根，允许安全传入带尾部其他内容的切片。
输出缓冲区必须可写；请求长度不能为负数或超过存储大小。固定记录参数要求
对应的名义类型，不能把相同大小的其他记录隐式传入。

argv 缓冲区必须由完整的 8 字节指针组成，并包含 NULL 终止项；包装只检查
这个缓冲区，不解引用其中地址。调用者仍负责被指向对象的生命周期。上述
检查不会授予 capabilities；调用继续经过 RAW 和内核的实际资源检查。

等待使用单调毫秒时钟，允许零超时下的一次立即检查；负超时抛 ValueError，
超时换算溢出抛 OverflowError，启动／内核失败及异常时钟抛 IOError，超时
抛 RuntimeError。宿主不伪造 LogitOS 调用结果；无平台支持时明确失败。

### sys 标准库

`sys` 提供原有文件、目录、进程、时间及网络功能，底层调用交给 ABI 模块。
`read_file/read_file_max/cwd` 的旧 nil 失败值改为 Optional[str]，`ls`
返回 Optional[List[str]]，调用者必须判空。`read_file_max` 保留整文件
容量上限：LogitFS 文件超过上限返回 None；它不是读取前缀的接口。无效
UTF-8 或非法参数仍抛类型化错误，二进制文件应使用 Bytes／文件 port。

`write_file` 接受 ByteStorage；写入文本显式使用 `Bytes(text)`。原有
remove/rename/mkdir/chdir/pid/cpu 保留整数返回值。`time` 返回原生 Time
记录，读取失败抛 IOError，不制造一个看似成功的零时间。

`spawn(path, arguments: List[str])` 中 arguments 是包含 argv[0] 的完整
参数列表。参数字节副本和指针数组由同一个原生对象持有，先验证并复制，再
fork；子进程 exec 失败退出 127。`wait` 返回实际退出状态，非正 pid 或
等待失败返回 -1；`run` 不会将启动失败的 -1 传给 waitpid 等待任意子进程。
`exit` 成功不返回。`sleep` 使用单调时钟与检查过的毫秒换算，负值、溢出及
失效／倒退的时钟分别报告错误。dns/ping 使用 ABI 的五秒等待规则，显式
dns_or/ping_or 保留捕获错误后返回指定默认值的行为。

## 5. 模块与诊断

支持同目录 `import module` 和 `from module import name`，模块图必须无环。循环错误的结构化 `related` 数组按顺序列出完整路径，首尾重复以闭合环。不存在的导入成员即使未被使用也会报告错误。

支持 `import std.strings as text`、`from std.strings import words as split_words`，以及 `import nested.values as values`。点号映射到子目录；目录本身不执行初始化脚本。普通导入先查当前源码目录，再查标准库；`std.` 明确从标准库根目录解析，缺失时不会回退到同名本地文件。未指定别名时绑定最后一个模块名；`std` 不是运行时命名空间对象。别名保留原始声明身份、隐私限制和同一模块初始化顺序，重复绑定报错。磁盘与未保存 overlay 使用相同解析规则。

诊断使用 UTF-8 字节范围及从 1 开始的字符行列。每个模块有自己的源码身份；诊断、符号和构建结果引用同一份检查快照。输入 overlay 会复制，后续编辑不会改变已生成的结果。含 NUL 或超过大小限制的 overlay 被拒绝，不能截断后当成成功输入。

当前源码身份字段是字节数和 FNV 校验值，不是防碰撞密码学摘要；来宾验收另存编译器、内核和产物的 SHA-256。完整并发编译服务、密码学快照 ID 及所有源码相关位置仍待完成。

## 6. 检查、构建、运行与测试

```text
as check main.as --json
as build main.as --target host -o program
as build main.as --target logitos-x86_64 -o program.aex
as run main.as --json
as test tests.as --json
as build main.as --emit-llvm -o program.ll
as run main.as --overlay dependency.as unsaved-dependency.txt --json
as check main.as --snapshot-stdin --json
as complete main.as --snapshot-stdin --at 128
```

`check/build/run/test/complete` 都接受 `--snapshot-stdin`，与 `--overlay` 互斥。
标准输入依次为 `AETHER-SNAPSHOT-1\n`、文件数量及换行；每个文件为
路径字节数及换行、源码字节数及换行、原始路径字节、原始源码字节。
两个字节串之后没有额外分隔符。数量范围 1–64，路径上限 511 字节，
单个源码上限 1 MiB；重复路径、NUL、截断和尾随数据均报错。路径与
源码使用 UTF-8 字节计数。解析器拥有输入副本，检查结束后释放。

Studio 通过这个管道发送所有已打开标签的源码副本，不会为检查而保存
用户文件。结果关联入口及已打开模块的编辑版本；导入文件的诊断按其
自己的路径和字节范围定位。未打开的磁盘模块在结果接收时校验字节数
和 FNV 值，不能将此机制称为密码学源码身份或完整磁盘快照服务。

`complete` 当前查询函数体或模块初始化表达式中的模块成员，以及已确定
结构体/类类型的字段和方法。接收者支持变量、构造器、函数调用、链式
字段和下标表达式；继承方法选择与私有方法可见性使用检查器的规则。
`--at` 是入口源码的 UTF-8 字节偏移，不接受字符内部位置。结果为 JSON，
包含源码身份、替换起点、成员名称/种类/类型/声明位置及所有已加载模块
的源码身份；最多返回 64 项，超出时 `truncated: true`。解析不完整输入
仍可返回候选，但不执行用户模块。导入别名、公开成员与名称遮蔽遵循检查器。
`handled: false` 表示该上下文尚无语义查询；已识别模块的空结果是权威结果，
不能回退为猜测导出。模块顶层裸 `module.` 尚不支持。

Studio 的模块与结构体/类成员补全使用独立异步进程，发送当前所有标签的未保存源码。
关闭候选、修改源码或切换标签会撤销请求的有效性；旧进程结果不能重新
弹出候选。后台诊断不关闭候选。局部名称和内建容器等成员补全仍使用
原有实现，尚未完成全部语言服务迁移。未闭合字符串等词法错误目前会
使整个模块没有语法树，此时返回空候选；词法错误恢复仍待补齐。

宿主工具链通过 `make BUILD=build-as-typed as-toolchain` 生成。命令可使用 `--toolchain DIR`，或从可执行文件旁的 `aether-toolchain` 查找。`--debug` 使用 O0；默认使用 O2。

`as test` 原生运行零参数、返回 `None` 的 `test_*` 函数。`assert` 条件必须为 `bool`，失败报告原始源码位置并停止后续测试。运行输出、退出码和编译诊断分开表达；输出超限时明确报告 `output_truncated`。

AEX 构建调用 OS 已有打包器，检查、链接或 LLVM 生成失败不覆盖已有产物。发布采用同目录临时文件、文件同步、原子改名、目录同步。若改名后的目录同步失败，会报告失败，但新文件可能已经可见。

当前保留了运行时错误的源码位置，尚未生成完整 DWARF 变量信息；`--debug` 不能被宣传为已经支持 Studio 断点、单步和变量查看。

## 8. 尚未交付的批准设计

原先列在这里的“可捕获类型化异常”现已有原生子集：`try/except/else`、主动抛出、重抛及错误值记录。详见功能对照；自定义异常层级和资源清理仍未完成。

旧列表曾把精确 GC、原生根记录和 List 全部列为未交付；现已实现非移动追踪 GC、字段扫描、栈/模块根、同类型 List 的追加/索引/赋值/迭代，以及动态不可变字符串。`test-as-managed` 与 `test-as-globals` 检验回收、根、初始化及故意破坏后的失败；完整对象系统和借用仍未交付。

模块变量的初始化函数按导入依赖后序执行，同一模块只执行一次。模块内部依源码顺序初始化，直接提前读取在检查时报错；经函数间接提前读取产生带源码位置的 RuntimeError。函数内重绑定需 `global name`，修改容器内容不重绑定其名字。普通赋值名字在整个函数内属于局部作用域。模块变量不能保存调用作用域的 Slice。

以下需求保持原计划，尚不能列为已实现：

- 自定义泛型协议、泛型结构体、`class`。
- 完整 List 方法、`Dict/Bytes/Optional`、Any 动态运算/调用、推导式、格式化字符串和完整标准库。
- `Region` 移动、可变借用、GC 容器借用冲突和完整生命周期分析。
- 文件等唯一资源、`with` 的各出口清理、自定义异常层级及其与资源/GC 的整合。
- 显式 C 布局、原始指针、`unsafe` 与 C ABI/capabilities 适配。

上述条目的阶段修正：当前已有词法 `unsafe:` 块、`addr` 和
`peek8/16/32/64`、`poke8/16/32/64` 的原生标量读写。每次调用仍检查
实际持有的 CAP_RAW；能力快照通过 caps/bits/path/without/scope 操作，
只允许收窄。无权限产生 PermissionError。unsafe 不改变普通数值运算的
溢出规则，也不会传递到在其中声明的函数体。原始整数地址不保留 GC 所有者；
调用者承担地址、长度、可写性和生命周期正确性。typed pointer、唯一 Region、
C 布局及完整 C ABI/资源适配仍未全部交付。
- Studio 多文件未保存快照、统一补全/重命名、宿主构建连接和完整调试。
- 完整三个应用工程、GC/资源来宾验收、与 Rust 的公平性能和内存比较。

上列旧缺项中的 Dict 和 Optional 已有原生实现：Dict 支持同类型键值、查找/插入/删除、快照迭代及两种 get；Optional 支持判空、局部流分析、GC、泛型及相等比较。Any 的格式化和相等比较已补齐，动态算术/调用仍未完成；标准库已原地重写 11 个模块，剩余 6 个。该修正不把其余缺项视为完成。

进一步修正：原生 class 的固定字段、构造器初始化分析、绑定方法、组合和 GC 已有宿主/来宾验收；继承和泛型方法仍缺。aslex 原地重写后共 12 个标准库为 A3，剩余 5 个。格式化字符串已复用静态表达式检查和原生格式化，支持嵌套及多行插值，格式规格继续明确拒绝。

Range 现在是可保存、可传参的惰性原生值；直接 range 循环仍不分配对象。长度超过 i64 时 len 抛 OverflowError；索引和成员检查不展开序列。字符串按现有 UTF-8 字节视图遍历。列表推导式的变量只属于表达式作用域，过滤条件先于元素计算，产生独立的同类型 List。多变量赋值先计算全部右侧，再按源码顺序写入；解包长度不匹配时不修改目标。

复合赋值（`+=`、`-=`、`*=`、`/=`、`%=`）先从左到右计算目标的所有者和下标，读取旧值，然后计算右侧，最后检查运算并写回。每个所有者和下标表达式只求值一次。普通 `=` 仍先计算右侧，再计算目标。返回的 Class、List、Dict、Buffer 可以直接作为赋值目标的所有者；临时值结构体和固定数组不能作为独立可写存储。

右侧可以修改或扩容容器；编译器保留所有者及旧值的 GC 根，并在写回时按原下标重新定位当前存储。负下标在写回时按当前长度解释。字典直接下标复合赋值可以重新插入被右侧删除的键，但初次读取缺失键会先抛 KeyError，不执行右侧。字典内联结构体字段写回时若键已删除，则抛 KeyError。越界、溢出或 Buffer 字节范围错误不执行最终写入；已经执行的右侧副作用不回滚。

上述 Bytes 缺项的阶段修正：现在支持独立的不可变 `Bytes` 类型。
`Bytes(Buffer)` 复制当前内容，之后修改 Buffer 不影响结果；`Bytes(str)`
复制字符串视图的现有字节表示，包含 NUL，不额外执行解码或 UTF-8 验证。
`Bytes(Bytes)` 可共享不可变对象。复制长度上限为 64 MiB，超限抛
ValueError，分配失败抛 MemoryError。

Bytes 的索引和迭代返回 i64 字节值（0–255）；支持负索引、len、整数成员
查询、推导式和严格长度解包。越界抛 IndexError，解包长度不匹配抛
ValueError。所有索引写入（含复合赋值）在编译期拒绝，不允许直接转换为
Buffer 或 str。`==`/`!=` 比较长度和字节内容，Any 内的比较保持相同语义。
Bytes 可用于泛型 Equatable、聚合字段、容器、Optional 和闭包，并保留精确
GC 根。格式化显示 `Bytes("\x00\xff")` 这样的转义表示，不直接输出控制字节。
字节切片、拼接、哈希键、文本解码和文件 I/O 接口仍未由本阶段交付。

文件接口的后续修正：`file_read(path: str) -> Bytes` 与
`file_write(path: str, data: Bytes) -> i64` 现在直接使用原生运行时。
读取完整文件（含空文件和任意二进制字节），单次最多 64 MiB；超过上限抛
ValueError。写入创建或截断目标，成功返回字节数，空 Bytes 会截断为空文件。
传入 str 内容需显式写成 `Bytes(text)`；读取结果不会自动转为 str。

路径支持相对路径、绝对路径及中文，空路径、嵌入 NUL 或超过 4096 字节的
路径抛 ValueError。读取/写入分别要求持有 CAP_FS_READ/CAP_FS_WRITE，
缺少权限或超出目录范围抛 PermissionError，实际打开/读写/关闭失败抛
IOError（宿主明确报告权限失败时保留 PermissionError）。异常保留调用源码位置。
短读不作为 EOF，短写继续完成，EINTR 重试读写；所有已经打开的文件都在
返回前关闭一次。关闭失败不能报告成功，读取失败不发布部分内容。
写入失败可能已改变目标文件，不提供原子替换或断电持久性保证。

带目录限制的路径先按组件归一化并核对边界，宿主使用目录描述符逐级打开，
拒绝路径中的符号链接；无目录限制的宿主访问保持普通路径语义。
LogitOS 当前没有符号链接，运行时检查之外仍受实际内核权限约束。
这两个完整文件操作自行管理资源，尚不表示唯一文件对象、ports、with 清理、
文本解码或文件标准库已经全部交付。

2026-09-16 修正：上句记录的是完整文件操作阶段。现在新增原生作用域文件
端口，语法为 `with file = open(path, mode):`，其中 path、mode 都是 str，
mode 缺省为 `r`。`r/rb` 只读，`w/wb` 创建并截断，`a/ab` 创建并追加；
兼容原接口的 `rw` 可创建文件，`r+b` 要求文件已经存在。读写模式必须同时
持有文件读、写能力，路径使用上述同一权限检查。

| Port 操作 | 结果与边界 |
| --- | --- |
| `read(count)` | Optional[Bytes]；正数长度，EOF 或已关闭时 None |
| `read_exact(count)` | Bytes；正数长度，不足或已关闭时 IOError |
| `readall()` | Bytes；读取剩余内容，EOF 或已关闭时空 Bytes |
| `line()` | Optional[str]；严格 UTF-8，去除结尾换行和 CR，EOF 为 None |
| `for line in file` / `file.lines()` | 按上述文本规则逐行借用读取 |
| `write(str或Bytes)` | i64，实际写入字节数，失败抛出类型化异常 |
| `close()` / `closed()` / `fd()` | 幂等关闭、关闭状态、描述符；关闭后 fd 为 -1 |
| `kind()` | 当前唯一资源种类为 `"file"` |

单次字节读取、写入及单行限制为 64 MiB；读写共享逻辑游标，缓冲预读不会
使后续写入落在错误位置。返回的 Bytes/str 有独立 GC 生命周期，关闭文件
后仍然有效。正常离开、return、break、continue 和异常按逆序释放资源。
捕获点还在 with 内时保留该文件。正常关闭失败产生 IOError/PermissionError；
异常传播时的关闭失败不替换正在传播的原始异常。

当前只接受在 with 中直接获取文件所有者；所有者不能复制、装入 Any 或
容器、捕获、跨函数传递或返回。with 名字只在其作用域有效，外部同名变量
随后恢复可见。这是当前可检查的所有权边界。所有权移动、借用描述符
`port(fd)`、进程管道、Region 和完整资源标准库仍须迁移，不能视为已完成。

#### 原生系统调用和内存文本桥接（2026-09-16）

三个接口均要求当前函数中显式的 `unsafe:`，执行时仍检查 CAP_RAW：

- `syscall(number, a, b, c) -> i64`：number 必须是 i64，后面零到三个参数
  必须各为 i64 或 u64。省略参数填零，从左到右求值。u64 地址按同宽 ABI
  字传递，内核的负值结果原样返回，由调用者按相应接口解释。
- `mem2str(memory, length) -> str`：memory 为 Buffer、Bytes 或 u64 地址，
  length 为 i64。长度限 0 到 64 MiB；超出已知存储边界产生 IndexError，
  负数/超限/空指针产生 ValueError。结果复制存储并严格验证 UTF-8。
- `mem2cstr(memory, limit=4096) -> str`：同样的存储类型，在 limit 和已知
  容量中的较小范围寻找 NUL；找不到产生 ValueError。NUL 不进入结果。
  这是内建接口的可省略实参，不代表任意用户函数的默认参数已经实现。

`addr` 现在也接受 Bytes。原始整数地址不保留所有者，程序必须确保内存
在操作期间有效；`unsafe` 不为越界地址提供恢复保证。使用 Buffer/Bytes
实参时编译器保留其 GC 根，转换出的文本不依赖原缓冲区后续修改或生命期。
向内核传递 C 字符串须显式提供 NUL 结尾的有效存储；普通 str 视图不承诺
其末尾存在 NUL。二进制数据应保留为 Bytes，不能靠文本桥接绕过 UTF-8。

`syscall` 的编号只属于 LogitOS ABI。宿主构建执行时产生带源码位置的
RuntimeError，不把这些编号传给 macOS/Linux。来宾中先检查 CAP_RAW，再由
内核检查具体调用的资源权限和路径范围。这一低层入口不等于可移植标准库
或完整 C ABI 已实现；生成的 ABI 布局、Region、指针视图仍须迁移。

旧接口行为修正：VM 的 mem2str 可制造非法 UTF-8 文本，mem2cstr 在 4096
字节未找到 NUL 时直接截断；A3 分别报告 ConversionError 和 ValueError。
旧程序应把二进制数据改用 Bytes，并为 C 字符串提供明确容量和结束符。

文本解码的后续修正：`Bytes.decode() -> str` 严格验证 UTF-8，不接收编码
或错误替换参数。非法首字节、错误续字节、截断、过长编码、代理区码点及
超过 U+10FFFF 的值产生带调用源码位置的 ConversionError。合法 NUL、BOM
和非字符码点原样保留；不会悄悄替换坏字节。

解码结果是不可变字节存储上的文本视图，无需再复制一次。非空视图的 GC
扫描保留 Bytes 所有者，空结果使用静态空串。`file_read(path).decode()`
构成显式的 UTF-8 文件读取路径。`str(bytes)` 仍是转义表示，不是解码。
此方法不改变现有 str 的字节索引/切片规则；按 Unicode 码点索引等完整文本
语义仍需独立迁移。

`args() -> List[str]` 每次返回独立的启动参数列表，包含第零项。直接运行产物时第零项为可执行程序名；`as run FILE -- ARGS` 时为源码入口 FILE，编译选项不进入程序参数。空参数、带空格参数、中文和 `--json` 这样的参数原样保留。模块初始化时也可读取参数。

`gc_stats() -> i64` 返回当前被管理的原生分配对象数量；容器身份及其独立跟踪的存储分别计数。`gc() -> i64` 回收并返回这次释放的对象数量，等于前后 gc_stats 的差。`gc_collect()` 只回收、不返回数值；`gc_live_bytes()` 专门报告载荷字节数。常量和直接数值不产生 VM 对象，所以绝对计数不要求与旧实现一致。

闭包已有原生捕获实现：嵌套 def 和 lambda 共享被捕获变量的存储；修改对同一次外层调用产生的所有闭包可见，不同调用互不影响。捕获的已知类型数值使用具体布局的 GC 单元，不进入动态 Value。环境保留这些单元，支持外层返回后的调用、递归闭包的循环回收、方法 self 和泛型外层的独立实例化。

lambda 的参数可由 Callable 注解、返回上下文、泛型回调参数或立即调用的实参确定；完全缺乏这些上下文时会要求注解。嵌套函数目前不能另行声明自己的泛型参数。捕获未初始化变量或调用作用域的 Slice 会报错；被捕获的 Optional 可被其他闭包修改，判空前须复制到普通局部快照。嵌套函数不会作为模块成员导出。

现有 `AS3900` 等诊断明确拒绝未支持的构造，不回退到 VM。系统内原生编译、新版自举、JIT 和内核执行仍在后续阶段。

## 9. 从旧版本迁移

1. A1 源码先按 A2 的精确整数与显式回绕规则修改并验证，旧格式 5 `.la` 必须重新编译。选择能迁移到静态语言的模块后添加 `# aether: 3.0` 声明。

4. 异常绑定改为 `except Error as error:` 或具体种类，主动抛出使用异常构造器。固定 class 字段、`Optional/Any` 和资源所有权仍按批准设计推进，相关旧模块尚不能整体迁移。
