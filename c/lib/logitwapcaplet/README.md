# logitwapcaplet

这是 LogitOS 独立实现的字符串驻留库：相同字节共用一个稳定对象，调用方用引用计数
管理寿命。保留 LibCSS 使用的 12 个 `lwc_*` 操作，项目代码采用 GPL-3.0-or-later。

`pool.c` 管索引和寿命。索引用开放寻址，只存对象指针；扩容不会移动字符串。
删除条目时回移探测链，避免后面的冲突条目突然查不到。最后一个对象释放时也释放
索引。锁保护索引与引用计数；遍历先保留快照，回调在锁外运行，因此回调可以再驻留
字符串而不死锁。

`string.c` 管不可变字节。大小写无关比较只折叠 ASCII，在创建对象时计算对应哈希，
不创建旧实现那种缓存的小写伙伴对象。显式 tolower 得到普通驻留对象，按普通引用
规则释放。嵌入的零字节是内容，长度不能靠 strlen 推断。

对象对调用方不透明。LibCSS 原来读取的 `insensitive` 字段已改为公开比较和哈希
接口。旧头中的 `lwc__intern_caseless_string`、断言宏以及“手动减引用后再销毁”的
`lwc_string_destroy` 属于旧表示的内部机制，未重建；使用 ref/unref 管理所有权。
因此这里不是旧对象布局或全部内部符号的二进制兼容层。

公开头和调用方用于核对接口，没有使用旧 .c 实现作为模板。这是工程过程说明，
不是法律意义上的 clean-room 认证。哈希数值和遍历顺序不作为稳定外部协议。

现有 CSS 声明、选择器、CSSOM 和真实 guest 页面均连接此实现。
具体结果与尚未覆盖的故障场景见 [交付核对报告](../../../docs/reports/logit-css-support-2026-10-25.md)。
